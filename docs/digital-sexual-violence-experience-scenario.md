# 디지털 성범죄 1인칭 웹 작품 시나리오 v0.2

## 1. 문서 정보

- 작업명: **《검색 가능한 사람》**
- 형식: 개인 모바일 기기에서 실행되는 1인칭 인터랙티브 웹 작품
- 대상: 일반 대중
- 예상 체험 시간: 17~19분
- 주인공: 한국에 사는 20대 후반 여성 직장인
- 중심 사건: 정체를 숨긴 대학 동문이 주인공의 사진과 신상정보를 익명 대화방에 제공하면서 시작된 성적 합성물 범죄가, 참여자들의 분산된 신원 특정·사칭·위치 노출·협박·직장 전달과 재유포로 확장되는 복합 피해
- 결말: 사진 제공자와 합성물 제작자가 처벌되어도 신원 미상 참여자, 복제본과 사회적 피해가 남아 삶이 복구되지 않는 파국
- 문서 범위: 화면, 문구, 사용자 행동, 서사 분기와 연출
- 이번 문서에서 다루지 않는 것: 개인정보 입력 방식의 구현 조건과 관련 정책

이 문서는 특정 피해자의 실제 사건을 재현하는 기록물이 아니다. 한국에서 공개적으로 확인된 지인 대상 합성물 제작·유포 사건과 피해지원 자료에서 반복되는 구조를 여러 허구 인물에게 분산해 하나의 최악 경로로 재구성한 시나리오다.

## 2. 작품의 한 문장

> 한 사람이 입력한 몇 개의 평범한 정보가 성적 합성물과 결합된 뒤, 삭제·신고·판결로도 회수할 수 없는 새로운 사회적 신원이 되어 그 사람의 현실을 대신한다.

## 3. 작품의 중심 명제

이 작품의 분기는 피해를 피하는 방법을 선택하게 하지 않는다.

> 사용자의 선택은 **파멸의 여부**가 아니라 **무엇을 통해 피해를 처음 알게 되는지**, **무엇이 먼저 무너지는지**, **어떤 흔적을 더 오래 바라보게 되는지**를 바꾼다.

피해 규모는 사용자의 대응 선택 때문에 커지지 않는다. 범죄를 저지르고, 저장하고, 재유포하고, 신원을 추적하고, 현실 관계로 전달하는 사람들의 행동 때문에 커진다.

## 4. 서사에서 말하는 1차·2차·3차·N차 피해

아래 구분은 법률상 공식 분류가 아니라 작품의 극적 구조를 위한 명칭이다.

| 단계 | 사건                                               | 무너지는 영역        |
| ---- | -------------------------------------------------- | -------------------- |
| 1차  | 대학 동문의 사진·신상정보 제공과 성적 합성물 제작  | 초상·성적 자기결정권 |
| 2차  | 익명 대화방 참여자의 저장, 복제, 재게시, 링크 공유 | 통제권과 삭제 가능성 |
| 3차  | 실명·직장·생활권 결합, 사칭                        | 신원과 물리적 안전감 |
| 4차  | 가족·친구·직장으로 직접 전송                       | 인간관계와 생계      |
| 5차  | 구경, 조롱, 해명 요구, 기사화, 검색어화            | 존엄과 공적 인격     |
| N차  | 삭제 뒤 재유포, 판결 뒤 재등장, 새 관계로 재침투   | 미래와 시간          |

## 5. 고정된 주인공 골격

사용자가 입력하거나 생성한 값은 아래 변수에 치환된다. 서사의 사회적 관계와 직장 생활 골격은 고정한다.

| 변수           | 의미                        | 기본 예시          |
| -------------- | --------------------------- | ------------------ |
| `{{이름}}`     | 주인공 이름                 | 윤서아             |
| `{{회사}}`     | 현재 직장                   | 다온리빙           |
| `{{직무}}`     | 직무                        | 브랜드 운영팀 사원 |
| `{{동네}}`     | 거주 생활권                 | 상수동             |
| `{{역}}`       | 출퇴근에 이용하는 역        | 상수역             |
| `{{장소}}`     | 자주 방문하는 장소          | 회사 근처 카페     |
| `{{친구}}`     | 가장 가까운 친구            | 지민               |
| `{{가족}}`     | 가장 자주 연락하는 가족     | 엄마               |
| `{{계정}}`     | 주로 쓰는 공개 계정         | seo_a.day          |
| `{{연락처끝}}` | 연락처 일부를 연상시키는 값 | 4821               |

### 조연

- `{{친구}}`: 주인공을 믿고 곁에 남지만, 자신도 표적이 된 뒤 모든 대화가 피해 확인과 증거 수집으로 변한다.
- `{{가족}}`: 곁에 남아 보호하려 하지만 주인공의 외출·직장·이름 사용을 제한하는 방식으로 반응한다.
- 박 팀장: 개인적으로는 곤란해하지만 회사의 평판을 우선한다.
- 인사 담당자: 정중한 문장으로 주인공을 업무와 조직에서 분리한다.
- 동료 수진: 게시물을 보았지만 모른 척하며, 시간이 지난 뒤 다른 동료에게 링크가 전달되었다는 사실을 알린다.
- 대학 동문 A: 주인공과 같은 대학을 다녔고 연락처와 공개 계정을 알고 있지만 가까운 사이는 아니었다. 피해가 발생하는 동안에는 정체가 드러나지 않고, 후반의 수사기록에서 최초 사진·신상정보 제공자로 확인된다.
- 제작자 B: 대학 동문 A가 제공한 자료로 성적 합성물을 만든 익명 대화방 참여자. 대학 동문 A와 다른 사람이다.
- 재유포자들: 저장자, 직장 제보자, 위치 추적자, 사칭 계정 운영자 등 서로 다른 익명 계정으로 표현된다. 한 명의 전지전능한 악역이 아니라 분산된 가해 구조로 보인다.
- 다른 피해자: 같은 대화방에서 표적이 된 대학 동문. 주인공과 사건을 연결하지만 관계의 내용은 위로보다 URL 대조, 진술 준비와 수사 진행 확인으로 채워진다.

## 6. 1인칭 표현 규칙

1. 모든 사건은 주인공의 스마트폰 안에서만 발견된다.
2. 주인공의 얼굴이나 신체를 외부 카메라 시점으로 보여주지 않는다.
3. 가해자 시점, 가해자의 작업 화면, 범죄 제작 과정은 보여주지 않는다.
4. 주인공의 감정을 내레이션으로 규정하지 않는다. 화면을 닫는 손짓, 읽지 못한 문장, 반복되는 진동과 관계의 침묵으로 전달한다.
5. 선택 결과에 성공, 실패, 정답, 점수를 붙이지 않는다.
6. 실제 서비스와 혼동되지 않도록 플랫폼과 회사 UI는 모두 가상으로 만든다.
7. 성적 합성물은 모자이크·색면·깨진 썸네일로만 표현한다. 공포는 이미지 자체가 아니라 제목, 검색 결과, 조회 흔적과 주변인의 반응으로 만든다.
8. 본편에서는 관객이 주인공보다 먼저 가해자의 정체나 유포 규모를 알 수 없다.
9. 전지적 정보는 후반에 주인공이 열람할 수 있게 된 수사기록·판결문·삭제 결과 안에서만 뒤늦게 공개한다.
10. 기록 시점은 감정을 해설하지 않고 날짜, 확인된 계정, 확인되지 않은 복제본처럼 사건 사실만 제시한다.

## 7. 작품 상태와 분기 규칙

### 7.1 노출 축

사용자가 구성한 인물 정보로 네 개의 노출 축을 계산한다.

| 입력 정보             | 이미지 노출 `I` | 위치 노출 `L` | 관계 노출 `R` | 직장 노출 `W` |
| --------------------- | --------------: | ------------: | ------------: | ------------: |
| 인물 이미지·외모 설정 |              +3 |             0 |             0 |             0 |
| 공개 계정             |              +1 |            +1 |            +1 |            +1 |
| 동네                  |               0 |            +3 |             0 |             0 |
| 역·자주 가는 장소     |               0 |            +3 |             0 |            +1 |
| 친구·가족 관계        |               0 |             0 |            +3 |             0 |
| 회사명·직무           |               0 |             0 |            +1 |            +3 |
| 연락 수단             |               0 |            +1 |            +2 |            +1 |

- 가장 높은 축이 `primaryRoute`가 된다.
- 두 번째 축이 `secondaryRoute`가 된다.
- 동점이면 같은 인물로 재접속했을 때 결과가 유지되도록 인물 값에서 만든 고정 시드로 결정한다.
- 주 경로는 약 70초, 보조 경로는 약 35초 동안 상세히 경험한다.
- 나머지 경로도 후반의 확산 화면에 짧게 등장한다.
- 따라서 어떤 입력 조합에서도 결말은 같지만, 무너지는 순서와 직접 보게 되는 내용은 달라진다.

### 7.3 분산 가해 규칙

- 대학 동문 A는 사진·실명·연락처와 사회적 관계의 출발점만 제공한다.
- 제작자 B는 합성물을 만들지만 주인공의 현재 직장이나 생활권을 모두 알지 못한다.
- 직장 전달, 사칭, 위치 추론과 재유포는 서로 다른 참여자가 수행한다.
- 주인공에게 도착하는 익명 메시지는 계정명과 문장 습관이 조금씩 달라야 한다.
- 후반 수사기록에서도 확인된 가해자와 신원 미상의 참여자를 구분한다.
- 특정된 가해자가 처벌되어도 다른 저장자·재유포자와 확인되지 않은 복제본은 남는다.
- 이 규칙으로 사건의 수는 유지하되 한 명의 가해자가 모든 것을 아는 작위적인 구조를 피한다.

## 9. 장면별 상세 시나리오

### S00. 이 사람으로 시작하기

**화면**

- 흰 화면 중앙에 비어 있는 인물 카드가 놓여 있다.
- 정보가 정해질 때마다 카드에 이름, 회사, 관계, 동선이 차례로 붙는다.
- 마지막에는 카드가 모바일 잠금화면의 사용자 프로필로 변한다.

**화면 문구**

> 오늘 하루를 시작할 사람을 만들어 주세요.

정보 구성 후:

> 이름: `{{이름}}`  
> 나이: 28  
> 직장: `{{회사}}` `{{직무}}`  
> 생활권: `{{동네}}`  
> 가장 가까운 사람: `{{친구}}`

버튼:

> 이 사람으로 시작하기

버튼을 누른 직후 문장:

> 이제부터 화면 속의 ‘나’는 `{{이름}}`입니다.

**사용자 행동**

- 인물 정보를 확정한다.
- `이 사람으로 시작하기`를 누른다.

**분기 조건**

### S02. “혹시 본인 맞으세요?”

**화면**

- 업무 메시지를 읽는 도중 화면 상단에 모르는 계정의 알림이 나타난다.
- 계정명은 무작위 문자열이다.

**최초 알림**

> user_0471 · 혹시 `{{이름}}`님 맞으세요?

3초 뒤 두 번째 알림:

> 이거 지금 돌아다니는데 본인 아닌가 해서요.

링크 미리보기에는 회색으로 깨진 썸네일과 일부만 보이는 제목이 있다.

> `{{회사}}` 다니는 `{{이름}}`…

**사용자 선택**

1. `메시지를 연다`
2. `알림을 지운다`
3. `계정을 검색한다`

**분기 결과**

- 메시지를 열면 `discovery = direct`.
- 알림을 지우면 8초 뒤 `{{친구}}`가 같은 링크를 보내며 `discovery = friend`.
- 계정을 검색하면 계정은 이미 사라지고, 검색 결과에서 회사명이 먼저 노출되며 `discovery = workplace`.

**전환**

- 어떤 선택을 해도 S03의 검색 결과 화면으로 들어간다.

**의미**

- 사건이 이미 시작된 뒤에야 주인공에게 선택지가 주어진다는 사실을 보여준다.

### S03. 내 이름이 제목이 되었다

**화면**

- 가상 검색 서비스 화면.
- 검색창에는 사용자가 입력하지 않았는데 `{{이름}} {{회사}}`가 완성되어 있다.
- 첫 번째 결과에는 모자이크된 합성물 썸네일이 있다.
- 화면을 닫으려 하면 뒤에 같은 제목의 다른 결과가 이미 떠 있다.

**검색 결과 문구**

> `{{회사}}` 직원 `{{이름}}` 영상

> `{{계정}}` 본인 맞음? 사진 비교

> `{{동네}}` 사는 사람이라는데 아는 사람

**댓글 미리보기**

> 합성인지 아닌지 모르겠는데 얼굴은 똑같네.

> 회사 어디인지 찾음.

> 원본 저장한 사람?

**사용자 행동**

- 첫 결과를 누른다.
- 뒤로 가기를 누른다.
- 검색창의 이름을 지운다.

**반응**

- 결과를 누르면 썸네일은 끝까지 선명해지지 않고 제목·계정·조회 흔적만 커진다.
- 뒤로 가면 다른 플랫폼의 같은 결과가 나온다.
- 이름을 지우면 추천 검색어에 `{{이름}} 영상`, `{{이름}} 회사`가 남는다.

**분기 조건**

- S02의 `discovery`에 따라 최초 결과 위에 친구 메시지, 회사 메일 또는 익명 DM이 겹친다.

**전환**

- 가장 높은 노출 점수의 UI가 화면을 덮으며 주 경로로 진입한다.

**의미**

- 성적 이미지가 사람의 이름과 직장을 대체하는 첫 순간이다.

### S04. 주 경로 — 가장 먼저 무너지는 것

이 장면은 `primaryRoute`에 따라 달라진다.

#### S04-I. 이미지가 먼저 퍼지는 경로

**화면**

- 같은 합성물의 썸네일이 게시물, 짧은 영상, 프로필 사진, 단체방 캡처 형태로 복제된다.
- 원본은 보이지 않지만 주인공의 공개 프로필 사진과 비교하는 화면이 반복된다.
- 게시물을 올린 계정과 주인공에게 메시지를 보낸 계정은 서로 다르다.

**문구**

> 비교해 보니까 `{{계정}}`에 있던 사진이랑 같은 사람 맞음.

> archive_17 · 삭제되기 전에 저장.

> tell_hr · `{{회사}}` 직원이라던데 회사에도 보냄.

익명 메시지:

> user_0471 · 네가 아니라고 해도 사람들은 보고 싶은 것만 봐.

#### S04-L. 위치가 먼저 드러나는 경로

**화면**

- 서로 다른 익명 계정이 올린 `{{동네}}`, `{{역}}`, `{{장소}}` 정보가 지도 위에 연결된다.
- 화면에는 실제 지도 대신 추상적인 거리 블록과 이동선만 보인다.

**문구**

> map_82 · 예전 사진 배경 `{{역}}` 맞지?

> route_note · 회사는 여기고 집은 이쪽인 듯.

> user_0913 · 오늘 회색 코트 입었네.

익명 메시지:

> user_0913 · 온라인에만 있는 일 같아?

#### S04-R. 인간관계가 먼저 침범되는 경로

**화면**

- 주인공을 사칭한 새 계정이 `{{친구}}`, 가족, 동료에게 같은 링크를 전송한다.
- 보낸 사람 프로필에는 주인공의 이름과 공개 계정 사진이 들어 있다.
- 사칭 계정은 합성물을 처음 올린 계정과 다르다.

**문구**

`{{친구}}`:

> 너 계정 새로 만들었어? 방금 나한테 이상한 거 보냈어.

동료 수진:

> 이거 네가 보낸 거 아니지? 회사 메일로도 왔어.

사칭 계정:

> 내가 직접 올린 거야.

#### S04-W. 직장이 먼저 침범되는 경로

**화면**

- 사내 메일의 전체 수신 목록에 외부 메일 한 통이 들어온다.
- 사용자는 메일 내용보다 수신자 명단에서 팀원 이름들을 먼저 보게 된다.

**메일 제목**

> 귀사 직원 `{{이름}}` 관련 제보

**업무 메신저**

> 박 팀장 · 잠깐 통화 가능해요?

> 인사팀 · 관련 사실 확인을 위해 오늘 대외 업무는 중단해 주세요.

**공통 사용자 행동**

- 화면 하나를 닫을 수 있다.
- 닫은 화면은 사라지지만 다른 형태의 복제본이 뒤에 남는다.
- 계정명을 비교해도 같은 사람인지 서로 다른 사람인지 알 수 없다.

**전환**

- 두 번째로 높은 노출 축의 알림이 화면 위에 도착한다.

**의미**

- 사용자가 제공한 정보가 단독으로는 평범하지만 성적 이미지와 결합되면 현실 접근 경로가 된다는 사실을 보여준다.

> user_0471 · 어디까지 퍼졌는지 너만 몰라.

**전환**

**의미**

### S06. 무엇부터 해야 하지

**화면**

- 화면 중앙에는 합성물 게시물 하나가, 뒤에는 익명 메시지와 지인 알림이 겹쳐 있다.
- 세 가지 행동만 남고 나머지 UI는 어두워진다.

**사용자 선택**

1. `게시물을 신고한다`
2. `{{친구}}에게 연락한다`
3. `익명 계정을 차단한다`

**선택별 반응**

게시물 신고:

> 신고가 접수되었습니다. 검토 결과를 알려드리겠습니다.

그 직후:

> 새로운 게시물 3개에서 `{{이름}}`님이 언급되었습니다.

친구에게 연락:

> `{{친구}}` · 응. 나도 봤어. 네가 아닌 거 알아. 일단 내가 캡처해 둘게.

그 직후 친구 화면:

> 메시지 요청 12개

계정 차단:

> user_0471을 차단했습니다.

8초간 완전한 정적 뒤:

> user_0472 · 차단하면 끝날 줄 알았어?

**분기 조건**

- 각각 `response = report`, `contact`, `block`을 기록한다.
- 이후 피해 규모는 바뀌지 않는다.

**전환**

- 회사 발신 전화가 전체 화면을 덮는다.

**의미**

- 합리적인 초기 대응이 잘못된 것이 아니지만 이미 벌어진 복제와 현실 침입을 즉시 되돌리지는 못한다.

### S07. 회사가 나를 보호하는 방식

**화면**

- `{{회사}} 인사팀`의 수신 전화.
- 전화를 받으면 얼굴 없는 통화 UI 위에 인사 담당자의 말이 자막으로 나타난다.

**통화 문구**

> 관련 게시물이 사내 메일로 다수 접수됐습니다.

> 회사도 피해를 보고 있어서 사실관계 확인이 필요합니다.

> 오늘 예정된 외부 미팅은 다른 직원이 대신 진행하겠습니다.

**사용자 선택**

1. `합성된 가짜라고 설명한다`
2. `피해 사실을 알리고 보호를 요청한다`
3. `아무 말도 하지 않는다`

**선택별 반응**

설명:

> 네, 주장하시는 내용은 알겠습니다. 확인이 끝날 때까지 기다려 주세요.

보호 요청:

> 회사가 개인 사건에 직접 개입하기는 어렵습니다. 우선 외부 노출이 적은 업무로 조정하겠습니다.

침묵:

> 답변이 어려우신 것으로 기록하겠습니다. 결정 사항은 메일로 보내드리겠습니다.

**분기 조건**

- `workResponse`를 기록한다.
- S13의 퇴사 장면에서 회사가 사용하는 문장만 달라진다.

**전환**

- 통화 종료와 동시에 주인공이 담당하던 외부 일정의 참석자 이름이 박 팀장으로 바뀐다.

**의미**

- 보호라는 언어가 처음에는 합리적인 임시 조치처럼 보이지만, 이후 주인공의 역할과 발언권을 조금씩 제거하는 출발점이 된다.

### S08. 믿는다는 말 뒤의 거리

**화면**

- `{{가족}}` 전화, `{{친구}}` 메시지, 친구 단체방이 동시에 도착한다.
- 한 사람에게 답하는 동안 다른 연락은 계속 진동한다.

**메시지**

`{{가족}}`:

> 회사에서까지 연락 왔어. 이게 무슨 일이니. 당분간 밖에 나가지 마.

`{{친구}}`:

> 난 네 말 믿어. 나한테 온 계정이랑 링크는 내가 따로 정리할게.

3초 뒤:

> 그런데 나한테도 계속 네가 어디 있는지 물어봐. 내가 뭘 더 해야 해?

친구 단체방:

> 지금 이 얘기 여기서 하는 건 좀 아닌 것 같아.

> 당분간 모임은 미루자.

**사용자 선택**

1. `{{가족}} 전화를 받는다`
2. `{{친구}}에게 답한다`
3. `휴대전화를 무음으로 바꾼다`

**선택별 반응**

- 가족을 선택하면 “번호를 바꾸고 회사도 쉬고 당분간 내가 정한 곳에 있자”는 말이 들린다.
- 친구를 선택하면 친구가 `받은 링크`, `계정`, `도착 시간`을 묻는 표를 보내온다.
- 무음을 선택하면 진동은 멈추지만 잠금화면에 부재중 전화와 읽지 않은 메시지 숫자가 쌓인다.

**분기 조건**

- 선택한 인물은 S13에서 주인공의 일정을 직접 관리하려 든다.
- 선택하지 않은 인물도 관계를 끊지는 않지만, 이후 대화는 안부보다 사건 확인으로만 이루어진다.

**전환**

- 화면 밝기가 밤으로 바뀌고 공동현관 알림이 나타난다.

**의미**

- 주변인이 피해자를 믿고 곁에 남더라도 평범한 관계는 사라지고, 보호·감시·증거 정리만 남을 수 있음을 보여준다.

### S09. 온라인에만 있는 일이 아니다

**문구**

## 10. 장면 간 핵심 인과관계

```text
평범한 개인정보
    ↓
정체를 숨긴 대학 동문이 사진·신상정보를 익명 대화방에 제공
    ↓
별도의 참여자가 성적 합성물을 제작
    ↓
저장자 / 위치 추적자 / 사칭 계정 / 직장 전달자가 분산해서 가담
    ↓
피해자는 수개월 뒤 지인이나 익명 메시지를 통해 가장 늦게 피해를 인지
    ↓
신고·삭제·채증·수사 시작
    ↓
개별 게시물 삭제와 동시에 복제본 재등장
    ↓
모든 지인이 잠재적 가해자로 보이고, 보호를 명목으로 직장·관계·일정의 통제권 상실
    ↓
다른 피해자들의 개별 사건과 자료가 뒤늦게 연결
    ↓
대학 동문 A와 제작자 B 특정·판결
    ↓
신원 미상 참여자, 새로운 유포자와 검색 결과는 존속
    ↓
새 관계보다 피해 정보가 먼저 도착
```

## 11. 문구 작성 원칙

- 가해자의 문장은 길지 않게 쓴다. 짧고 구체적인 현실 정보가 노골적인 욕설보다 강하게 작동한다.
- 성적 모욕의 언어와 주변 반응은 직접적으로 쓰고, 합성물 자체를 관람자가 선정물로 소비할 수 있는 방식으로 재현한다.
- 주변 인물은 피해자를 대놓고 비난하기보다 `회사도 피해다`, `우리가 어떻게 해야 할지 모르겠다`, `안전을 위해 쉬어라` 같은 말로 주인공의 역할과 선택권을 줄인다.
- 친구와 가족은 사라지지 않는다. 대신 안부·농담·일상 대화가 증거 정리, 위치 확인과 일정 관리로 대체되어 평범한 관계가 사라지게 한다.
- 전지적 해설자는 두지 않는다. 후반의 수사기록과 판결문만 주인공이 당시 알 수 없었던 사실을 지연해서 공개한다.
- 공식 지원기관의 인물은 냉담한 악역으로 만들지 않는다. 도움은 실제로 작동하지만 복제와 사회적 피해를 소급해서 없앨 수 없다는 한계를 사건의 동시 진행으로 표현한다.
- 법적 처벌을 무가치하다고 표현하지 않는다. 처벌이 성취되어도 이미 발생한 현실 피해가 자동 복구되지 않는다는 차이를 보여준다.

## 12. 사실성 근거와 법적 표현 메모

2026년 9월 현재 확인한 공식 자료를 기준으로 한다. 이후 실제 구현에서 법률명, 기관명이나 절차를 노출할 때 최신 상태를 다시 확인할 필요는 없다.

   [중앙디지털성범죄피해자지원센터 — 지원 신청 방법](https://d4u.stop.or.kr/ko/support/content/guide)

   [중앙디지털성범죄피해자지원센터 — 삭제지원 안내](https://d4u.stop.or.kr/ko/support/delete/info)

7. 2025년 공식 피해지원 보고서에서는 지속 지원 피해자가 전체 지원 피해자의 45.1%였고 전년보다 26.3% 증가했다. 가해자 특정 불가가 29.0%로 가장 높았으며, 피해자는 평균 약 1.7개의 피해 유형을 중복 경험했다. 장기 지원, 불확실한 가해자와 복합 피해를 결합한 현재 구조는 이 통계에서 모티브를 얻었다. [성평등가족부 — 2025 디지털성범죄 피해자 지원 보고서 발간](https://www.mogef.go.kr/nw/rpd/nw_rpd_s001d.do?bbtSn=711001&mid=news405)
