# 디지털 성범죄 1인칭 웹 작품 시나리오 v0.1

## 1. 문서 정보

- 작업명: **《검색 가능한 사람》**
- 형식: 개인 모바일 기기에서 실행되는 1인칭 인터랙티브 웹 작품
- 대상: 일반 대중
- 예상 체험 시간: 16~18분
- 주인공: 한국에 사는 20대 후반 여성 직장인
- 중심 사건: 성적 합성물 제작·유포에서 시작해 신원 특정, 사칭, 위치 노출, 협박, 직장·관계 붕괴와 재유포로 확장되는 복합 피해
- 결말: 법적 절차가 진행되거나 최초 가해자가 처벌되어도 사회적 신원과 삶이 복구되지 않는 파국
- 문서 범위: 화면, 문구, 사용자 행동, 서사 분기와 연출
- 이번 문서에서 다루지 않는 것: 개인정보 입력 방식의 구현 조건과 관련 정책

이 문서는 특정 피해자의 실제 사건을 재현하는 기록물이 아니다. 여러 디지털 성범죄 피해 유형을 하나의 최악 경로로 압축한 허구의 시나리오다.

## 2. 작품의 한 문장

> 한 사람이 입력한 몇 개의 평범한 정보가 성적 합성물과 결합된 뒤, 삭제·신고·판결로도 회수할 수 없는 새로운 사회적 신원이 되어 그 사람의 현실을 대신한다.

## 3. 작품의 중심 명제

이 작품의 분기는 피해를 피하는 방법을 선택하게 하지 않는다.

> 사용자의 선택은 **파멸의 여부**가 아니라 **무엇을 통해 피해를 처음 알게 되는지**, **무엇이 먼저 무너지는지**, **어떤 흔적을 더 오래 바라보게 되는지**를 바꾼다.

피해 규모는 사용자의 대응 선택 때문에 커지지 않는다. 범죄를 저지르고, 저장하고, 재유포하고, 신원을 추적하고, 현실 관계로 전달하는 사람들의 행동 때문에 커진다.

## 4. 서사에서 말하는 1차·2차·3차·N차 피해

아래 구분은 법률상 공식 분류가 아니라 작품의 극적 구조를 위한 명칭이다.

| 단계 | 사건                                             | 무너지는 영역        |
| ---- | ------------------------------------------------ | -------------------- |
| 1차  | 성적 합성물 제작과 최초 게시                     | 초상·성적 자기결정권 |
| 2차  | 저장, 복제, 재게시, 링크 공유                    | 통제권과 삭제 가능성 |
| 3차  | 실명·직장·생활권 결합, 사칭                      | 신원과 물리적 안전감 |
| 4차  | 가족·친구·직장으로 직접 전송                     | 인간관계와 생계      |
| 5차  | 구경, 조롱, 해명 요구, 기사화, 검색어화          | 존엄과 공적 인격     |
| N차  | 삭제 뒤 재유포, 판결 뒤 재등장, 새 관계로 재침투 | 미래와 시간          |

## 5. 고정된 주인공 골격

사용자가 입력하거나 생성한 값은 아래 변수에 치환된다. 서사의 사회적 관계와 직장 생활 골격은 고정한다.

| 변수           | 의미                        | 기본 예시          |
| -------------- | --------------------------- | ------------------ |
| `{{이름}}`     | 주인공 이름                 | 윤서아             |
| `{{회사}}`     | 현재 직장                   | 다온리빙           |
| `{{직무}}`     | 직무                        | 브랜드 운영팀 사원 |
| `{{동네}}`     | 거주 생활권                 | 상수동             |
| `{{역}}`       | 출퇴근에 이용하는 역        | 상수역             |
| `{{장소}}`     | 자주 방문하는 장소          | 회사 근처 카페     |
| `{{친구}}`     | 가장 가까운 친구            | 지민               |
| `{{가족}}`     | 가장 자주 연락하는 가족     | 엄마               |
| `{{계정}}`     | 주로 쓰는 공개 계정         | seo_a.day          |
| `{{연락처끝}}` | 연락처 일부를 연상시키는 값 | 4821               |

### 조연

- `{{친구}}`: 처음에는 주인공을 믿지만 자신도 표적이 되자 점차 관계에서 물러난다.
- `{{가족}}`: 보호하려 하지만 주인공의 외출·직장·이름 사용을 제한하는 방식으로 반응한다.
- 박 팀장: 개인적으로는 곤란해하지만 회사의 평판을 우선한다.
- 인사 담당자: 정중한 문장으로 주인공을 업무와 조직에서 분리한다.
- 동료 수진: 게시물을 보았지만 모른 척하며, 시간이 지난 뒤 다른 동료에게 링크가 전달되었다는 사실을 알린다.
- 최초 가해자: 얼굴과 직접 음성 없이 계정, 메시지와 사건 기록으로만 존재한다.
- 재유포자들: 서로 다른 익명 계정과 화면의 점으로 표현된다. 하나의 악역이 아니라 확산 구조로 보인다.

## 6. 1인칭 표현 규칙

1. 모든 사건은 주인공의 스마트폰 안에서만 발견된다.
2. 주인공의 얼굴이나 신체를 외부 카메라 시점으로 보여주지 않는다.
3. 가해자 시점, 가해자의 작업 화면, 범죄 제작 과정은 보여주지 않는다.
4. 주인공의 감정을 내레이션으로 규정하지 않는다. 화면을 닫는 손짓, 읽지 못한 문장, 반복되는 진동과 관계의 침묵으로 전달한다.
5. 선택 결과에 성공, 실패, 정답, 점수를 붙이지 않는다.
6. 실제 서비스와 혼동되지 않도록 플랫폼과 회사 UI는 모두 가상으로 만든다.
7. 성적 합성물은 모자이크·색면·깨진 썸네일로만 표현한다. 공포는 이미지 자체가 아니라 제목, 검색 결과, 조회 흔적과 주변인의 반응으로 만든다.

## 7. 작품 상태와 분기 규칙

### 7.1 노출 축

사용자가 구성한 인물 정보로 네 개의 노출 축을 계산한다.

| 입력 정보             | 이미지 노출 `I` | 위치 노출 `L` | 관계 노출 `R` | 직장 노출 `W` |
| --------------------- | --------------: | ------------: | ------------: | ------------: |
| 인물 이미지·외모 설정 |              +3 |             0 |             0 |             0 |
| 공개 계정             |              +1 |            +1 |            +1 |            +1 |
| 동네                  |               0 |            +3 |             0 |             0 |
| 역·자주 가는 장소     |               0 |            +3 |             0 |            +1 |
| 친구·가족 관계        |               0 |             0 |            +3 |             0 |
| 회사명·직무           |               0 |             0 |            +1 |            +3 |
| 연락 수단             |               0 |            +1 |            +2 |            +1 |

- 가장 높은 축이 `primaryRoute`가 된다.
- 두 번째 축이 `secondaryRoute`가 된다.
- 동점이면 같은 인물로 재접속했을 때 결과가 유지되도록 인물 값에서 만든 고정 시드로 결정한다.
- 주 경로는 약 70초, 보조 경로는 약 35초 동안 상세히 경험한다.
- 나머지 경로도 후반의 확산 화면에 짧게 등장한다.
- 따라서 어떤 입력 조합에서도 결말은 같지만, 무너지는 순서와 직접 보게 되는 내용은 달라진다.

## 9. 장면별 상세 시나리오

### S00. 이 사람으로 시작하기

**화면**

- 흰 화면 중앙에 비어 있는 인물 카드가 놓여 있다.
- 정보가 정해질 때마다 카드에 이름, 회사, 관계, 동선이 차례로 붙는다.
- 마지막에는 카드가 모바일 잠금화면의 사용자 프로필로 변한다.

**화면 문구**

> 오늘 하루를 시작할 사람을 만들어 주세요.

정보 구성 후:

> 이름: `{{이름}}`  
> 나이: 28  
> 직장: `{{회사}}` `{{직무}}`  
> 생활권: `{{동네}}`  
> 가장 가까운 사람: `{{친구}}`

버튼:

> 이 사람으로 시작하기

버튼을 누른 직후 문장:

> 이제부터 화면 속의 ‘나’는 `{{이름}}`입니다.

**사용자 행동**

- 인물 정보를 확정한다.
- `이 사람으로 시작하기`를 누른다.

**분기 조건**

- 입력 정보로 `I`, `L`, `R`, `W` 점수와 주·보조 경로를 정한다.

**전환**

- 인물 카드가 화면 전체로 확대되며 잠금화면으로 변한다.

**의미**

- 사용자가 관찰자가 아니라 이후 모든 메시지에서 ‘나’라고 불릴 사람임을 확정한다.

### S01. 평범한 월요일

**화면**

- 잠금화면 시각은 `07:42`.
- 배경은 `{{동네}}`에서 찍은 평범한 아침 풍경이다.
- 알림 세 개가 천천히 쌓인다.

**알림 문구**

> `{{가족}}` · 어제 늦게 들어갔어? 저녁에 전화해.

> `{{친구}}` · 어제 찍은 사진 보내줘 ㅋㅋ

> 워크온 · 박 팀장: 오늘 10시 회의 자료만 한 번 확인해 주세요.

피드에 들어가면:

> `{{계정}}`님, 1년 전 오늘의 사진이 있습니다.

**사용자 행동**

- 가족 알림을 옆으로 밀어 둔다.
- 친구 메시지에 하트 반응을 보낸다.
- 업무 메시지를 읽는다.

순서는 자유롭다. 아무것도 하지 않아도 12초 뒤 업무 화면으로 전환된다.

**분기 조건**

- 없음.

**전환**

- 밝은 배경의 업무 메신저로 자연스럽게 이동한다.

**의미**

- 이후 무너질 직장, 가족, 친구 관계를 짧은 시간 안에 일상으로 인식시킨다.

### S02. “혹시 본인 맞으세요?”

**화면**

- 업무 메시지를 읽는 도중 화면 상단에 모르는 계정의 알림이 나타난다.
- 계정명은 무작위 문자열이다.

**최초 알림**

> user_0471 · 혹시 `{{이름}}`님 맞으세요?

3초 뒤 두 번째 알림:

> 이거 지금 돌아다니는데 본인 아닌가 해서요.

링크 미리보기에는 회색으로 깨진 썸네일과 일부만 보이는 제목이 있다.

> `{{회사}}` 다니는 `{{이름}}`…

**사용자 선택**

1. `메시지를 연다`
2. `알림을 지운다`
3. `계정을 검색한다`

**분기 결과**

- 메시지를 열면 `discovery = direct`.
- 알림을 지우면 8초 뒤 `{{친구}}`가 같은 링크를 보내며 `discovery = friend`.
- 계정을 검색하면 계정은 이미 사라지고, 검색 결과에서 회사명이 먼저 노출되며 `discovery = workplace`.

**전환**

- 어떤 선택을 해도 S03의 검색 결과 화면으로 들어간다.

**의미**

- 사건이 이미 시작된 뒤에야 주인공에게 선택지가 주어진다는 사실을 보여준다.

### S03. 내 이름이 제목이 되었다

**화면**

- 가상 검색 서비스 화면.
- 검색창에는 사용자가 입력하지 않았는데 `{{이름}} {{회사}}`가 완성되어 있다.
- 첫 번째 결과에는 모자이크된 합성물 썸네일이 있다.
- 화면을 닫으려 하면 뒤에 같은 제목의 다른 결과가 이미 떠 있다.

**검색 결과 문구**

> `{{회사}}` 직원 `{{이름}}` 영상

> `{{계정}}` 본인 맞음? 사진 비교

> `{{동네}}` 사는 사람이라는데 아는 사람

**댓글 미리보기**

> 합성인지 아닌지 모르겠는데 얼굴은 똑같네.

> 회사 어디인지 찾음.

> 원본 저장한 사람?

**사용자 행동**

- 첫 결과를 누른다.
- 뒤로 가기를 누른다.
- 검색창의 이름을 지운다.

**반응**

- 결과를 누르면 썸네일은 끝까지 선명해지지 않고 제목·계정·조회 흔적만 커진다.
- 뒤로 가면 다른 플랫폼의 같은 결과가 나온다.
- 이름을 지우면 추천 검색어에 `{{이름}} 영상`, `{{이름}} 회사`가 남는다.

**분기 조건**

- S02의 `discovery`에 따라 최초 결과 위에 친구 메시지, 회사 메일 또는 익명 DM이 겹친다.

**전환**

- 가장 높은 노출 점수의 UI가 화면을 덮으며 주 경로로 진입한다.

**의미**

- 성적 이미지가 사람의 이름과 직장을 대체하는 첫 순간이다.

### S04. 주 경로 — 가장 먼저 무너지는 것

이 장면은 `primaryRoute`에 따라 달라진다.

#### S04-I. 이미지가 먼저 퍼지는 경로

**화면**

- 같은 합성물의 썸네일이 게시물, 짧은 영상, 프로필 사진, 단체방 캡처 형태로 복제된다.
- 원본은 보이지 않지만 주인공의 공개 프로필 사진과 비교하는 화면이 반복된다.

**문구**

> 비교해 보니까 `{{계정}}`에 있던 사진이랑 같은 사람 맞음.

> 삭제되기 전에 저장.

> `{{회사}}` 직원이라던데 회사에도 보냄.

익명 메시지:

> 네가 아니라고 해도 사람들은 보고 싶은 것만 봐.

#### S04-L. 위치가 먼저 드러나는 경로

**화면**

- `{{동네}}`, `{{역}}`, `{{장소}}`가 지도 위에 연결된다.
- 화면에는 실제 지도 대신 추상적인 거리 블록과 이동선만 보인다.

**문구**

> `{{역}}`에서 매일 내리던데.

> 회사는 여기고 집은 이쪽인 듯.

> 오늘 회색 코트 입었네.

익명 메시지:

> 온라인에만 있는 일 같아?

#### S04-R. 인간관계가 먼저 침범되는 경로

**화면**

- 주인공을 사칭한 새 계정이 `{{친구}}`, 가족, 동료에게 같은 링크를 전송한다.
- 보낸 사람 프로필에는 주인공의 이름과 공개 계정 사진이 들어 있다.

**문구**

`{{친구}}`:

> 너 계정 새로 만들었어? 방금 나한테 이상한 거 보냈어.

동료 수진:

> 이거 네가 보낸 거 아니지? 회사 메일로도 왔어.

사칭 계정:

> 내가 직접 올린 거야.

#### S04-W. 직장이 먼저 침범되는 경로

**화면**

- 사내 메일의 전체 수신 목록에 외부 메일 한 통이 들어온다.
- 사용자는 메일 내용보다 수신자 명단에서 팀원 이름들을 먼저 보게 된다.

**메일 제목**

> 귀사 직원 `{{이름}}` 관련 제보

**업무 메신저**

> 박 팀장 · 잠깐 통화 가능해요?

> 인사팀 · 관련 사실 확인을 위해 오늘 대외 업무는 중단해 주세요.

**공통 사용자 행동**

- 화면 하나를 닫을 수 있다.
- 닫은 화면은 사라지지만 다른 형태의 복제본이 뒤에 남는다.

**전환**

- 두 번째로 높은 노출 축의 알림이 화면 위에 도착한다.

**의미**

- 사용자가 제공한 정보가 단독으로는 평범하지만 성적 이미지와 결합되면 현실 접근 경로가 된다는 사실을 보여준다.

### S05. 보조 경로 — 화면 밖으로 나온 사건

**화면**

- `secondaryRoute`의 장면을 35초 동안 보여준다.
- 나머지 두 노출 축은 잠금화면 알림으로만 나타난다.

**보조 경로 문구 예시**

- 이미지 경로: `새로운 게시물에서 회원님의 계정이 언급되었습니다.`
- 위치 경로: `공동현관 호출 · 응답 없음 · 4회`
- 관계 경로: `{{가족}} · 부재중 전화 6통`
- 직장 경로: `인사팀 · 면담 일정이 등록되었습니다.`

**공통 익명 메시지**

> 어디까지 퍼졌는지 너만 몰라.

> 한 군데 지우면 다른 데 올리면 돼.

**사용자 행동**

- 도착한 알림 중 하나를 연다.
- 열지 않은 알림도 숫자가 계속 증가한다.

**분기 조건**

- 사용자가 연 알림의 축이 이후 S08 또는 S09에서 먼저 재등장한다.

**전환**

- 모든 알림이 멈추고 화면 하단에 세 가지 대응 버튼이 나타난다.

**의미**

- ‘인터넷 게시물’이 아니라 직장·가족·집으로 들어오는 사건임을 확정한다.

### S06. 무엇부터 해야 하지

**화면**

- 화면 중앙에는 합성물 게시물 하나가, 뒤에는 익명 메시지와 지인 알림이 겹쳐 있다.
- 세 가지 행동만 남고 나머지 UI는 어두워진다.

**사용자 선택**

1. `게시물을 신고한다`
2. `{{친구}}에게 연락한다`
3. `익명 계정을 차단한다`

**선택별 반응**

게시물 신고:

> 신고가 접수되었습니다. 검토 결과를 알려드리겠습니다.

그 직후:

> 새로운 게시물 3개에서 `{{이름}}`님이 언급되었습니다.

친구에게 연락:

> `{{친구}}` · 응. 나도 봤어. 네가 아닌 거 알아. 일단 내가 캡처해 둘게.

그 직후 친구 화면:

> 메시지 요청 12개

계정 차단:

> user_0471을 차단했습니다.

8초간 완전한 정적 뒤:

> user_0472 · 차단하면 끝날 줄 알았어?

**분기 조건**

- 각각 `response = report`, `contact`, `block`을 기록한다.
- 이후 피해 규모는 바뀌지 않는다.

**전환**

- 회사 발신 전화가 전체 화면을 덮는다.

**의미**

- 합리적인 초기 대응이 잘못된 것이 아니지만 이미 벌어진 복제와 현실 침입을 즉시 되돌리지는 못한다.

### S07. 회사가 나를 보호하는 방식

**화면**

- `{{회사}} 인사팀`의 수신 전화.
- 전화를 받으면 얼굴 없는 통화 UI 위에 인사 담당자의 말이 자막으로 나타난다.

**통화 문구**

> 관련 게시물이 사내 메일로 다수 접수됐습니다.

> 회사도 피해를 보고 있어서 사실관계 확인이 필요합니다.

> 우선 오늘부터 대외 업무와 사내 메신저 사용을 중단해 주세요.

> 다른 직원에게 직접 연락하거나 해명하는 것도 잠시 삼가 주세요.

**사용자 선택**

1. `합성된 가짜라고 설명한다`
2. `피해 사실을 알리고 보호를 요청한다`
3. `아무 말도 하지 않는다`

**선택별 반응**

설명:

> 네, 주장하시는 내용은 알겠습니다. 확인이 끝날 때까지 기다려 주세요.

보호 요청:

> 회사가 개인 사건에 직접 개입하기는 어렵습니다. 출근하지 않는 것이 현재로서는 가장 안전합니다.

침묵:

> 답변이 어려우신 것으로 기록하겠습니다. 결정 사항은 메일로 보내드리겠습니다.

**분기 조건**

- `workResponse`를 기록한다.
- S13의 퇴사 장면에서 회사가 사용하는 문장만 달라진다.

**전환**

- 통화 종료와 동시에 사내 메신저에서 주인공의 상태가 `오프라인`으로 바뀐다.

**의미**

- 보호라는 언어가 주인공의 업무·발언·관계를 제거하는 방식으로 작동한다.

### S08. 믿는다는 말 뒤의 거리

**화면**

- `{{가족}}` 전화, `{{친구}}` 메시지, 친구 단체방이 동시에 도착한다.
- 한 사람에게 답하는 동안 다른 연락은 계속 진동한다.

**메시지**

`{{가족}}`:

> 회사에서까지 연락 왔어. 이게 무슨 일이니. 당분간 밖에 나가지 마.

`{{친구}}`:

> 난 네 말 믿어. 그런데 나한테도 계속 링크 보내고 네가 어디 있는지 물어봐.

친구 단체방:

> 지금 이 얘기 여기서 하는 건 좀 아닌 것 같아.

> 당분간 모임은 미루자.

**사용자 선택**

1. `{{가족}} 전화를 받는다`
2. `{{친구}}에게 답한다`
3. `휴대전화를 무음으로 바꾼다`

**선택별 반응**

- 가족을 선택하면 “번호를 바꾸고 회사도 그만두자”는 말이 들린다.
- 친구를 선택하면 “내가 어떻게 도와야 하는지 모르겠다”는 답이 온다.
- 무음을 선택하면 진동은 멈추지만 잠금화면에 부재중 전화와 읽지 않은 메시지 숫자가 쌓인다.

**분기 조건**

- 선택한 인물은 S13까지 연락을 유지한다.
- 선택하지 않은 관계는 S13에서 먼저 끊어진다.

**전환**

- 화면 밝기가 밤으로 바뀌고 공동현관 알림이 나타난다.

**의미**

- 주변인이 피해자를 믿더라도 공포와 부담 때문에 관계에서 후퇴할 수 있음을 보여준다.

### S09. 온라인에만 있는 일이 아니다

**화면**

- 시각 `23:17`.
- 공동현관 호출 기록이 네 번 쌓여 있다.
- 통화 화면에는 영상도 음성도 없다.
- 익명 메시지에 `{{역}}`과 옷차림이 등장한다.

**문구**

> 오늘도 `{{역}}`에서 내렸네.

> 집 불은 켜져 있는데 왜 전화를 안 받아?

> 이사해도 다시 찾으면 돼.

**사용자 행동**

- 현관 호출을 거절한다.
- 집 조명 앱을 끈다.
- `{{가족}}` 또는 `{{친구}}`에게 현재 위치를 보낸다.

**반응**

- 어떤 행동을 해도 화면 속 지도에는 이미 `{{동네}}`가 표시되어 있다.
- 10초 뒤 호출은 멈추지만 `배송 완료 · 주문하지 않은 상품` 알림이 도착한다.

**분기 조건**

- 위치 경로가 주 경로였다면 익명 메시지가 먼저 온다.
- 다른 경로였다면 공동현관 호출 뒤 메시지가 온다.

**전환**

- 화면이 완전히 어두워졌다가 `3일 뒤`라는 날짜로 켜진다.

**의미**

- 정보 노출이 집 안에서조차 안전하다는 감각을 없앤다.

### S10. 피해를 증명하기 위해 피해를 다시 본다

**화면**

- 공식 피해지원기관의 모바일 상담·삭제지원 접수 화면을 닮은 가상 UI.
- 상담원이 먼저 짧게 인사하고 필요한 정보가 세 칸으로 나타난다.

**상담 문구**

> 지금 확인된 피해부터 함께 정리하겠습니다.

> 삭제와 모니터링을 위해 게시물 주소, 피해물을 특정할 수 있는 자료, 검색 가능한 키워드가 필요합니다.

**입력 영역**

- `게시물 URL`
- `피해 촬영물 또는 화면 자료`
- `게시물 제목·계정 등 검색 키워드`

**사용자 선택**

1. `지금 확인한 주소만 제출한다`
2. `더 찾아서 목록을 만든다`
3. `상담원에게 먼저 설명한다`

**선택별 장면**

지금 제출:

> 4건이 접수되었습니다.

화면 뒤에는 아직 제출되지 않은 게시물 알림이 남는다.

더 찾아보기:

- 사용자가 `URL 추가`를 누를 때마다 모자이크된 게시물을 다시 열어야 한다.
- 네 번째 URL부터 화면 상단의 이름 대신 `증거 04`, `증거 05`가 표시된다.

상담원에게 설명:

> 한 번에 전부 설명하지 않으셔도 됩니다. 지금 확인할 수 있는 것부터 진행하겠습니다.

설명 도중에도 새로운 게시물 알림이 뒤에서 쌓인다.

**공통 접수 문구**

> 상담이 접수되었습니다. 확인 후 삭제지원과 유포 모니터링 절차를 안내드리겠습니다.

경찰 신고 화면으로 이어지는 문구:

> 가해자를 알 수 없는 경우에도 유포 시점, 계정 ID, 대화 기록 등 확인 가능한 자료를 제출해 주세요.

**분기 조건**

- `evidenceMode = current`, `search`, `counsel` 중 하나를 기록한다.
- S11의 결과보고서 숫자와 발견 경로가 달라지지만 피해 결말은 바뀌지 않는다.

**전환**

- 접수 완료 화면 위로 달력이 빠르게 12일 이동한다.

**의미**

- 지원기관의 존재와 도움을 부정하지 않으면서도, 삭제를 요청하기 위해 피해 자료를 특정하고 반복해서 마주해야 하는 부담을 체험하게 한다.

### S11. 삭제되었습니다

**화면**

- 공식 결과 알림과 플랫폼 신고 결과가 차례로 도착한다.

**문구**

> 신고한 게시물이 운영정책 위반으로 삭제되었습니다.

> 삭제 확인 12건 · 처리 중 6건 · 신규 확인 9건

숫자는 해당 인물의 허구적 사건 진행 상태이며 실제 기관 통계로 표시하지 않는다.

**연출**

- 모든 진동과 소리가 8초 동안 멈춘다.
- 흰 빈 화면만 남는다.
- 사용자가 화면을 한 번 누르면 새 알림 하나가 나타난다.

**새 알림**

> 새 복제 게시물이 발견되었습니다.

게시물 문구:

> 지워졌길래 다시 올림.

> 원래 링크 막혀서 여기 백업.

**사용자 행동**

- `새 주소 추가`를 누른다.
- `나중에 확인`을 누른다.

**반응**

- 새 주소를 추가하면 처리 중 숫자와 함께 신규 확인 숫자도 증가한다.
- 나중에 확인을 누르면 잠금화면 미리보기에 신규 발견 알림이 남는다.

**전환**

- 게시물 하나가 여러 사람의 채팅방과 피드로 갈라진다.

**의미**

- 삭제가 의미 없는 것이 아니라, 개별 삭제가 복제 가능성을 소급해서 없애지는 못한다는 사실을 보여준다.

---

### S12. 도와준다는 사람도 링크를 보낸다

**화면**

- 주인공을 조롱하는 게시물과 옹호하는 게시물이 같은 속도로 확산된다.
- 옹호 게시물도 주인공의 얼굴과 피해 게시물 제목을 다시 첨부한다.

**문구**

옹호 계정:

> 이건 합성입니다. 비교해 보면 바로 알 수 있어요.

첨부:

> `{{계정}}` 원본 사진 / 피해 합성물 비교

구경 계정:

> 합성 논란 정리. 회사랑 실명까지 다 나옴.

익명 댓글:

> 가짜라면서 왜 회사를 쉬지?

> 본인이 직접 해명하면 되잖아.

**사용자 행동**

- 옹호 게시물에 `사진을 내려 달라`고 요청한다.
- 사실관계를 설명하는 글을 작성한다.
- 아무것도 올리지 않는다.

**선택별 반응**

사진 삭제 요청:

> 피해자를 도우려던 건데 왜 저한테 뭐라고 하세요?

해명문 작성:

- 사용자가 작성한 문장 일부가 잘려 `{{이름}} 본인 입장`이라는 새 게시물 제목으로 재유통된다.

침묵:

> 당사자는 아직 아무 입장도 없음.

**분기 조건**

- 선택에 따라 재유포 게시물의 제목만 바뀐다.
- 모든 경로에서 검색 추천어 세 개가 고정된다.

**고정 검색 추천어**

> `{{이름}} 영상`  
> `{{이름}} 회사`  
> `{{이름}} 입장문`

**전환**

- 검색 추천어가 캘린더 일정으로 변하며 `5주 뒤`로 이동한다.

**의미**

- 악의적인 재유포뿐 아니라 구경, 해명 요구, 잘못된 옹호도 피해자의 얼굴과 사건을 계속 유통시킬 수 있음을 보여준다.

### S13. 일상이 사건 관리표가 되었다

**화면**

- 달력의 원래 일정이 모두 사라지고 사건 관련 일정만 남는다.

**달력**

> 월 · 인사팀 면담  
> 화 · 피해 게시물 URL 정리  
> 수 · 수사기관 자료 제출  
> 목 · 이사할 방 확인  
> 금 · 삭제지원 진행 결과 확인

**관계 메시지**

S08에서 선택하지 않은 인물:

> 미안해. 나한테도 계속 연락이 와. 당분간 연락하지 말자.

S08에서 선택한 인물:

> 네가 힘든 건 아는데 나도 이제 어떻게 해야 할지 모르겠어.

**회사 메시지**

`workResponse = explain`:

> 사실관계와 별개로 현재 업무 복귀는 어렵다고 판단했습니다.

`workResponse = requestHelp`:

> 보호 조치를 계속 유지하기 위해 휴직 또는 퇴사 여부를 결정해 주세요.

`workResponse = silence`:

> 정해진 기간 내 회신이 없어 인사 절차를 진행합니다.

**사용자 선택**

1. `계속 출근하겠다고 한다`
2. `휴직을 신청한다`
3. `퇴사한다`

**선택별 반응**

- 계속 출근: 사내 출입 QR이 `승인 대기` 상태가 되고 동료 대화방이 조용해진다.
- 휴직: 업무 계정이 비활성화되고 달력에서 사람 이름이 모두 사라진다.
- 퇴사: 회사 이름은 사라지지만 검색 결과 제목에는 이전 회사명이 계속 남는다.

**분기 조건**

- `employmentExit = denied`, `leave`, `resign`을 기록한다.
- S14의 채용 담당자 문구에만 반영된다.

**전환**

- 달력이 세 달 뒤로 넘어가고 새로운 채용 앱이 열린다.

**의미**

- 일을 할 권리와 경제적 생존이 범죄의 후속 피해로 무너지는 장면이다.

### S14. 새로운 곳에서도 먼저 도착해 있는 이름

**화면**

- 다른 프로필 사진과 축약된 이름으로 만든 채용 프로필.
- 서류 합격 알림이 잠시 나타난다.

**초기 문구**

> 축하합니다. 2차 면접 대상자로 선정되었습니다.

5초 뒤 채용 담당자 메시지:

> 공개 검색 결과에서 지원자님과 관련된 게시물을 확인했습니다.

> 사실관계를 확인할 수 있는 자료가 있을까요?

**사용자 선택**

1. `합성물 피해라고 설명한다`
2. `수사·삭제지원 자료를 보낸다`
3. `지원 자체를 철회한다`

**선택별 반응**

설명:

> 내부 검토 후 연락드리겠습니다.

자료 전송:

> 민감한 사안으로 당사에서 판단하기 어렵습니다.

철회:

> 지원이 취소되었습니다.

**공통 결과**

> 채용 절차가 종료되었습니다.

동시에 새 번호로 익명 메시지가 도착한다.

> 번호 바꿨네. `{{연락처끝}}` 맞지?

**분기 조건**

- 이전 직장 선택에 따라 채용 담당자가 `휴직 중`, `퇴사 사유`, `근무 공백`을 추가로 묻는다.

**전환**

- 화면이 잠기고 날짜가 아홉 달 뒤로 바뀐다.

**의미**

- 피해가 과거의 사건이 아니라 미래의 모든 자기소개보다 먼저 발견되는 경력이 되었음을 보여준다.

### S15. 가해자를 찾았습니다

**화면**

- 수사 진행 알림과 삭제지원 결과가 같은 날 도착한다.
- 처음으로 제도적 진전이 명확히 보인다.

**문구**

> 최초 게시 계정의 사용자가 특정되었습니다.

> 해당 사건은 수사를 거쳐 재판 절차로 진행될 예정입니다.

> 삭제지원과 유포 모니터링은 계속됩니다.

**사용자 선택**

1. `사건 진행 내용을 연다`
2. `나중에 확인한다`

**선택별 반응**

사건 내용 열기:

- 사건 문서의 `피해자` 칸에 `{{이름}}`이 반복된다.
- 첨부 증거 목록의 제목마다 검색어와 게시물명이 다시 나타난다.
- `legalView = open`.

나중에 확인:

- 잠금화면에 `사건 진행`, `새 복제본 발견`, `삭제 완료` 알림이 함께 남는다.
- `legalView = defer`.

**공통 익명 게시물**

> 올린 사람 잡혔다는데 파일 있는 사람은 아직 많음.

**전환**

- 재판 진행 날짜가 빠르게 지나가며 `1년 7개월 뒤`로 이동한다.

**의미**

- 가해자 특정과 처벌 가능성은 중요하지만, 최초 가해자를 찾는 일과 이미 분산된 피해를 회수하는 일은 같지 않음을 보여준다.

### S16. 사건은 종결되었습니다

**화면**

- 단정하고 조용한 사건 알림 화면.
- 화려한 연출 없이 한 문장만 나타난다.

**문구**

> 피고인에 대한 판결이 확정되었습니다.

사용자가 문장을 읽고 4초가 지나면:

> 사건 상태: 종결

그 아래 새 알림:

> 유포 모니터링 · 새로운 복제 게시물 1건이 확인되었습니다.

**사용자 선택**

1. `모니터링을 계속한다`
2. `알림을 더 이상 받지 않는다`

**선택별 반응**

모니터링 계속:

> 다음 결과를 확인할 수 있도록 알려드리겠습니다.

알림 중단:

> 알림이 꺼졌습니다.

알림을 끈 뒤에도 검색창 자동완성에는 `{{이름}}` 관련 검색어가 남는다.

**분기 조건**

- 선택은 S18에서 보이는 알림의 유무만 바꾼다.
- 외부 노드는 사라지지 않는다.

**전환**

- 사건 화면이 닫히고 완전히 새로운 모바일 홈 화면이 등장한다.

**의미**

- 형사사건의 종결과 피해의 종결이 서로 다른 시간에 놓여 있음을 선명하게 대비한다.

**화면**

- 2년 뒤.
- 새 직장 이름, 축약한 이름, 다른 배경화면.
- 새로운 동료와 나눈 평범한 점심 대화가 보인다.

**메시지**

> 새 동료 · 내일 점심은 그 국수집 갈까요?

4초 뒤:

링크 미리보기:

> 게시일 · 3일 전

**사용자 행동**

**분기 조건**

- 없음.

**전환**

**의미**

### S18. 끝난 사건, 끝나지 않은 사람

**화면**

- 가운데 `{{이름}}`이 적힌 점 하나.
- 최초 게시물, 복제 계정, 검색 결과, 회사 메일, 가족, 친구, 집, 채용 담당자, 재판 기록이 선으로 연결된다.
- 삭제된 게시물 노드는 흐려지지만, 그것을 저장하거나 전달한 노드는 그대로 남는다.
- 새 복제본을 뜻하는 점이 천천히 하나씩 생긴다.

**화면 문구**

> 최초 게시물: 삭제됨

> 최초 가해자: 판결 확정

> 사건: 종결

> 새 유포자: 계속 발견됨

> `{{이름}}`: 여전히 검색됨

버튼:

> 내 이름 지우기

**사용자 행동과 반응**

- 버튼을 누르면 중앙의 이름만 잠시 사라진다.
- 이름이 없는 중앙점에 외부 노드의 선은 계속 연결되어 있다.
- 잠시 뒤 새 동료의 메시지가 중앙점의 새 이름이 된다.

**최종 문구**

> 법은 사건을 끝냈다.  
> 인터넷은 끝내지 않았다.

2초 뒤:

> 그녀는 사건에서 살아남았다.  
> 그러나 사건 밖으로 돌아오지 못했다.

**종료**

- 검은 화면.
- `체험 종료`만 남는다.

## 10. 장면 간 핵심 인과관계

```text
평범한 개인정보
    ↓
성적 합성물과 실명·직장 결합
    ↓
이미지 / 위치 / 관계 / 직장 중 한 경로가 먼저 폭발
    ↓
다른 경로가 합류해 온라인 사건이 현실 생활로 이동
    ↓
신고·삭제·채증·수사 시작
    ↓
개별 게시물 삭제와 동시에 복제본 재등장
    ↓
직장 분리·관계 후퇴·주거 불안·경제적 단절
    ↓
최초 가해자 특정과 판결
    ↓
새로운 유포자와 검색 결과는 존속
    ↓
새 관계보다 피해 정보가 먼저 도착
```

## 11. 문구 작성 원칙

- 가해자의 문장은 길지 않게 쓴다. 짧고 구체적인 현실 정보가 노골적인 욕설보다 강하게 작동한다.
- 성적 모욕을 사실적으로 보여주고, 관람자가 소비할 수 있는 선정적 세부 묘사까지 만든다.
- 주변 인물은 피해자를 대놓고 비난하기보다 `회사도 피해다`, `우리가 어떻게 해야 할지 모르겠다`, `안전을 위해 쉬어라` 같은 말로 주인공을 관계 밖으로 밀어낸다.
- 공식 지원기관의 인물은 냉담한 악역으로 만들지 않는다. 도움은 실제로 작동하지만 복제와 사회적 피해를 소급해서 없앨 수 없다는 한계를 사건의 동시 진행으로 표현한다.
- 법적 처벌을 무가치하다고 표현하지 않는다. 처벌이 성취되어도 이미 발생한 현실 피해가 자동 복구되지 않는다는 차이를 보여준다.
