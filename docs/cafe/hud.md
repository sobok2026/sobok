# 카페 화면 정보 설계

## 기준

매장을 보는 시간이 화면을 읽는 시간보다 길어야 한다. 정보는 필요한 순간을 기준으로 나누고 같은 값은 한 자리에서만 보여준다. 월드가 전달하는 정보는 HUD가 반복하지 않는다. 한 순간에는 가능한 행동만 보여주고 그중 하나만 강조한다.

2026-09-26 사용자 결정으로 기존 배치 대신 아래 구조를 따른다. 단계별 튜토리얼은 자동으로 띄우지 않는다. 대신 주문 레일이 다음 할 일 한 줄을 항상 보여준다. 이 줄은 방법이 아니라 목표를 말한다.

이 게임은 교육용이다. 2026-09-27 사용자 결정으로 가르칠 지식은 UI가 대신 답하지 않는다. UI는 목표와 판단 재료(주문 스티커·기한표·시계·용기의 선)만 주고 판단은 플레이어가 한다. 판정은 행동한 그 자리에서 바로 하고 무엇이 틀렸는지 말한다. 길 찾기와 조작 안내는 가르칠 지식이 아니므로 그대로 준다.

같은 날 사용자 결정으로 레시피와 계량선 읽기도 가르칠 지식에 넣었다. 작업 카드는 처음부터 양·설정값을 말하지 않고 판정만 한다. 레시피 원문은 H 도움말의 이 음료 탭에 남긴다. 제조는 컵이 아니라 용기를 기준으로 진행하고 주문 스티커를 컵에 붙인다.

## 화면 배치

| 영역          | 표시하는 정보                                                                                                                                                                                                      |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |

| 조준 프롬프트 | 조준점 바로 아래에 E·동사·대상. 직원 통로 제한도 같은 자리                                                                                                                                                         |

| 공간 안내     | 목표 작업대 위의 금색 표식. 화면 밖이면 가장자리 화살표와 장소 이름                                                                                                                                                |

근무일은 M 매장 현황과 결산 제목에 둔다. 주문번호와 `전달 x/y잔`은 별도의 HUD 배지로 두지 않으며, 주문 라벨에 인쇄된 주문번호와 잔 순번은 컵·프린터·확대 보기에서 표시한다. 상시 HUD는 스크롤하지 않고 라벨 보기 버튼만 마우스 입력을 받는다. 운반 중인 물건은 손에 든 3D 모델과 레일·표식이 알려준다.

## 목표의 단일 원천

[guidance.ts](../../apps/cafe/src/simulation/guidance.ts)의 `objective(state)`가 다음 장소·할 일·막힘을 한 번 계산한다. 주문 레일, 3D 표식, 가장자리 화살표가 이 값을 읽는다. 작업 카드의 막힘은 같은 파일의 `craftBlocker`·`preparationBlocker`를 쓴다. 해결 문장은 재료·컵 재고 도움말과 같은 함수에서 가져오므로 H 도움말과 어긋나지 않는다.

## 판단과 판정

| 지식           | 플레이어가 하는 일                      | 판정                                                                              |
| -------------- | --------------------------------------- | --------------------------------------------------------------------------------- |
| 컵 종류·사이즈 | 주문서를 보고 컵 보관대 격자에서 고른다 | 집는 순간. 틀리면 컵은 제자리에 두고 틀린 부분을 알린다                           |
| 품질기한       | 라벨 쓰기에서 기한을 직접 적는다        | 붙이는 순간. 이르거나 늦으면 붙지 않는다                                          |
| 원팩 보관 장소 | 입고한 원팩을 알맞은 곳에 넣는다        | 넣는 순간. 잘못된 곳이면 거부하고 맞는 장소를 알린다                              |
| 레시피 횟수    | 펌프·샷·스쿱·톡을 한 번씩 누른다        | F로 확인할 때. 정확해야 한다. 모자라면 이어서 하고 많으면 다시 만든다             |
| 레시피 양·선   | 게이지의 눈금이나 계기를 보고 멈춘다    | F로 확인할 때. 목표의 ±5% 안이면 통과. 덜 부었으면 이어서 붓고 넘치면 다시 만든다 |
| 장비·제공 설정 | 스팀 온도·원두·추출·버튼·리드를 고른다  | 시작하거나 확인할 때. 틀리면 시작하지 않고 틀린 항목을 알린다                     |

- 주문 레일과 조준 프롬프트는 `컵 보관대에서 컵 고르기`까지만 말한다. 컵 이름, 필요한 컵의 재고 부족, H 도움말의 지금 탭도 컵을 말하지 않는다.
- 컵 판정은 매장·포장 → 온도 → 사이즈 순서로 읽고 틀린 것만 누른 칸 위 말풍선에 쓴다(`사이즈가 달라요`, `매장·포장과 온도가 달라요`). 전용 잔이 걸린 선택은 사이즈 대신 잔 종류를 본다(`잔 종류가 달라요`). 칸은 빨간 테두리로 짧게 흔들리고 주문 한 줄에서 틀린 부분에 테두리를 그린다. 맞는 컵이 비어 있으면 같은 말풍선이 보충 버튼이나 세척 방법을 준다.
- 라벨 쓰기는 실제 라벨 모양이다. 개봉·제조 시각은 시계에서 옮겨 적으므로 자동으로 채운다. 기한 칸은 시작 날짜에서 시작해 플레이어가 올린다.
- 일·개월 기한은 날짜만(`9월 2일까지`), 시간 기한은 날짜와 분까지(`9월 2일 08:10까지`) 적는다. 자정에 끝나는 시간 기한은 `24:00`과 다음 날 `00:00`을 같은 값으로 받는다.
- 기한표는 라벨 쓰기 아래에 접어 둔다. 품목 기한과 세는 법만 적는다. 배합은 넣은 원재료 중 가장 이른 기한을 라벨 옆에 보여준다. 실제 용기에 붙은 값이라 판단 재료다.
- 판정 문구는 방향만 말하고 답을 쓰지 않는다(`기한을 늦게 적었어요`). 흔한 실수는 한 줄을 덧붙인다(`시작한 날을 첫날로 세요.`, `넣은 원재료 중 더 먼저 끝나는 것이 있어요.`).
- 계량 판정 문구도 값을 쓰지 않는다(`아직 덜 부었어요`, `횟수가 많아요. 다시 만들어주세요.`, `스팀 온도가 달라요`). 목표에서 붓기를 자동으로 멈추지 않는다. 용기가 넘치는 물리적 한계에서만 멈춘다.
- 되돌릴 수 있는 선택(설정·리드)은 거부하고 다시 고르게 한다. 되돌릴 수 없는 투입(넘친 양·많은 횟수)은 다시 만들게 한다.

## 작업 카드

- 제목은 동사와 용기다(`스팀 피처에 일반 우유 붓기`, `컵에 글레이즈드 소스 펌핑`, `우유 스팀`). 양·설정·시간은 쓰지 않는다.
- 오른쪽 값은 손에 든 계기가 읽어 주는 현재값만 쓴다(`2펌프`, `1샷`, `38ml`, `4.2초`). 목표는 쓰지 않는다.
- 선·간격·분수로 재는 붓기는 높이 게이지를 쓴다. 게이지의 끝은 용기 테두리이고 목표가 아니다. 목표에 닿아도 색이 바뀌지 않는다. 눈금은 그 용기에 실제로 있는 것만 둔다. 피처는 사이즈 새김선(S·T·G·V), 투명 컵은 라벨 없는 인쇄선, 컵은 테두리에서 5mm 간격의 눈금을 둔다. 2026-09-27 사용자는 용기 옆면 확대 대신 이 가로 눈금 게이지를 골랐다.
- 3D 스팀 피처에도 같은 사이즈 선을 새겨 월드와 게이지가 같은 말을 한다. 컵의 금색 목표선은 두지 않는다.
- 장비 설정은 선택지를 모두 같은 모양으로 늘어놓고 답을 표시하지 않는다. 숫자 키 1~9로 고를 수 있고 시작한 뒤에는 바꿀 수 없다.
- 지금 누를 키 하나만 강조한다. 도구가 필요하면 G, 도구를 들었거나 시작 전이면 Space, 시작한 뒤에는 F다. 강조는 목표 도달과 무관하다.
- 시간이 드는 장비(스팀)는 Space 한 번으로 시작하고 스스로 멈춘다. 완료 확인 입력은 없다. 그 장비 앞에서는 남은 시간을, 다른 곳에서는 주문 레일의 작업 칩을 본다.
- 컵·용기 집기는 이 장소에서 단계를 시작하기 전에만 보조 줄에 둔다. 폐기는 실수한 뒤에만 보이며 Q를 길게 누르거나 버튼을 누르고 있어야 실행된다.
- 할 수 없는 행동은 비활성 버튼 대신 숨기고 이유와 해결 행동을 적는다. 스티커가 없거나 용기가 다른 곳에 있으면 먼저 할 일로, 실수는 빨간색으로 쓴다.

## 용기와 주문 스티커

- 한 잔의 제조는 컵과 보조 용기(스팀 피처·샷 글라스·블렌더 피처 등)로 이뤄지고 각 용기는 자기 위치를 가진다. 단계는 그 단계가 쓰는 용기가 모두 그 작업대에 있을 때 진행한다. 우유 계량과 스팀은 컵 없이 스팀 완드에서 한다.
- 보조 용기는 처음 쓰는 단계의 작업대에 놓인 채로 시작하고 옮겨야 할 때 E로 집고 놓는다. 한 번에 하나만 든다.
- 결제하면 음료마다 주문 스티커가 컵 보관대 옆 스티커 프린터에 나온다. 컵을 고른 뒤 프린터에서 E로 붙인다. 스티커는 주문 내용(메뉴·온도·사이즈·매장/포장·커스텀)만 적고 컵 종류는 적지 않는다. 컵 판정이 먼저 끝나므로 컵 판단을 대신하지 않는다.
- 스티커를 붙이기 전에는 제조를 시작할 수 없다. 다시 만들면 새 스티커가 나온다.
- 2026-09-28 사용자 결정으로 실제 주문 라벨의 기본 우유·샷·시럽량과 음료 약어를 표시한다. 상단 연두색 띠, 왼쪽 마킹 칸, 오른쪽 제조 요약, 하단 음료 코드·주문 순번을 컵·프린터·확대 보기가 함께 사용한다. HUD에는 주문 요약만 두고 스티커 부착 여부로 크기나 길 안내 위치를 바꾸지 않는다. L 또는 라벨 보기 버튼으로 확대하면 시간을 멈추고, L·Esc·닫기로 원래 작업과 마우스 상태에 돌아간다. 확인되지 않은 음료 약어는 사용자가 승인한 영문 이니셜을 사용한다. 출처와 정보 표시의 예외 범위는 [주문 라벨](./order-stickers.md)에 기록한다.

## 작업대 패널

2026-09-27 사용자 결정으로 작업대 패널은 고를 것이 있는 곳에서만 연다. 할 일이 하나뿐이면 E가 바로 실행하고(청소 시작, 대기 용기가 하나인 세척 등) 할 일이 없으면 패널을 열지 않는다. 이때 조준 프롬프트가 이유를 한 줄로 말한다(`놓을 컵이 없어요`, `씻을 용기가 없어요`).

패널은 내용 높이만큼만 차지하고 위에서 아래로 다음 순서를 따른다.

| 순서 | 영역      | 내용                                                                                    |
| ---- | --------- | --------------------------------------------------------------------------------------- |
| 1    | 제목      | 장소 이름 하나                                                                          |
| 2    | 지금 카드 | 주문 레일의 목표가 이 장소일 때만. 제목은 상황, 버튼은 행동 하나                        |
| 3    | 탭        | 한 장소에 성격이 다른 목록이 있을 때만(창고: 재료·컵·소모품). 확인이 필요한 수를 배지로 |
| 4    | 검색      | 목록에 없는 품목은 검색으로 찾는다. 검색어가 있으면 목록만 결과로 바뀐다                |
| 5    | 목록      | 현재 주문에 필요한 것, 확인할 것만. 지금 카드에 올린 항목은 목록에서 뺀다               |

높이가 바뀌는 영역은 항상 입력 컨트롤 아래에 둔다. 검색을 목록 아래에 두면 글자를 칠 때마다 검색창이 움직인다.

- 지금 카드는 [guidance.ts](../../apps/cafe/src/simulation/guidance.ts)의 `objective(state)`가 넘기는 대상(`subject`)을 쓴다. 주문 레일·3D 표식과 같은 원천이라 서로 어긋나지 않는다.
- 지금 카드의 제목과 버튼은 같은 말을 하지 않는다(`일반 우유가 부족해요` / `원팩 개봉`). 입고·보관·개봉·라벨 같은 진행 칩은 두지 않는다. 원팩 흐름은 H 업무 안내에서 설명한다.
- 행은 이름과 잔량, 상태 칩 하나, 행동 하나다. 상태는 `기한 지남`·`라벨 전`·`부족`·`미개봉 N` 또는 사용 중인 라벨(`~9/2`)이다.
- 행 버튼은 보조 행동이다. 강조 버튼은 지금 카드에만 둔다. 폐기는 버튼을 누르고 있어야 실행한다.
- 원재료 목록·보관 설명·자료 출처 문구를 상시 노출하지 않는다. 라벨을 쓰기 전에는 기한을 보여주지 않는다.

| 장소      | 지금 카드                     | 목록                                       |
| --------- | ----------------------------- | ------------------------------------------ |
| 냉장고    | 개봉·라벨 쓰기·폐기           | 이 주문에 필요한 냉장 재료, 라벨·만료 확인 |
| 창고      | 원팩·소모품 입고, 소모품 집기 | 탭별 재료·일회용 컵 후방 재고·소모품       |
| 컵 보관대 | –                             | 주문 한 줄, 매장·포장 × 온도 카드 격자     |
| 준비대    | 대상 부재료 만들기            | 이 주문에 필요한 부재료, 검색              |
| 세척대    | –                             | 대기 용기가 둘 이상일 때 고를 용기         |

컵 보관대는 주문이 있으면 늘 고를 것이 있으므로 E가 항상 시트를 연다. 2026-09-27 사용자 결정으로 열은 판정의 첫 단계인 `매장 다회용`·`포장 일회용`, 행은 HOT·ICED·전용으로 나눈 카드 격자다. 카드 제목은 종류와 온도(`머그 HOT`)이고 전용 잔·전용 컵은 온도 없이 잔 이름으로 구분한다. 카드 안에는 판매하는 규격만 네 칸씩 놓으며 각 칸 아래에 사이즈나 잔 이름을 쓴다. 컵 실루엣은 3D 컵과 같은 윤곽 데이터로 그리고 테두리 색은 온도, 채움과 모양은 재질을 나타낸다. 수량은 칸 이름 아래 줄에 `4개`처럼 쓴다. 고를 때는 수량이 판단과 무관하므로 빈 칸에만 `0개`를 쓰고 하단 상태 칸을 두지 않는다. 주문이 없을 때는 모든 칸에 수량을 쓴다. 누를 수 있는 칸만 버튼 모양이므로 이때 칸은 평평하고 빈 일회용 컵 칸만 `보충` 버튼으로 떠오른다. 주문 한 줄은 판정하는 세 값(온도·사이즈·매장/포장)을 같은 크기의 칩으로 보여주고 틀린 칩에만 테두리를 그린다. 칸 이름이 14px로 한 칸에 들어가도록 컵 보관대 패널은 다른 패널보다 넓다.

## 보관 장소

2026-09-27 사용자 결정으로 냉장고와 창고를 서로 다른 장소로 나눈다. 냉장고에는 냉장 보관 재료만 들어간다. 창고는 오른쪽 벽의 선반으로 실온 원팩, 일회용 컵과 소모품 후방 재고를 두고 입고를 받는다. 냉동 보관은 이번 범위에 넣지 않는다.

- 원팩은 창고에서 입고한다. 입고한 원팩은 손에 든 채 알맞은 곳에 E로 넣는다. 어디에 보관할지 아는 것이 업무 지식 시험이다.
- 그래서 보관 방식은 원팩·라벨·손에 든 모델에 표시하지 않는다. 손에 든 원팩은 재료와 관계없이 같은 상자로 보인다. 주문 레일도 `원팩을 알맞은 곳에 넣기`라고만 말하고 3D 표식을 띄우지 않는다.
- 잘못된 장소에 넣으면 거부하고 보관 방식과 맞는 장소를 알려준다(`냉장 보관 재료예요. 냉장고에 넣어주세요.`).
- 넣은 원팩은 그 자리에서 개봉하고 라벨을 붙인 뒤 사용한다. 준비대에서 만든 배합은 기존처럼 냉장고나 실온 선반으로 운반한다.

## 이름

한 장소는 이름 하나로 부른다. `냉장고 · 창고`처럼 두 이름을 이어 쓰지 않는다. 두 곳을 함께 말할 때만 `냉장고나 창고`처럼 문장으로 쓴다. 이름은 플레이어가 월드에서 보는 물건을 따른다.

| 장소 ID   | 이름          | 장소 ID     | 이름             |
| --------- | ------------- | ----------- | ---------------- |
| `steam`   | 스팀 완드     | `fridge`    | 냉장고           |
| `brew`    | 콜드 브루 탭  | `stock`     | 창고             |
| `topping` | 토핑 스테이션 | `shelf`     | 실온 선반        |
| `rack`    | 도구 선반     | `cold-prep` | 콜드 브루 추출대 |

장소 이름 뒤 조사는 `toward()`처럼 받침을 계산해 붙인다(`실온 선반으로`, `냉장고로`). 그 밖의 조사는 `josa()`를 쓴다.

물건을 옮기는 동사는 아래로 통일한다. 재고 위치는 `진열`(컵 보관대·컨디먼트 바에 나와 있는 것)과 `후방`(창고 선반)으로 부른다.

| 동사        | 뜻                                    | 쓰지 않는 표현   |
| ----------- | ------------------------------------- | ---------------- |
| 입고        | 돈을 내고 창고로 들여온다             | –                |
| 보관        | 원팩·배합을 제자리에 넣는다           | 넣기             |
| 보충        | 후방 재고를 진열 자리로 옮긴다        | 채우기           |
| 개봉        | 원팩을 연다. 기한이 시작된다          | –                |
| 라벨 쓰기   | 기한을 적는다. F 버튼만 `라벨 붙이기` | 날짜 라벨 붙이기 |
| 집기 · 놓기 | 손에 들거나 내려놓는다                | 꺼내기·가져오기  |
| 폐기        | 길게 눌러 버린다                      | –                |

## 대화상자

| 화면     | 표시하는 정보                                                                                        |
| -------- | ---------------------------------------------------------------------------------------------------- |
| 시작     | 게임 이름, 시작·이어 하기. 도움말과 저장 관리는 보조 선택지                                          |
| H 도움말 | 탭 다섯 개. 지금(현재 작업의 이유·원문), 이 음료(단계별 레시피와 양), 업무 안내, 조작법, 제조법 검색 |
| M 매장   | 근무일. 할 일 탭은 맨 위에 지금 할 일, 아래에 장소별 남은 일. 운영 기록은 별도 탭                    |
| Esc 메뉴 | 계속하기, 매장 현황, 도움말. 설정과 저장 관리는 접어서 제공. 처음부터 시작은 저장 관리와 떨어뜨린다  |
| 결산     | 판매액·전달 음료·현금. 입고와 폐기는 실제 내역이 있을 때 펼쳐 보기                                   |

도움말과 매장 현황을 보는 동안 시간은 멈춘다. H 도움말을 닫으면 열기 전 화면으로 돌아간다. 작업 패널에서 도움말을 열었다면 해당 패널을 유지한다. 대화상자는 키보드 포커스를 안에 유지하고 Esc로 닫는다.

- 이 음료 탭은 원문 지시문을 한 번만 쓰고 그 아래에 재료·계량·장소를 행으로 둔다. 진행 중인 단계를 강조한다.
- 대화상자와 패널의 글자는 14px 이상이다. 소리를 끄면 음량·미리 듣기를 숨긴다.

## 텍스트와 색

1080p 기준으로 행동 동사·값·메뉴명은 18px 이상, 보조 정보는 15px, 최소 14px이다. HUD에서 12px 글자를 쓰지 않는다. 온도는 HOT·ICED 글자와 색을 함께 쓰고 흰 글자의 대비는 4.5:1 이상이다.

## 제거한 정보

장르·입력 장치·로컬 저장 소개, 분위기 문구, 영문 장식 제목, 반복되는 조작법, 마우스 모드 설명, 상시 소리 토글, 일반 조작 성공 알림, 상단의 근무일·영업 중, 주문번호, 작업 카드의 작업대 이름·단계 번호·재료 줄, 하단 운반 문구를 제거한다. 2026-09-27에 지금 카드의 `지금` 머리말과 진행 칩, 재료 행의 부족량·팩 수 메모, 준비대의 단계 수, 컵 보관대의 비어 있는 컵 목록, 섹션 제목의 가격, 라벨 전 만료 시각을 제거했다. 같은 날 레시피 판정 도입과 함께 작업 카드의 목표값·퍼센트·목표 문구·설정 메모, 목표 도달 시 게이지 색 변화, 컵의 금색 목표선, 모든 단계의 컵 집기·폐기 줄, 작업 중 레일의 지금 줄, H 지금 탭의 키 목록, 스팀의 `회` 단위와 완료 확인 입력을 제거했다. 정상 선행 작업은 빨간 막힘 대신 먼저로 쓴다. 일반적인 상태 변화는 물건·계기 읽기·수위·레일의 대기 잔 수로 전달한다. 실패는 오류 알림으로, 저장 실패는 백업으로 이어지는 버튼으로 표시한다.

소리와 마우스 감도는 설정에, 정상 저장 상태는 저장 관리에만 표시한다. 게임 규칙·레시피·재료 기한 계산은 HUD가 결정하지 않는다.

## 넓은 POS

2026-09-26부터 POS는 화면 대부분을 사용하는 전용 작업 화면이다. 왼쪽에는 손님 요청·주문서·합계, 오른쪽에는 상품·커스텀·결제를 표시한다. 결제 후 주문 레일이 진행 중인 잔과 대기 잔 수를 요약한다. 세부 흐름은 [POS 구현](./pos.md)을 따른다.
