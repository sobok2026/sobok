# POS 주문·커스텀·결제

2026-09-26 사용자 확인으로 넓은 POS 화면, 한 손님의 여러 잔 주문, 결제 완료 후 제조 확정을 적용한다. 현금·신용카드·분할 결제를 제공하며 한 잔씩 제조·전달하고 마지막 잔을 받은 뒤 손님이 이동한다. 2026-09-27에 거래 내역·영수증·현금영수증과 커스텀을 확장했다. 환불은 사용자 요청으로 후속 작업에 남긴다. 충전·회원·쿠폰·제휴 할인·상품권도 이번 범위가 아니다. 외부 결제나 카드 정보 수집 없이 게임 내부에서 처리한다.

## 화면과 조작

E로 POS를 열면 왼쪽 주문서를 유지하며 오른쪽을 주문·커스텀·결제로 바꾼다. 진녹색 바탕, 민트색 보조 버튼, 청록색 선택 상태, HOT/ICED 색상, 5열 상품 격자와 숫자 키패드를 사용한다. 상품 목록은 페이지로 이동하고 검색·분류·브라우저별 즐겨찾기를 지원한다.

주문 행을 고르면 해당 음료의 규격을 수정한다. `+ 새 음료`로 선택을 해제하면 다음 음료의 온도·사이즈·컵을 정할 수 있다. 수량 변경, 한 잔 분리, 개별·전체 삭제를 제공한다. 왼쪽에 손님이 말한 주문을 표시하고 상세 창에서도 확인할 수 있다.

Esc는 상세 팝업, 커스텀·결제, POS 순서로 닫는다. H 도움말과 M 매장 현황의 기존 동작을 유지한다. POS는 작업 화면이므로 게임 시간은 계속 흐른다.

## 주문과 결제의 상태

`simulation/state.ts`의 `sale` 하나가 주문 초안과 결제된 주문을 소유한다. 상품·수량·커스텀·전달 수량을 가진 `lines`, 결제별 수단·적용액·받은 금액을 가진 `payments`, 결제 완료 시각 `paidAt`을 저장한다. 손님 요청은 `customer.items`에 별도로 보존한다. 현재 제조할 잔은 `currentTicket`이 결제된 항목 중 미전달 항목에서 계산하며 별도 상태로 복사하지 않는다.

- 결제 전에는 컵을 준비하거나 손님을 픽업대로 이동시키지 않는다.
- 결제를 마치면 음료마다 주문 스티커가 컵 보관대 옆 스티커 프린터에 나온다. 스티커 수는 결제한 잔 중 전달하지 않았고 컵에 붙이지 않은 잔의 수(`pendingStickers`)로 계산하며 따로 저장하지 않는다. 컵에 붙였는지만 `cup.craft.sticker`에 저장한다.
- 스티커의 기본 샷·시럽량과 변경 옵션은 커스텀 적용 후 제조 계획에서 계산한다. 결제 시각과 주문 전체의 잔 순번을 고정해 컵·프린터·라벨 확대 보기가 같은 내용을 표시한다. 주문 레일은 간단한 요약과 L 라벨 보기 진입점만 둔다. 2026-09-28 사용자 결정과 실물 참고 출처는 [주문 라벨](./order-stickers.md)을 따른다.
- 첫 결제 전에 손님 요청과 입력한 상품·규격·수량·커스텀을 대조한다.
- 부분 결제가 있으면 결제를 취소한 뒤 주문을 수정한다. POS를 닫거나 저장해도 결제 내역을 보존한다.
- 카드 결제액은 남은 금액 이하로 입력한다. 현금은 받은 금액을 기록하고 초과분을 거스름돈으로 계산한다.
- 전체 금액이 결제되면 제조 주문을 확정하고 운영 자금·판매액·수단별 판매액에 한 번 반영한다. 동일한 결제 ID의 중복 처리는 금액을 다시 더하지 않는다.
- 게임의 `cash`는 기존 입고 지출에 사용하는 운영 자금이다. 현금 판매와 카드 판매를 모두 합산하며 실제 현금 서랍의 잔액을 뜻하지 않는다. 결산에서는 현금·카드 판매를 각각 표시한다.
- 한 잔을 전달할 때는 전달 수량만 올린다. 마지막 잔 이후 컨디먼트·착석·반납·퇴장 흐름으로 넘어간다. 여러 다회용 컵과 ICED 음료별 빨대 수량도 함께 처리한다.
- 손님은 순서에 따라 1~3개 항목을 요청하고, 단일 항목 차례에는 두 잔을 요청한다. 일부 주문에는 해당 제조법이 지원하는 커스텀을 포함한다.

새 저장 형식만 허용하는 기존 정책을 따른다. 거래 내역과 확장 커스텀 필드가 없는 이전 저장을 자동 변환하지 않으며 새 근무가 필요하다.

## 거래 내역과 영수증

전액 결제와 함께 `transactions`에 거래를 한 번 기록한다. 손님 ID를 거래 ID로 사용하며 상품명·규격·커스텀 표기·수량·단가·결제수단을 결제 시점의 값으로 보존한다. 손님이 떠나거나 다음 근무일이 되어 현재 주문과 당일 집계가 초기화되어도 거래 기록은 유지한다. 기존 단일 게임 저장에 포함하며 별도 저장소를 만들지 않는다.

하단 **거래 내역**에서 오늘·전체 기간, 거래 번호·상품명 검색, 거래별 영수증을 조회한다. 영수증은 각 결제수단의 적용액과 현금 거스름돈을 보여준다. 미리보기에서 브라우저 인쇄를 요청할 수 있으며 출력 요청 횟수와 마지막 요청 시각을 기록한다. 인쇄 취소 여부나 실제 프린터 출력을 감지한 기록은 아니다.

현금이 포함된 주문은 결제 후 소득공제(개인)·지출증빙(사업자)·미발행 중 하나를 고른다. 발행금액은 거스름돈을 뺀 현금 적용액이며 카드 결제액은 제외한다. 개인 번호 10~11자리, 사업자 번호 10자리는 화면 입력에서만 사용한다. 게임 행동에는 끝 네 자리만 전달하고 저장·백업·영수증에도 끝 네 자리만 남긴다. 거래 내역에서 다시 발행하거나 미발행으로 바꾼 이력도 보존한다. 최신 선택이 영수증에 표시되며 이 과정은 게임 내 재현이다.

## 커스텀과 제조

`content/customizations.ts`는 옵션·가격·주문 표기를, `recipeFor`는 기존 제조 계획에 옵션을 적용한 계획을 소유한다. 원본 레시피 JSON의 계량값은 수정하지 않는다. 변경된 계획을 제조 HUD·도구·재료 소비·도움말이 함께 읽는다.

지원 옵션은 샷·시럽 수량, 일반·블론드·디카페인·1/2 디카페인 원두, 일반·저지방·무지방·두유·오트 우유, 우유 양·거품·온도, 바닐라·헤이즐넛·카라멜 시럽, 얼음·휘핑·드리즐의 제외·양 조절 및 추가, 프라푸치노 로스트, 자바칩이다. 해당 음료가 사용하는 제조 경로에 맞는 옵션만 표시한다. 우유 거품·온도는 스팀 음료, 로스트·자바칩은 블렌더 음료에 제공한다. 자바칩은 스쿱 수와 모두 갈기·반반·모두 토핑을 고른다. 반반 3스쿱은 블렌딩 전 1.5스쿱, 제공 전 토핑 1.5스쿱으로 나눈다.

기본 포함 시럽·자바칩의 수량 변경과 휘핑·드리즐 양 조절은 무료다. 새 시럽·휘핑·드리즐·자바칩 종류는 음료당 한 번 과금하며, 기본보다 늘린 로스트도 음료당 한 번 과금한다. 기존 모카 재료가 있는 음료의 초콜릿 드리즐은 기본 재료로 처리한다. 재료를 빼거나 일반 원두로 바꿔도 음료 기본 가격을 차감하지 않는다.

사용자 확인으로 **적게는 기본 투입량의 50%, 많이는 150%**인 게임 규칙을 적용한다. 실제 매장 계량 규칙이라는 의미가 아니다. 누적 컵 선이나 테두리 간격 자체를 곱하지 않고, 그 단계 시작 시 내용물에서 계산한 투입량에 배율을 적용한다. 재료 소비와 목표 액면을 같이 계산하고 진행 중 저장에서도 시작량을 유지한다.

우유 양과 거품도 같은 배율을 사용한다. 우유 또는 거품을 바꾸면 원래 피처에서 제공하던 비율을 유지하여 이관량을 다시 계산한다. 원래 컵 선을 그대로 채우다가 피처 내용물이 부족해지는 상황을 피하며, 거품 없이는 거품 이관 단계를 생략한다. 스팀 가열 시간과 거품량은 별도로 계산한다. 온도는 레시피 기본·기본 온도·X-Hot 중 고르며 기존 스팀 장비 설정으로 제조한다.

`data/shop/pos-customizations.json`은 승인된 임시 게임 기준을 소유한다. 일반 휘핑은 기본 50ml, 적게 25ml, 많이 75ml다. 원문에 휘핑 양이 없는 기본 메뉴에도 이 값을 적용한다. 양이 없는 카라멜 드리즐은 카페 브륄레 프라푸치노의 4~5바퀴 중 4바퀴, 초콜릿 드리즐은 블랙 글레이즈드 라떼의 모카 1바퀴를 게임 기본값으로 사용한다. 명시된 원문 수량은 유지한다.

일반 휘핑은 2026-09-28 사용자 확인에 따라 크림 260ml·심플 시럽 3펌프를 통에 담고 가스 주입 후 30회 흔들어 직접 제조한다. 냉장 24시간이며 기존 게임 규격 500ml를 준비 산출량으로 유지한다. 바트의 크림 1L·심플 시럽 11펌프 배합은 자료실에 기록하고 자동휘핑머신 작업은 확인 대상으로 남긴다. 로스트는 2026-09-28 제공 제조표로 원팩 1봉·정수 1L 제조법을 연결해 직접 준비하며 실온 48시간 보관한다. 휘핑·로스트의 완성품 입고 임시 설정을 제거하고 원재료를 소비하는 준비 경로를 사용한다. 저지방 우유는 일반 우유와 같은 1,000ml 원팩·3,000원·냉장·2일 기한 및 재고 환산값을 사용한다. 로스트·자바칩 추가 창의 기본 제안 수량은 Short 1, Tall 2, Grande 3, Venti 4, Trenta 5이며 실제로 선택한 수량이 제조에 적용된다.

## 파일 책임

- `features/service/PosPanel.tsx`: POS 화면 조합, 주문서·규격 선택·업무창.
- `PosMenu.tsx`, `PosCustomize.tsx`, `PosCheckout.tsx`: 상품 선택, 커스텀, 결제 화면.
- `PosControls.tsx`: POS 내부 버튼·팝업·숫자 키패드.
- `TransactionHistory.tsx`, `Receipt.tsx`, `CashReceiptForm.tsx`: 거래 조회·영수증·현금영수증 화면. `transactions.ts`는 결제 시점 기록, `receipt-actions.ts`는 발행·출력 요청을 처리한다.
- `PosExtraCustomizations.tsx`, `content/customization-options.ts`, `customization-extras.ts`, `customization-milk.ts`: 추가 옵션 선택·운영 기준·제조 단계·우유 이관량 조정.
- `pos-actions.ts`: 장바구니 편집과 결제 확정. `orders.ts`: 금액·요청 대조·현재 제조 항목·고객의 컵 계산.
- `actions.ts`, `customer-progress.ts`: 잔별 전달과 고객 이동·여러 컵 반납.
- `data/shop/pos-menu.json`: 상품의 화면 분류와 HOT/ICED 연결용 메뉴군. 신규 메뉴 추가 시 함께 확인한다.
- `features/production`, `content/stock-amounts.ts`: 기존 공통 제조 실행과 커스텀 투입 배율. 별도의 제조 엔진을 추가하지 않는다.

## 확인 기록

2026-09-27 최종 타입 검사·자료 검사·폰트 검사·프로덕션 빌드와 변경한 파일의 Biome·Prettier 검사를 통과했다. 자료 검사는 현재 판매 119개 메뉴·281개 사이즈 조합의 제조 순서를 확인했다. 테스트 코드는 추가하지 않았다.

2026-09-27 별도 브라우저의 1440×1000·1280×720 화면에서 로스트·자바칩, 블론드·저지방·우유 양·거품·온도·휘핑을 선택했다. 자바 칩 프라푸치노 2잔 14,600원을 현금 5,000원 결제 후 저장·재개하고 카드 9,600원으로 마쳤다. 거래 1건 생성, 개인→사업자 발행 이력, 식별번호 끝 네 자리만 저장, 출력 요청 2회, 다음 날 거래 유지와 당일 집계 초기화를 확인했다. 인쇄용 PDF 생성도 확인했으며 실제 프린터 출력은 확인하지 않았다.

제조 계획에서 휘핑 25·50·75ml, 로스트 펌핑과 자바칩 반반 투입, 우유·거품 50%·150%, 기본·X-Hot 장비 선택을 확인했다. 스팀 음료의 우유·거품 옵션 117개 조합에서 커스텀으로 새 이관 부족이 생기지 않는지 계산했다. 모든 메뉴의 제조·전달을 플레이한 결과는 아니다.

2026-09-26 타입 검사·자료 검사·프로덕션 빌드와 변경한 화면·로직의 Biome 검사를 완료했다. 자료 검사는 현재 판매 104개 메뉴·244개 사이즈 조합을 확인했다.

별도 브라우저에서 1440×1000 주문 화면과 1280×720 커스텀·현금·카드 화면을 확인했다. UI로 콜드 브루 두 잔에 바닐라 시럽 2펌프·얼음 적게를 입력하고, 11,800원 중 현금 3,000원을 결제한 뒤 새로고침했다. 재개 후 남은 8,800원을 카드로 결제했으며, 저장에는 현금 3,000원·카드 8,800원·판매액 11,800원과 픽업 이동 상태가 남았다. Esc로 POS를 닫아 제조 HUD로 돌아오는 것도 확인했다.

준비된 콜드 브루 재고와 작업대 위치를 설정한 별도 상태에서 실제 제조 행동·계량·완료·전달을 두 잔씩 실행했다. 기본·적게·많이의 얼음 투입량은 1:0.5:1.5였고, 첫 잔에는 픽업 대기, 두 번째 잔에는 컨디먼트 이동이 됐다. 결제 전 제조 차단, 부분 결제 저장 복원, 중복 결제 방지와 다회용 컵 보존도 확인했다. 매장의 모든 메뉴를 처음부터 제조·전달한 결과는 아니다.

## COW와 드립 메뉴

2026-09-28 관리메뉴에 COW 설정을 추가했다. HOT·ICED 원두를 별도로 고르고 확정하면 드립·아이스 드립 상품 카드와 원두 검색에 반영된다. 접수한 주문은 당시 원두를 보존하며 결제·영수증·제조에 같은 원두를 사용한다. 새 COW가 이미 추출한 배치의 원두나 기한을 덮어쓰지 않는다. 기존 영업 관리·마감은 관리메뉴 안과 매장 현황에서 계속 연다. [URN 제조·재고 규칙](./digital-urn-proposal.md)에 따라 준비 경로가 연결되어 두 메뉴의 Tall·Grande·Venti 판매가 활성화됐다.
