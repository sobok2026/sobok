## 확정된 범위

- PC 웹, Vite + React + TypeScript + Three.js, IndexedDB 로컬 저장을 유지한다.
- 음료 제조와 POS·청소·설거지·정리·재고 관리를 함께 다룬다. 승진해야 다른 업무가 열리는 구조는 만들지 않는다.
- 초기 메뉴인 Tall 콜드 브루 ICED, 블랙 글레이즈드 라떼 HOT·ICED에 사용자 선택으로 호지 글레이즈드 티 라떼 HOT·ICED를 추가했다. 한 번에 주문 한 건을 처리한다.
- 컨디먼트 바에 컵 반납·회수·청소와 냅킨·빨대·설탕 보충을 제공한다. 반납 90%·테이블 방치 10%, 사용한 표면 오염 30%와 소모품 소비·입고 임시 규칙은 사용자 확인을 받았다.
- 컵·도구 자동 정렬과 누르고 붓기·클릭 펌핑을 유지한다. 근무 중 시간은 실제 시간처럼 흐르고 다음 날은 건너뛴다.
- 첫 근무 안내는 짧게 표시하며 언제든 숨기거나 다시 연다. 첫 콜드 브루와 첫 라떼 전달 후 자동으로 접되 업무를 잠그지 않는다. 작업음은 사용자 요청에 따라 실제 매장에 가까운 녹음 기반 소리로 구성하며 기본 음소거·음량 조절을 제공한다.
- 품질 기한은 N일이면 시작일 포함 N일의 마지막 날 종료, N시간이면 시작 시각부터 계산한다. 폼·바모카는 제조 후 기본 기한과 투입 원재료의 가장 빠른 기한 중 이른 시각을 적용한다. 미확인 실물 수치·절차는 기존 임시값을 유지한다.
- 준비 용기는 작업대에서 라벨을 붙인 뒤 직접 운반한다. 콜드 브루는 9,000원으로 원두 한 배치분을 확보해 자료의 5lb·물 14L를 계량하고 20시간 추출한다. 완성량 3L는 기존 임시값을 유지한다.
- 저장 버전 관리와 이전 저장 구조의 마이그레이션은 구현하지 않는다. 현재 구조 검증, 자동 저장, 이전 정상 저장본 복구, JSON 백업은 유지한다.
- **탭 간 상태 동기화는 구현하지 않는다. 현재 중복 실행 제한을 유지한다.**
- 자동 테스트 코드나 테스트를 위한 구조 변경은 이번 후속 작업에 포함하지 않는다. 완료 확인은 타입 검사·빌드와 필요한 브라우저 수동 조작으로 한다.

## 탭 처리 결정

현재 [App.tsx](../../apps/cafe/src/ui/App.tsx)의 `navigator.locks.request('sobok-cafe-writer', { ifAvailable: true })`는 한 탭만 게임을 진행하고 저장하도록 제한한다. 탭 사이에 게임 상태를 보내거나 합치는 기능은 없다.

이 동작을 그대로 유지한다.

- 앱 로딩 후 잠금을 획득한다. 시작 화면만 열려 있는 탭도 잠금을 보유할 수 있다.
- 잠금을 얻지 못한 탭은 시작·조작·저장이 제한되고 다른 창을 닫고 새로고침하라는 안내를 받는다.
- 잠금을 가진 탭을 닫은 뒤 다른 탭에서 새로고침해 이어간다. 자동 인계나 강제 가져오기는 추가하지 않는다.
- 현재 Web Locks 미지원 환경에서는 제한 없이 진행하는 분기가 있다. 모든 브라우저에서 중복 방지가 보장되는 것으로 표현하지 않는다. 별도 호환 계층은 추가하지 않는다.

현재 자동 저장은 근무를 시작한 탭에서 8초 주기로 실행되고 일시정지 중에도 가능하다. 중복 제한을 제거하면 다른 탭의 오래된 상태가 같은 저장을 덮어쓸 수 있다. 기존 제한의 추가 구현 비용은 없고, 실시간 동기화는 이 게임에 필요한 새 플레이 경험을 거의 늘리지 않으므로 개발 범위에서 제외한다.

BroadcastChannel 동기화, 상태 병합, 자동 잠금 인계, 시작 버튼으로 잠금 획득 시점을 옮기는 변경은 작업 목록에 넣지 않는다. 이는 이번 사용자 결정이며, 이후 명시적으로 방향을 바꿀 때만 재검토한다.

## 우선순위와 작업 규모

P0는 기존 흐름의 막힘을 먼저 확인하는 작업, P1은 다음 플레이 버전에서 체감 효과가 큰 작업, P2는 기초 루프가 안정된 뒤 확장할 작업이다. 규모는 일정 약속이 아닌 상대적인 공수다. S는 기존 동작·화면의 국소 수정, M은 작업 상태와 화면·3D 표현의 연결, L은 여러 업무 흐름과 자료 확인이 함께 필요한 변경이다.

| 1    | CAFE-01 | P0       | 초기 상태부터 한 근무를 완주하고 안내·조작 막힘 정리 | S–M  | 기존 기능을 끝까지 쓸 수 있게 하므로 가장 먼저 수행    |

| 8    | CAFE-08 | P2       | 용기 운반과 콜드 브루 준비 확장                      | M–L  | 매장 동선과 다음 날 준비의 의미 강화                   |
| 9    | CAFE-09 | P2       | 자료가 있는 메뉴를 한 종류씩 확장                    | M–L  | 콘텐츠 증가. 필요한 재료·장비·준비 배합까지 함께 구현  |
| 10   | CAFE-10 | P2       | 3D 표현·조작 설정·측정 기반 성능 개선                | M    | 가독성과 장시간 플레이 편의 개선                       |

CAFE-01~06, CAFE-07의 이번 확인 범위와 CAFE-08은 완료했다. 이후 자료 갱신 시 `import:references`·`check:references`로 연결을 확인한다. 서로 다른 신규 기능을 한 번에 크게 확장하기보다 한 작업의 완료 기준을 확인한 뒤 다음으로 넘어간다.

## 작업별 범위와 완료 기준

### CAFE-01 · 한 근무 완주와 조작 막힘

완료했다. 실제 `initialState()`에서 시작해 아래 흐름을 확인했다. 이후 이 흐름에 영향을 주는 변경이 있을 때 필요한 부분을 다시 확인한다.

- 콜드 브루 → HOT 라떼 → ICED 라떼를 처리하며 필요한 우유 개봉, 폼·바모카 준비, 세척·선반 정리를 수행한다.
- 계량 중 일시정지·재접속, 재료 부족 후 보충, 과다 계량 후 재제조, 만료 재료 폐기, 마감·다음 날을 확인한다.
- 작업할 수 없는 이유와 다음 행동이 보이도록 안내를 정리한다. 새 시스템 추가보다 재현된 막힘 해결을 우선한다.

혼합 작업대의 청소 메뉴에 접근하지 못하는 상황을 브라우저에서 재현한 뒤, 컵을 다른 작업대에 놓으면 메뉴를 열도록 수정했다. 컵을 든 채 부재료 준비나 세척으로 향해야 할 때에는 먼저 컵을 내려놓을 작업대와 선행 행동을 안내한다.

**완료 기준:** 새 근무에서 세 음료를 전달하고 마감·다음 날까지 진행할 수 있다. 준비나 세척을 병행할 때 컵·도구가 사라지거나 중복 차감되지 않는다. 막힌 행동에는 해결 방법이 표시된다.

### CAFE-02 · 청소·설거지·정리

세척 대상 선택 → 누르고 씻기 → 선반 정리, 테이블 컵 회수 → 누르고 닦기, 작업대 얼룩 닦기, 쓰레기 정리의 조작을 추가한다. 기존 E·G·Space 조작과 자동 정렬 방식을 활용한다. 세척의 세부 단계·시간은 현장 자료 확인 전까지 게임용 규칙으로 명시한다.

완료했다. 두 테이블의 컵 수와 오염 여부를 분리하고 E로 회수·운반·분리수거, G로 천 집기·놓기, 누르고 닦기·F 확인을 연결했다. 작업대는 현재 얼룩을 한 번 닦아 정리하고, 쓰레기는 누르고 모아 봉투를 묶은 뒤 비운다. 기존 자동 타이머 청소는 제거했다.

처음에는 현재 피처 수량과 청소 상태를 활용한다. 모든 도구에 개별 인벤토리·물리 시뮬레이션을 붙이는 전면 교체부터 시작하지 않는다. 두 테이블 중 실제 청소 가능한 대상과 화면의 오염 표시를 일치시킨다.

**완료 기준:** 누르는 동안 작업이 진행되고 손을 떼거나 자리를 떠나면 멈춘다. 중간 저장·복원 후 이어 할 수 있다. 세척·정리 완료가 재사용 가능한 도구 수와 마감 체크에 반영된다.

### CAFE-03 · 운영 결산과 재고 판단

완료했다. 판매액·원팩/컵/소모품/추출 준비비 지출·재료별 폐기량·시작/현재 잔액과 현금 증감을 기록하고 매장 현황·결산에 표시한다. 재제조 컵의 실제 투입량, 미완성 배합의 원재료, 완성 배치의 잔량을 각각 해당 시점의 재료로 기록한다. 원가 배분을 구현하기 전에는 판매액에서 입고 지출을 뺀 값을 순이익으로 표시하지 않는다. 가격과 원팩 규격은 계속 게임용 값을 사용한다.

재고 화면에서는 사용 가능·미개봉·라벨/보관 대기·만료를 구분하고, 현재 주문에 부족한 품목을 먼저 보여준다. 품목별 상세 라벨은 유지한다. 임의의 복잡한 수요 예측이나 회계 엔진은 도입하지 않는다.

**완료 기준:** 판매·입고·폐기 각각의 행동이 결산 수치로 설명된다. 플레이어가 재료 부족의 원인을 알고 필요한 원팩이나 준비 배합을 선택할 수 있다. 초기 구현은 하루 결산에 집중하며 장기 통계는 별도 확장으로 둔다.

### CAFE-04 · 손님 동선

완료했다. 한 명의 손님과 주문 한 건 구조를 유지하며 입장 → 주문 대기 → 픽업 이동·대기 → 수령 → 컨디먼트 이용 → 테이블 10초 체류 → 반납 또는 컵 방치 → 퇴장을 표현한다. 10초 체류와 앞 손님 퇴장 후 다음 손님 입장은 사용자 확인을 받았다. 고정 매장의 지정된 경로로 직원 공간·테이블·의자·반납대를 피해 움직인다. 대규모 군중·범용 경로 탐색·여러 주문 큐는 이 작업에 포함하지 않는다.

**완료 기준:** 손님이 직원 통로와 가구를 통과하지 않는다. 주문 번호·요청 메뉴·전달 대상이 연결되고 같은 음료를 두 번 판매하지 않는다. 일시정지·저장 복원·마감 시 손님 상태도 일관된다. 대기시간 초과로 퇴장시키는 난이도는 별도 결정 전까지 추가하지 않는다.

### CAFE-05 · 첫 근무 안내와 피드백

첫 콜드 브루와 첫 라떼에서 현재 목표·필요한 도구·선행 행동을 짧게 안내한다. 안내를 닫고 다시 볼 수 있게 하며, 안내를 완료해야 업무가 열리는 제한은 두지 않는다. 컵·얼음·물·스팀·세척과 계량 확인·완료·전달의 소리·시각 피드백을 제공한다. 펌프·오류의 스위치 찰칵음은 사용자 요청으로 제거했다. 기본 음소거이며 음량과 안내 표시 설정은 게임 저장과 분리해 보관한다.

**완료 기준:** 조작 안내를 별도로 외우지 않아도 첫 주문을 끝낼 수 있다. 들고 있는 물건과 작업이 막힌 이유를 알 수 있다. 소리를 끌 수 있고, 소리 없이도 완료·오류를 구별할 수 있다.

### CAFE-06 · 자료 갱신 경로

완료했다. [reference-links.ts](../../apps/cafe/src/game/reference-links.ts)에서 메뉴명·온도·배합·단계 의미를 유일하게 찾아 단위·수량·실제 제조 순서를 확인한다. [catalog.ts](../../apps/cafe/src/game/catalog.ts)는 해당 단계와 작업대·재고 차감을 명시적으로 연결하며, HOT·ICED의 샷·펌프·드리즐·토핑 수량을 각 자료에서 읽는다. 폼·바모카 준비, 콜드 브루 추출 시간과 초기 품질 기한도 같은 연결을 사용한다.

가져오기는 열 제목과 신규 자료를 검사·포맷한 뒤 생성 파일을 교체한다. `check:references`와 개발 시작·빌드도 같은 검사를 수행하며 잘못된 자료는 해당 파일·시트·항목과 함께 중단한다. 배열·행 위치만 바뀌면 연결을 유지하고, 실제 순서나 의미가 바뀌면 플레이 흐름 검토를 요청한다. 원본·생성 JSON과 기존 게임의 수치·작업 순서는 변경하지 않았다.

현재 품질 기준 전체가 실행 규칙으로 자동 연결되지는 않는다. 엑셀에서 읽었다는 이유만으로 170행 전체가 구현됐다고 간주하지 않는다. 모든 표를 자동 해석하는 범용 도구 대신 플레이에 필요한 항목부터 연결한다.

**완료 기준:** 메뉴 순서가 바뀌어도 다른 음료의 수량을 가져오지 않는다. 필요한 행이 없거나 단위가 달라지면 확인할 항목이 명확히 드러난다. 원본 근거와 임시 게임 수치를 문서에서 구별할 수 있다.

### CAFE-07 · 실제 절차와 품질 기준

컵 기준선의 형상·ml 환산, 준비 배합 완성 수율, 원팩 규격, 샷당 원두량, 스팀과 세척 세부, 기한의 달력 계산 관례를 확인한다. 배합에 사용한 원재료의 남은 기한이 완성 배치에 어떤 영향을 주는지도 확인 대상이다.

이번 확인 범위는 완료했다. 사용자는 모든 N일 기한에 시작일을 포함하는 달력 계산을 선택했고, 배합은 실제 투입 원재료의 가장 빠른 기한으로 제한하도록 결정했다. 해당 기한을 계량 도중부터 저장하고, 만료된 배합의 추가 투입·혼합·블렌딩·라벨·보관을 차단한다. 새로운 완성 배합의 기본 기한보다 원재료 기한이 빠르면 라벨에 이유를 표시한다.

용량·수율·원팩·샷당 원두량·스팀·세척 절차는 사용자가 기존 임시값 유지를 선택했다. 이를 실제 매장 기준이 확인된 것으로 표시하지 않으며, 추가 자료가 생기면 해당 부분만 재검토한다. 저장과 백업은 필수 상태가 모두 있는 현재 형식만 허용한다.

**완료 기준:** 확인된 값에는 자료 근거가 있고 관련 계산과 표시가 함께 바뀐다. 확인되지 않은 값은 기존 임시 규칙을 유지한다. 실제 자료가 없는 부분을 정확한 매장 절차로 단정하지 않는다.

### CAFE-08 · 용기 운반과 장시간 준비

보관 위치 선택 후 즉시 이관되는 재료를 실제로 집고 옮기는 조작, 콜드 브루의 원두·물 계량과 추출 완료 후 회수를 각각 작은 작업으로 나눈다. 반복적인 긴 이동이 재미를 늘리는지 먼저 확인한다. 기존 자동 정렬 원칙을 유지하고 자유 유체·충돌 물리부터 만들지 않는다.

완료했다. 준비대에서 라벨을 붙인 폼·바모카를 E로 집어 각각 냉장고·실온 선반에 E로 보관한다. 같은 작업대에 다시 내려놓을 수 있고, 잘못된 장소나 다른 물건과 동시 운반은 거부한다. 원팩은 창고에서 개봉·라벨·보관하는 흐름을 유지한다.

콜드 브루 추출대를 추가했다. 사용자 선택에 따라 전용 원두 재고를 별도로 만들지 않고 한 배치분을 9,000원에 확보한다. 원두 5lb·물 14L 계량 후 20시간 추출하며, 추출 중에는 마감·다음 날 이동이 가능하다. 완료 시각을 저장하고 E로 3L를 회수·라벨·냉장 운반해야 사용 가능 재고에 넣는다. 준비 중단은 원두 한 배치분 폐기, 완료 후 폐기는 추출액으로 구분한다.

**완료 기준:** 이동은 재료를 새로 만들거나 소비하지 않고, 용기의 잔량·라벨·기한을 유지한다. 콜드 브루는 다음 날 건너뛰기와 함께 진행되며 같은 추출 결과가 중복 생성되지 않는다. 미개봉 소비기한·보관 온도 누적 같은 새 규칙은 자료 확인 후 별도 범위로 정한다.

### CAFE-09 · 메뉴 확장

다음 메뉴는 제공 자료에 있는 후보 중 사용자가 고른다. 한 번에 한 종류를 추가하고 필요한 원재료·준비 배합·기구·작업 순서·POS·전달 판정을 함께 연결한다. 데이터 행만 추가해 실제로 제조할 수 없는 메뉴를 주문에 노출하지 않는다.

이번 메뉴는 완료했다. 호지차 샷 정수 250ml·파우더 8스쿱·10회 쉐이킹과 냉장 24시간을 자료에서 읽고, 라벨·용기 운반과 원재료 기한 상한을 적용한다. 매 음료마다 다시 섞은 뒤 실제 붓는 만큼만 소비한다. 두 온도 모두 클래식 3펌프·폼·파우더·리드까지 원문의 순서를 따른다. 신규 게임용 용량·수율·규격·가격·재혼합 횟수와 월 기한 해석은 [임시 규칙](./prototype-rules.md#호지-글레이즈드-티-라떼)에 구분했다.

**착수 조건:** CAFE-06 완료, 해당 메뉴의 누락 단위·장비 동작 확인. **완료 기준:** 실제 초기 재고와 준비 절차를 거쳐 주문부터 전달까지 플레이할 수 있다. 사이즈·커스텀 주문·다중 주문은 동시에 확대하지 않는다.

### CAFE-10 · 표현과 성능

기본 개선을 완료했다. 사용자 선택인 Chrome·Edge/FHD/60fps를 기준으로 측정하고, 마우스 감도 50~200%(기본 100%)를 추가했다. 반복 장식의 그리기를 묶고 액체·토핑은 내용물이 변할 때만 갱신한다. 시작·일시정지·결산에서 지속 렌더링을 생략하며 장면 종료 시 GPU 자원을 정리한다. 변경 전후 수치와 검증 범위는 [구현 기록](./implementation.md#표현과-성능-측정)에 남겼다.

**완료 기준:** 측정된 문제를 해당 장면·자원에서 개선하고 목표 환경에서 확인한다. 빌드의 Three.js 청크 크기 경고만으로 엔진 교체, WebGPU 전환이나 광범위한 코드 분리를 착수하지 않는다.

## 구현 전 결정이 필요한 항목

| 항목                     | 현재 기준                        | 결정 시점                               |
| ------------------------ | -------------------------------- | --------------------------------------- |
| 세척 세부·장비 시간      | 문서의 임시 게임 규칙            | 실제 절차로 바꿀 때 자료 확인           |
| 수율·포장 규격·실물 계량 | 사용자 선택으로 임시 수치 유지   | 실물 자료 확보 및 관련 메뉴 추가 전     |
| 추가 메뉴                | 호지 HOT·ICED까지 다섯 형태 구현 | 다음 종류 확장 전 사용자 선택           |
| 주문 압박·다중 주문      | 한 건, 대기시간 퇴장 없음        | 별도 난이도 확장 제안 시                |
| 장기 경영                | 하루 판매·입고·폐기 판단부터     | 발주 리드타임·고정비·직원 분담 도입 전  |
| 품질 목표                | Chrome·Edge, FHD, 60fps          | 저사양 Windows·고배율 화면·에셋 교체 전 |

이 결정들이 정해지지 않았다는 이유로 CAFE-01~06 전체를 중단할 필요는 없다. 영향을 받는 세부 구현에서만 확인하고, 이미 허용된 임시 규칙은 유지한다.

## 이번 후속 범위에서 제외

- 탭 간 실시간 동기화·병합·자동 인계와 현재 중복 실행 제한의 재설계.
- 저장 데이터 버전 관리·마이그레이션·구형 데이터 자동 변환.
- 원격 DB·계정·클라우드 저장·멀티플레이, 모바일·게임패드 지원.
- 대규모 범용 인벤토리·작업 엔진·경로 탐색 체계의 선행 구축.
- 실제 결제·회원 서비스, 직원 승진에 따른 업무 잠금.
- 측정이나 플레이 필요 없이 진행하는 엔진 교체·전면 구조 변경.

배포 설정은 이미 있으므로 신규 배포 기반을 만드는 작업은 없다. 출시할 변경 묶음이 준비되면 기존 GitHub Actions 절차를 사용한다. 실제 배포 상태는 이 문서의 로컬 코드 분석과 별도로 확인한다.

## 다음 구현 묶음

CAFE-01~09와 CAFE-10의 기본 성능·조작 개선을 마쳤다. 이후에는 실제 플레이에서 불편한 작업대·도구 표현을 고르거나, 저사양 Windows·고배율 화면·장시간 전체 근무의 추가 확인 범위를 정한다. 호지 메뉴의 추가 임시값도 사용자 답변이 오면 반영한다. 다음 메뉴·사이즈·커스텀 주문·다중 손님·원격 배포는 별도 선택 없이 확대하지 않는다.
