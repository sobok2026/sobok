# 카페 후속 작업

## 추가 결정이 필요한 범위

| 항목          | 확인하거나 결정할 내용                                                                                                                              |
| ------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| 실제 절차     | 세척·위생 단계, 보관 온도와 냉장 밖 체류, 미개봉 소비기한                                                                                           |
| 계량 자료     | 실물 컵 선·원팩 규격·샷당 원두량·완성 수율. 미확인 항목은 [게임용 규칙](./prototype-rules.md)과 구분                                                |
| 제조 자료     | 표 미검출 영상·미변환 전자책, 제조 원문 충돌과 미기재 수량, 바트 자동휘핑머신 절차                                                                  |
| 메뉴 확장     | 다음 메뉴는 사용자 선택 후 필요한 자료·부재료·장비·주문부터 전달까지의 흐름을 함께 연결                                                             |
| 손님과 난이도 | 다양한 외형·행동·다중 손님, 주문 대기시간 압박                                                                                                      |
| 경영          | 환불, 장기 통계·수요 예측·원가 배분, 발주 리드타임·고정비·직원 분담                                                                                 |
| 조작과 성능   | 실제 플레이에서 불편한 작업대·도구 표현, 키 재지정, 저사양 Windows·고배율 화면·장시간 근무                                                          |
| 매장 기자재   | 더북한산점 후방 설비의 기종·수량·위치, 푸드 쇼케이스·가열기·제빙기 기능. [확인 수준과 부족한 기자재](./graphics.md#부족하거나-확인이-필요한-기자재) |
| 위층 업무     | 2층·루프탑 탐색과 계단 이동은 구현했다. 위층 전 좌석 접객·컵 회수·청소 업무는 추가 결정이 필요하다.                                                 |

확인되지 않은 세부가 있어도 영향을 받지 않는 작업까지 중단하지 않는다. 새 근거가 확보되면 해당 제조 JSON과 [자료 운영 문서](./recipe-data.md)를 함께 갱신한다.

## 확장 원칙

- 한 업무의 완료 기준을 확인한 뒤 다음 범위를 정한다. 여러 신규 기능을 한 번에 확대하지 않는다.
- 측정된 문제를 해당 장면·자원에서 개선한다. 청크 크기 경고만으로 엔진 교체·WebGPU 전환·전면 구조 변경에 착수하지 않는다. 기존 측정 범위는 [성능 기록](./implementation.md)에 있다.
- 모바일의 세로·가로 터치 조작은 [모바일 화면과 조작](./mobile-controls.md)의 2026-09-29 사용자 결정을 따른다. 실제 기기 조작성·GPU 성능은 후속 확인 범위다.
- 게임패드, 원격 DB·계정·클라우드 저장·멀티플레이, 범용 인벤토리·작업 엔진·경로 탐색은 별도 합의가 필요한 확장이다.
- 저장·탭 정책 변경은 [아키텍처](./architecture.md#저장과-탭-정책)의 사용자 결정을 먼저 따른다. 출시할 변경은 [기존 배포 절차](../../apps/cafe/README.md#배포)를 사용한다.
