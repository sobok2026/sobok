# 모바일 화면과 조작

2026-09-29 사용자 결정으로 세로·가로 화면을 모두 지원하고 가로 플레이를 권장한다. 화면 회전을 강제하거나 시작을 막는 안내창은 두지 않는다.

## 디자인·플레이 분석

| 관점                                | 기존 문제                                                                                   | 적용                                                                                                                                                         |
| ----------------------------------- | ------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Apple · 손이 닿는 위치와 화면 경계  | PC의 중앙 프롬프트와 키보드 이동을 터치로 대신할 수 없다. 노치와 홈 인디케이터 여백도 없다. | 배경은 화면 끝까지, 정보와 버튼은 safe-area 안에 둔다. 왼손 이동·빈 화면 드래그·오른손 작업으로 역할을 나누고 주요 버튼은 최소 44 CSS px 높이를 확보한다.    |
| 토스 · 일관된 행동 표현과 읽기      | 모바일에서도 E·G·Space 같은 키 이름을 읽어야 하고 작은 화면에서 정보가 겹친다.              | 터치 중에는 키 배지를 숨기고 동사를 보여준다. 작업 안내는 입력 기기에 의존하지 않는다. 주문의 상세 정보는 라벨에서 읽고 메뉴는 상단 한 곳에 둔다.            |
| Blizzard · 매장을 가리지 않는 HUD   | 이동·작업·메뉴가 같은 공간을 차지하면 매장의 상태를 읽기 어렵다.                            | 상황에 맞는 작업 카드와 행동만 표시한다. 가로에서는 작업 카드를 오른쪽, 세로에서는 이동 스틱 위에 둔다. 선택 패널·도움말·일시정지 중에는 이동 스틱을 숨긴다. |
| PUBG · 익숙한 양손 조작과 입력 소유 | 화면을 누르는 동작이 시점 회전과 작업 시작을 겸하고, 어떤 손가락을 떼어도 작업이 멈춘다.    | 왼쪽 스틱과 빈 화면 드래그를 동시에 받는다. 각 입력은 자기 pointer ID만 해제한다. 화면을 둘러보는 터치는 재료 투입·물건 놓기를 실행하지 않는다.              |

모바일에서도 레시피 선택·계량·기한 계산의 판단은 유지한다. 자동 조준, 정답 수치 표시, 목표량 자동 정지, 자동 이동은 추가하지 않는다. 빠른 전투 조작보다 정밀한 카페 작업에 맞춰 스틱 중앙에는 작은 유격을 두고 기울기에 따라 걷는 속도를 조절한다.

## 화면

- `viewport-fit=cover`와 `100dvh`로 3D 화면을 가득 채운다. Canvas와 조준점은 전체 화면을 기준으로 한다.
- HUD·작업대·설정·도움말·POS는 네 방향의 `env(safe-area-inset-*)`를 적용한 영역을 기준으로 배치한다. 짧은 화면의 패널 높이도 그 영역을 넘지 않는다.
- 이동 스틱은 왼쪽 아래, 가능한 작업 버튼은 오른쪽 아래, 메뉴·시계는 오른쪽 위에 둔다. 터치 기기에서 상단 도움말·매장 바로가기는 메뉴 안에서 접근한다.
- 세로 화면은 주문과 메뉴가 겹치지 않도록 폭을 나눈다. 주문 상세·커스텀은 기존 라벨 보기에서 확인한다.
- POS는 세로에서 상품 선택과 주문 내역을 위아래로 배치한다. 좁은 화면에서는 상품을 3열로 보여주고 패널 내부를 스크롤한다. 입력창은 16px 이상으로 유지한다.
- 배경까지 터치 스크롤을 막지 않는다. Canvas·스틱·누르는 작업 버튼만 `touch-action: none`을 사용해 자료와 패널은 계속 스크롤할 수 있게 한다.

## 조작

| 입력                | 동작                                                                                                               |
| ------------------- | ------------------------------------------------------------------------------------------------------------------ |
| 왼손 스틱           | 7px 유격 이후 기울기에 따라 걷는다. 대각선도 최고 속도가 같다.                                                     |
| 스틱을 위로 더 밀기 | 반경 42px를 넘어 64px 이상 위쪽으로 밀고 있는 동안 기존 달리기 속도 2배를 적용한다. 자동 달리기로 고정하지 않는다. |
| 빈 화면 드래그      | 시점을 돌린다. 이동과 동시에 사용할 수 있다. 설정의 시점 감도를 함께 적용한다.                                     |
| 오른쪽 작업 버튼    | 바라보는 작업대의 기존 상호작용을 실행한다.                                                                        |
| 작업 카드           | 도구 선택·계량·확인을 기존 작업 규칙으로 실행한다. 누르는 작업은 손을 떼면 즉시 정산하고 멈춘다.                   |
| 폐기·취소           | 기존 800ms 길게 누르기를 유지한다.                                                                                 |

작업 버튼을 누르는 동안 시점 회전은 멈춘다. 이동을 시작하면 진행 중인 수동 작업을 멈춘다. 손가락을 떼거나 터치가 취소되거나 캡처를 잃으면 해당 입력을 해제한다. 화면 크기 변경·회전·창 비활성화·메뉴 진입에서도 입력을 초기화한다. 다른 손가락의 해제는 누르고 있는 작업을 끊지 않는다.

기본 입력은 기기의 주 포인터를 보고 정하고, 이후 실제 터치·펜·마우스·이동 키 입력에 맞춰 전환한다. 화면 너비만으로 모바일을 판정하지 않는다. 입력은 기존 `player-controls`와 세션 행동 콜백으로 전달하며 게임 저장 형식이나 업무 판정은 바꾸지 않는다. 터치에서 Pointer Lock을 요청하지 않는다.

## 근거와 확인 범위

- [Apple Game controls](https://developer.apple.com/design/human-interface-guidelines/game-controls): safe-area, 엄지 도달 범위, 44pt 주요 버튼, 상황별 노출, 왼손 이동·직접 드래그 시점. 웹 구현에서는 CSS px로 터치 영역을 확보한다.
- [WebKit · Designing Websites for iPhone X](https://webkit.org/blog/7929/designing-websites-for-iphone-x/): `viewport-fit=cover`와 네 방향의 safe-area inset.
- [토스 · 디자이너가 제품에만 집중할 수 있는 방법](https://toss.tech/article/toss-design-system): 화면 크기와 긴 텍스트 대응, 공통 컴포넌트의 일관된 경험, 눌림 피드백과 접근성.
- [Blizzard · Updated UI and HUD](https://news.blizzard.com/en-gb/article/23837944/get-into-the-grid-of-things-with-the-updated-ui-and-hud): 시야를 가리는 요소를 줄이는 HUD 구성.
- [PUBG Mobile · What are the controls?](https://pubgmobile.helpshift.com/hc/en/3-pubg-mobile/faq/37-what-are-the-controls/): 왼손 이동, 버튼이 없는 화면 드래그, 스틱을 이용한 달리기.

브라우저의 모바일 화면·멀티터치 에뮬레이션과 safe-area 여백을 넣어 배치와 입력을 확인한다. 실제 iOS Safari의 브라우저 바·홈 제스처, Android 기기별 동작 및 모바일 GPU 성능은 별도 기기 확인이 필요하다. 기존 데스크톱 성능 수치를 모바일 성능 보장으로 사용하지 않는다.
