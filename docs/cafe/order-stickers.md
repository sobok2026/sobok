# 주문 라벨

2026-09-28 사용자 요청으로 한국 스타벅스의 실물 주문 라벨을 참고해 3D 컵·프린터 출력물과 라벨 확대 보기에 적용했다. 사용자는 기본 샷·시럽량과 음료 약어까지 표시하고, 실제 코드를 확인하지 못한 메뉴는 영문 이름에서 약어를 만드는 방식을 선택했다. 이후 HUD 분석을 바탕으로 전체 라벨은 상시 표시에서 빼고, 사용자가 직접 열어 읽는 구성을 승인했다.

## 실물에서 가져온 구성

- 세로로 긴 흰 감열지, 작은 모서리 곡률과 상단 연두색 띠.
- 상단의 큰 주문번호와 작은 한글 음료명.
- 왼쪽의 `Decaf`·`Shots` 두 칸, 그 아래 `Syrup`·`Milk`·`Custom` 칸.
- 세로 구분선 오른쪽의 우유·샷·시럽 등 제조 요약과 아래쪽 결제 시각.
- 하단의 `i T)` 같은 온도·사이즈, 음료 코드, `1 of 2 (Bev 2)` 형태의 주문 순번과 매장·포장 표시.

실물 사진의 고객 이름·매장 정보·인증 로고는 옮기지 않는다. 게임 주문번호를 `A-01` 형태로 표기하고, 주문 채널별 번호 체계는 추가하지 않는다. 용지의 물리적 규격을 확인한 것은 아니며 사진의 비율을 참고한 게임용 표현이다.

## 데이터와 표시

[order-sticker.ts](../../apps/cafe/src/features/service/order-sticker.ts)는 결제한 주문과 커스텀 적용 후 제조 계획에서 라벨을 계산한다. 실제 기본 우유·샷·시럽 펌프 수는 오른쪽에, 변경한 샷·시럽·우유는 왼쪽 마킹 칸에도 표시한다. 기본 디카페인·리스트레토도 해당 칸에 반영한다. 시럽 제외는 `0V`처럼 0으로 표시하고, 약어를 확인하지 못한 재료나 복잡한 커스텀은 한글로 적는다. 컵 종류·계량선·스팀 설정의 정답은 추가하지 않는다.

음료 마킹은 아래 공개 자료에서 확인한 값을 먼저 사용한다. 나머지는 레시피의 영문 ID에서 단어의 첫 글자를 따서 만든다(`black-glazed-latte` → `BGL`, `hoji-glazed-tea-latte` → `HGTL`). 온도는 별도의 `i` 표기로 구분하고, 이름이 다른 변형은 해당 변형의 영문 이니셜을 덧붙인다. **자동 생성 약어는 게임용이며 실제 매장 코드라고 확인한 값이 아니다.**

라벨의 시각은 게임의 현재 시각이 아니라 `sale.paidAt`을 사용한다. 순번은 주문의 전체 수량에서 해당 잔의 위치를 계산하므로 여러 메뉴·여러 잔에서도 중복되지 않는다. 컵에 붙인 라벨은 프린터 대기 목록에서 빠지고, 재제조하면 같은 주문의 라벨이 다시 나온다. 라벨용 저장 필드는 추가하지 않는다.

[order-sticker-print.ts](../../apps/cafe/src/features/service/order-sticker-print.ts)의 배치를 확대 보기의 SVG와 3D CanvasTexture가 함께 사용한다. 긴 이름·커스텀은 줄바꿈하고 용지 높이를 늘려 누락하지 않는다. 컵 라벨은 컵 곡면을 따르고, 프린터는 최대 네 장의 서로 다른 대기 라벨을 표시한다. 장면 종료 시 기존 자원 정리에서 텍스처를 해제한다.

## 상시 요약과 확대 보기

주문 레일은 현재 음료·온도·사이즈·매장/포장·커스텀 개수·제조 단계와 대기 잔 수만 요약한다. 대기 잔 수는 현재 음료 한 잔을 제외한 미전달 수량이며, 메뉴별 `1/3잔` 같은 순번은 따로 표시하지 않는다. 전체 라벨과 스크롤은 두지 않는다. 작업 중에는 기존처럼 메뉴명과 단계 점으로 접히고, 장비 작동 칩과 다음 행동은 긴 커스텀에 밀리지 않는다. 스티커를 붙여도 HUD의 표현 방식이나 길 안내 위치는 바뀌지 않는다.

결제된 현재 음료가 있으면 레일의 `라벨 보기` 버튼 또는 `L`로 [OrderLabelDialog](../../apps/cafe/src/features/service/OrderLabelDialog.tsx)를 연다. 출력된 주문은 컵에 붙이기 전에도 읽을 수 있다. 확인 중에는 게임 시간·제조 입력·작업음을 멈추고 커서를 푼다. `L`·`Esc`·닫기 버튼으로 열기 전 화면·작업대 패널·시점 조작 상태에 돌아간다. 실제 주문 내용과 라벨 부착 상태는 바꾸지 않는다.

라벨은 384px 너비를 기본으로 읽기 좋게 확대한다. 작은 창이나 긴 커스텀은 대화상자 본문에서만 스크롤하며, 제목과 닫기 버튼은 고정한다. 키보드로 본문에 초점을 옮겨 방향키·Page Up/Down으로 읽을 수 있다. 확대 보기 상태는 기존 세션에만 두며 저장 스키마에 추가하지 않는다.

레시피 양을 숨기는 교육 원칙의 예외는 **실제 주문 라벨에 인쇄하는 샷·시럽 요약**에 한정한다. 기본량과 커스텀은 실제 라벨과 확대 보기에 유지하고 작업 카드와 판정 규칙은 그대로 따른다.
