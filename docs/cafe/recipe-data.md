# 카페 제조 자료 운영

`apps/cafe/data/`의 JSON을 Git으로 관리한다. 제조 규칙, 판매 조건, 재고 운영값을 나누고 앱이 같은 자료에서 주문·작업 순서·재료 소비·매출을 계산한다. 월간 갱신은 해당 JSON을 직접 수정한다. 레시피 DB, 데이터 버전, 마이그레이션, 하위 호환 계층은 없다. 게임 진행만 브라우저 IndexedDB에 현재 형식으로 저장한다.

## 자료 범위

209개 문서·280개 제조 구분을 수록한다. 아카데미 영상 표에서 정리한 203개 문서, 제공 자료의 5lb 콜드 브루 배합 1개와 부재료 제조표로 보완한 5개 문서다. HOT·ICED, 기본·대용량 등은 문서 안의 `variants`로 구분한다.

[자료 범위](../../apps/cafe/data/coverage.json)는 원래 목록 231개 중 영상 230개와 전자책 1개를 구분한다. 영상 205개에서 표 241개를 확인했고 중복 자료 2개를 정리했다. 표 미검출 영상 25개와 미변환 전자책은 목록에 남아 있다. 전체 목록을 변환했다고 표시하지 않는다. 원본 영상·이미지는 앱이나 빌드에 포함하지 않는다. `references/`의 엑셀은 참고 자료다.

현재 판매 범위는 온도·제조 구분을 나눈 129개 메뉴, 305개 사이즈 조합이며 부재료 준비대는 66개 제조법을 제공한다. 별도 콜드 브루 추출대가 한 제조법을 담당한다. 가격·원문·준비 경로 확인이 남은 75개 음료 구분은 보류한다.

판매 메뉴는 고정된 ID 목록으로 관리하지 않는다. 공개 가격, 해당 규격의 원문 계량, 제공 용기, 실제로 만들 수 있는 부재료의 전체 경로가 갖춰진 조합을 구성한다. 원문 검토가 필요한 제조법, 불명확한 수량, 가격 미확인 조합은 사유와 함께 판매에서 제외한다. H 자료실은 판매 여부와 관계없이 전체 원문을 보여준다.

## 제조 데이터 작성 원칙

- 재료·레시피·제조 구분·단계·장비·장비 프로그램·용기·POS 메뉴 그룹의 고정 ID는 영문 소문자·숫자를 하이픈으로 연결한 `kebab-case`로 작성한다. 장비 프로그램 번호처럼 숫자만 있는 ID도 허용한다.
- 레시피 파일명은 문서 ID와 같게 둔다. 메뉴의 `recipeId:variantId`, 준비 산출량의 `recipeId/variantId`는 각 ID를 기존 구분자로 연결한다. 이름이 바뀌어도 ID는 유지하며 `name`·`label`·설명·원문 조건은 한글로 보존한다. 상태 필드·코드 변수의 `camelCase`와 실행 중 생성하는 UUID는 별도다.
- ID 변경은 정의·참조·재고 키·POS 연결을 함께 수정한다. 이전 ID의 별칭·변환표·저장 버전·마이그레이션은 두지 않는다. 기존 ID가 남은 게임 저장·JSON 백업은 현재 형식으로 읽지 못할 수 있으며 새 근무를 시작한다.
- 별도 등록된 재료는 영어 이름이 비슷해도 합치지 않는다. `green-tea-bag-for-base`와 `green-tea-bag-for-iced-tea`, `mango-passion-fruit-juice`와 `mango-passion-fruit-juice-for-banana`는 각각 유지한다.
- `amount`는 투입량, `count`는 펌프·샷·스쿱 등의 횟수다. `line`, `mark`, `fill-volume`, `rim-gap`은 내용물이 도달할 기준이다. 투입량과 최종 도달선을 바꾸지 않는다.
- 사이즈별 수량은 `by-size`로 기록한다. 다른 사이즈의 눈금·스쿱은 `referenceSize`로 지정한다.
- 컵 기준선과 텀블러 ml 계량은 서로 다른 조건이다. 텀블러 수량을 컵 선의 실측 용량으로 쓰지 않는다.
- 펌프 횟수와 토출량을 구분한다. 10.2ml × 18펌프는 183.6ml이며 원문의 180ml는 사용자가 확인한 반올림 표기다.
- `run-machine.program`은 프로그램 번호, `cycles`는 작동 횟수다. 3번 프로그램 1회는 블렌딩 3회가 아니다.
- 범위·대략값·최소 횟수를 보존한다. 소수 횟수는 해당 분할 단위로 조작한다. 빈칸을 0이나 임의의 기본값으로 채우지 않는다.
- 계량 기준이 없으면 `unspecified`, 완성 수율이 없으면 `output.amount: null`로 둔다. 판매를 위해 원문 데이터를 추정치로 채우지 않는다.
- 대체 계량법은 `alternatives`, 조건은 `when`, 원문에 명시된 기본 커스텀은 `defaults`로 관리한다. 한국어 이름을 검색해 기본 선택을 추측하지 않는다.
- 물성이 묽을 때 추가 블렌딩하는 등의 관찰 조건은 제조 중 확인한다. 같은 원문 단계에 속한 동작은 같은 조건 결정을 공유한다.
- 단계의 `label`은 원문 단계 이름이다. 동작이 여러 개인 단계는 제조 화면에서 각 동작의 재료나 작업 이름으로 나뉜다. 같은 이름이 반복되면 붓는 곳·부위·위치를 덧붙인다. 규칙은 [step-labels.ts](../../apps/cafe/src/features/production/step-labels.ts)에 두고 JSON에 동작별 이름을 따로 적지 않는다.
- 비슷한 이름의 베이스·파우더를 같은 재료로 간주하지 않는다. 준비 재료를 소비하는 동작만 제조 의존 관계에 포함한다.

원문에 없는 재혼합 횟수, 얼음 스쿱 수, 혼합·에스프레소·스팀 시간을 만들지 않는다. 시간이 없는 장비 동작은 완료 확인으로 진행한다. 원문의 프로그램 시간, 공기 주입, 티백 물기 빼기, 콜드 브루 20시간은 유지한다. 게임 시계를 가속해도 제조 기간 자체는 바꾸지 않는다.

## 제조 실행과 재고

`features/production/workflow.ts`는 원문 행동을 작업대·조작·도구·목표에 연결한다. `runtime.ts`는 현재 단계, 진행량, 장비 작업, 조건 결정, 실제 사용 배치를 처리한다. 제조 가능한 음료와 부재료는 같은 엔진을 사용하고, 콜드 브루 추출대는 별도 장비 업무로 관리한다.

사용 전 혼합은 실제로 사용할 재고 배치에 귀속된다. 빈 보틀로 혼합을 완료할 수 없다. 선택한 배치가 만료되거나 폐기되면 새 배치를 혼합하고 남은 양부터 붓는다. 재혼합 자체는 재료를 소비하지 않는다.

연속 입력은 명시된 최대량에서 멈춘다. 범위는 최소량 이상에서 완료할 수 있고, 최소 이상 조건은 상한을 만들지 않는다. 횟수 투입은 목표를 넘으면 실패한다. `1e-9` 보정은 부동소수점 계산 오차 처리다.

재고 계산은 실제 사용 배치에서 소비하고 용기 간 이동에서는 다시 차감하지 않는다. 용기 내 재료 수량·부피와 액체·거품·고체 구분을 사용해 전체 이관, 액체만 붓기, 거품 올리기, 얼음 거르기를 처리한다. 화면의 높이·색은 계산 결과의 표현이며 재고량의 근거가 아니다.

부재료 제조를 마치면 원문의 라벨·보관 지시를 배치 업무로 연결한다. 완성 배치는 라벨과 보관을 마쳐야 사용할 수 있다. 투입 원재료의 가장 빠른 만료 시각을 유지하고, 현재 원재료 기한과 완성품 기본 기한 중 이른 시각을 적용한다. 사용한 재료가 만료된 음료·배합은 더 진행하거나 판매할 수 없다. 음료 판매 후 제조 용기에 남은 재료는 폐기 기록에 반영한다.

## 게임용 운영값과 컵 용량

사용자가 승인한 게임용 원팩·입고가·초기 재고·기한·환산값·준비 산출량은 `data/shop/`에 둔다. 원문에 명시된 단위와 토출량, `lineVolumes`의 ml를 우선하며 불명확한 재고 환산만 운영값을 사용한다. 이 값은 제조 목표나 자료실의 원문을 바꾸지 않는다.

일회용 아이스 컵의 `serving-cup.lineVolumes`는 다음 ml만 저장한다.

| 사이즈 | 하단선(ml) | 중단선(ml) | 상단선(ml) |
| ------ | ---------: | ---------: | ---------: |
| Tall   |     111.73 |     163.63 |     206.23 |
| Venti  |     170.20 |     249.33 |     307.37 |

한국 매장용 샷당 원두량은 공개 자료에서 확정하지 못했다. [Starbucks at Home](https://www.starbucksathome.com/brewing-guide/how-use-espresso-machine-brew-espresso)의 가정용 안내를 매장 머신 규격으로 단정하지 않는다. 재고용 9g/샷은 게임 설정이다.

`cold-brew-batch`는 제공 자료의 5lb·물 14L·20시간이며 완성량 3L는 게임 재고량이다. 별도 `cold-brew-toddy`의 3lb·물 5L 후 4L·20시간·완성 원액 6L를 다른 배합에 대입하지 않는다.

## 제공 용기와 컵

제조법의 제공 용기가 컵 보관대의 컵을 정한다. `serving-cup`은 온도·이용 방식·사이즈에 맞는 표준 컵이 되고 전용 용기는 같은 ID의 전용 잔이 된다. 에스프레소 포장의 `short-paper-cup`은 HOT 종이컵 Short 재고를 쓴다. 표준 컵에 없는 규격이나 이용 방식은 판매에서 제외한다. 컵 종류와 규격은 [매장·포장 컵](./design.md#매장포장-컵)을 따른다.

2026-09-27 사용자 결정으로 원문에 없는 제공 용기를 게임 설정으로 정했다. 칵테일은 원문이 `전용 잔`으로만 적으며 모두 매장에서만 판매한다.

- 마티니·시트러스 콜드브루 마티니·에스프레소 마티니·라떼 위스키 마티니는 `martini-glass`, 딸기 레몬 보드카 블렌디드는 `tulip-glass`다. 장충라운지R점 사진([신세계그룹 뉴스룸](https://www.shinsegaegroupnewsroom.com/go-hyeongjang-estate-starbucks-lounge/), [덴 매거진](https://www.theden.co.kr/news/articleView.html?idxno=2958), [아주경제](https://www.ajunews.com/view/20240911202804145))에서 잔 모양을 확인했다.
- 사진으로 확인하지 못한 아페롤 스프릿츠·오미자 유스베리 모히토와 기존 `cocktail-glass` 음료는 `cocktail-glass`로 두고 하이볼 모양으로 그린다.
- 스타벅스 더블 샷 원문은 7oz 컵과 전용 리드만 적는다. 포장은 `double-shot-cup`, 매장은 `double-shot-glass`로 나누고 리드는 포장에만 덮는다.

## 월간 갱신

1. 바뀐 원문을 대조해 제조 구분·수량·순서·조건을 해당 JSON에서 수정한다.
2. 필요한 재료·장비·용기를 연결한다. 미확인 수량은 미확인 상태로 남긴다.
3. 판매할 규격의 공개 가격을 `menu.json`에 넣고 근거 문서를 갱신한다. 새 재료의 게임 재고 설정도 `data/shop/`에 추가한다.
4. 원문 확인이 끝난 `review`를 해소한다. 새 추출 자료를 확보했으면 `coverage.json`도 갱신한다.
5. 검사 결과의 제외 사유를 확인하고 영향을 받는 주문·제조·준비·판매 화면을 확인한다.

```sh
bun run --filter=@sobok/cafe check:recipes
bun run --filter=@sobok/cafe type
bun run --filter=@sobok/cafe build
```

`check:recipes --details`는 메뉴별 판매 보류 사유를 출력한다. `dev`와 `build`도 자료 검사를 먼저 실행한다. 새 행동 종류가 없으면 음료별 실행 코드나 POS 분기를 추가하지 않는다. 테스트 코드는 사용자 방침에 따라 추가하지 않는다.

## 구현 확인 범위

전체 JSON 검사·타입 검사·프로덕션 빌드가 통과했다. 판매 계획 460개(사이즈·이용 방식)와 준비법 59개의 조건·범위별 자료 검산에서 이관 598건의 공급 부족이 없었다. 화면 높이로 재고량을 계산하는 경로는 제거했다.

실제 상태 처리 함수를 통해 아메리카노 Tall·더블 머스캣 Venti·퓨어 말차 ICED Tall·스팀 우유 Tall의 재료 소비부터 판매액 반영까지 확인했다. 퍼플 머스캣 토핑과 말차 샷의 제조·라벨·운반·보관도 함께 실행했다. 브라우저에서는 POS의 104개 메뉴와 지원 규격, 현재 형식 백업 불러오기, 더블 머스캣 Venti 전달 후 8,300원·완료 1잔·잔액 58,300원을 확인했다. 모든 메뉴의 키보드·마우스 제조를 직접 수행한 것은 아니다. 검증용 백업·실행 자료는 앱에 포함하지 않았으며 테스트 코드는 추가하지 않았다.

## 부재료 제조표 보완

2026-09-28 사용자 제공 `IMG_9241.heic`의 부재료 제조표를 대조하고, 사진과 기존 설정이 충돌하는 수치는 사용자 확인 후 사진 기준으로 수정했다. 시그니처 초코는 사용자 정정인 실온 2일·마감 시 냉장을 우선한다. [항목별 대조와 미확인 사항](./preparation-source-comparison.md)을 함께 관리한다.

확인된 보관·기한은 `quality.json`에 두며 `shop/inventory.json`의 중복 임시값을 제거했다. `storageLifetimes`는 같은 재료의 보관 방식별 기한, `closingStorage`는 마감 시 보관 조건이다. 배치의 `storage`는 선택한 보관 방식이며 `ingredientExpiresAt`은 실제 투입 원재료의 가장 이른 만료 시각이다. 선택을 바꿔도 최초 제조 시각과 원재료 기한을 보존한다. 냉장 기한의 라벨을 미리 써도 냉장 보관 전까지는 기존 실온 기한이 적용되며, 이미 만료된 배치는 이동으로 되살릴 수 없다.

새 시그니처 초코 원팩은 사용자 승인으로 바모카 원팩의 게임 재고값을 재사용한다. 원문의 완성 수율은 미기재 상태로 두고, 로스트·시그니처 초코·하프앤하프의 게임 산출량은 기존 품목 규격인 1,000ml를 사용한다. 에스프레소 칩은 기존 원두 환산인 스쿱당 2g과 범위 최솟값 규칙에 따라 4g, 대용량 콜드 폼·클래식 밀크티는 기존 게임 수율의 두 배인 780ml·2,080ml다. 이 수치는 매장 실측값이 아니다.

일반 휘핑 통 제조는 사용자 확인으로 슈크림 휘핑과 같은 가스 주입·30회 흔들기를 추가했다. 완성품 입고를 해제하고 기존 게임 규격 500ml를 준비 산출량으로 연결했다. 바트의 자동휘핑머신 작업은 확인 대상이다.
