# 카페 제조 자료 운영

제조 기준은 `apps/cafe/data/`의 JSON에 두고 앱이 같은 데이터를 읽는다. 레시피의 문장이나 한국어 이름으로 행동을 추측하지 않고, 재료·도구·용기 ID와 `operations`에 기록한 순서·수량·조건을 사용한다. 월간 갱신도 이 JSON을 직접 수정한다.

## 수록 범위와 현재 플레이

2026-09-25 정리 기준으로 204개 문서와 272개 제조 구분을 수록했다. 아카데미 영상 표에서 정리한 203개 문서에 기존 제공 자료의 5lb 콜드 브루 배합 1개를 더한 수다. HOT·ICED, 기본·대용량 등은 문서 안의 별도 `variants`로 구분한다.

[자료 범위](../../apps/cafe/data/coverage.json)는 원래 목록 231개 중 영상 230개와 전자책 1개를 구분한다. 영상 205개에서 표 241개를 확인했고 중복·이전 자료 2개를 정리했다. 표가 검출되지 않은 영상 25개와 아직 변환하지 않은 전자책은 이름·출처와 함께 남아 있다. 이 목록 전체의 내용을 추출한 것으로 표현하지 않는다.

현재 POS는 온도를 구분한 9개 메뉴, 28개 사이즈 조합을 제공한다. 준비대의 글레이즈드 폼·바모카·호지차 샷·말차 샷 4종도 원문 `operations`를 실행한다. 콜드 브루 배치 준비는 별도 추출 업무가 담당한다. 자료에 메뉴가 추가됐다는 이유로 POS에 자동 노출하지 않는다.

H 도움말의 자료실에서는 수록한 전체 제조법을 확인할 수 있다. 초기 실행에는 현재 매장에서 사용하는 문서를 읽고, 전체 자료실은 열 때 별도로 불러온다. 원본 영상·캡처 이미지는 앱이나 빌드에 포함하지 않는다. 원본 엑셀은 `apps/cafe/references/`에 참고 자료로 남기며 앱의 가져오기 입력으로 사용하지 않는다.

## 제조 데이터 작성 원칙

수량은 의미에 맞는 필드로 기록한다. `amount`는 투입하는 ml·g 등의 양, `count`는 펌프·샷·스쿱 등의 횟수다. `line`은 하단·중간·상단·사이즈·MAX선, `mark`는 쉐이커 C선이나 번호선, `fill-volume`은 용기의 내용물 전체가 도달할 부피선을 뜻한다. 컵 테두리 아래 간격은 `rim-gap`으로 보존한다. 투입량과 최종 도달선은 서로 바꾸지 않는다.

- T/G/V별 수량은 `by-size`로 기록한다. 다른 주문 사이즈의 스쿱·계량선을 사용하면 `referenceSize`를 지정한다.
- 컵 기준선과 텀블러 ml 계량은 서로 다른 조건으로 보존한다. 텀블러 수량을 일반 컵의 실측 용량으로 쓰지 않는다.
- 펌프의 횟수와 장비의 토출량을 구분한다. 원문에 있는 7.5ml·10.2ml·3.75ml만 해당 펌프에 연결한다.
- `run-machine.program`은 버튼·프로그램 번호, `cycles`는 누르는 횟수다. 3번 버튼 1회는 블렌딩 3회를 뜻하지 않는다.
- 범위·대략값·최소 횟수는 해당 필드로 보존한다. 빈칸을 0, 앞 행의 값, 임의의 기본값으로 채우지 않는다.
- 도구·스팀 설정·장비 시간이 명시되지 않았다면 생략한다. 원문에 정량이 없으면 `unspecified`, 완성 수율이 없으면 `output.amount: null`로 둔다.
- 대체 계량법은 `alternatives`에, 컵·이용 방식·커스텀·물성 조건은 `when`에 기록한다. 예를 들어 묽은 폼의 추가 블렌딩은 관찰 조건이 맞을 때만 실행한다.
- 준비 재료는 명확한 근거가 있을 때 제조법과 연결한다. 비슷한 이름만으로 서로 다른 베이스나 파우더를 합치지 않는다.
- 실행 수량은 `operations`를 기준으로 관리한다. 같은 수량을 별도 편집용 표에 반복하지 않고, 설명·주의사항에는 원문의 필요한 맥락을 보존한다.

원문에 없던 매 음료 재혼합 3회, 얼음 3스쿱, 바모카 혼합 6초, 에스프레소 2초·스팀 5초를 제조 기준으로 사용하지 않는다. 횟수·시간이 없는 혼합과 장비 동작은 완료 확인으로 진행한다. 원문이 명시한 폼 프로그램 약 25초와 콜드 브루 20시간은 실제 제조 시간으로 남긴다. 시뮬레이션 시간을 가속하더라도 원문의 기간을 바꾸지 않는다.

## 현재 플레이의 목표 확인과 재혼합

음료·준비대·콜드 브루 계량은 원문 목표에 추가 허용 구간을 두지 않는다. 연속 붓기·얼음·드리즐과 준비대 붓기, 콜드 브루 물 계량은 입력 진행률이 목표에 도달하면 자동으로 멈춘다. 펌프·톡 등 정수 횟수의 목표 초과는 실패로 처리한다. 부동소수점 계산 오차 보정 `1e-9`는 이 판정의 산술 처리이며 실제 재료의 물리 오차 허용값이 아니다.

호지차·말차의 사용 전 재혼합은 사용할 수 있는 실제 재고 배치에 귀속된다. 사용할 배치가 없는 빈 보틀은 혼합할 수 없다. 선택한 배치가 만료되거나 폐기되면 새 배치를 다시 혼합한 뒤 붓는다. 이미 부은 진행량과 소비량은 유지하고 남은 양부터 이어가며, 재혼합 행동 자체로 재료를 소비하지 않는다.

## 자료 확인 상태와 게임 지원

현재 정리에는 원문 확인이 필요한 제조 구분 10개와, 그 밖에 정량 미기재·동작 확인이 필요한 제조 구분 53개가 있다. 이 수는 월간 수정 후 검사 결과로 다시 확인한다.

| 구분                       | 의미와 처리                                                                                            |
| -------------------------- | ------------------------------------------------------------------------------------------------------ |
| `variant.review`           | 원문 충돌이나 판독이 해결되지 않은 구체적인 질문. 근거 확인 전 실행을 허용하지 않는다.                 |
| 정량 미기재·동작 확인 필요 | 원문이 수량 등을 제시하지 않아 자동 제조 계획에 필요한 값이 없는 상태. 없는 값을 추정해 채우지 않는다. |
| 현재 매장의 게임 기능 지원 | 그 제조법의 장비·재료·저장·작업대·전달을 현재 매장에서 사용할 수 있는지에 대한 별도 판단.              |

3D 장비가 아직 없다는 이유만으로 원문 `review`를 만들지 않는다. 반대로 원문 검토가 끝났다는 이유만으로 게임에서 모든 메뉴를 제조할 수 있다고 표시하지 않는다. `check:recipes`는 원문 상태와 자료의 실행 요건을 보고하고 현재 판매 조합을 검사한다. 새로운 메뉴의 실제 플레이 지원은 해당 업무 구현에서 연결한다.

## 재고 추정과 실제 계량 근거

미측정 컵 선의 ml, 원문에 없는 완성 수율, 샷당 원두 소비 같은 기존 추정치는 [재고 추정 파일](../../apps/cafe/data/simulation/stock-estimates.json)에만 두고 `stock-amounts.ts`를 통해 사용한다. 제조 순서·목표 계량·자료실의 원문 표시는 이 추정치를 읽지 않는다. 폼 450ml, 바모카 1500ml, 두 차의 샷 250ml, 현재 콜드 브루 배치 3000ml와 원두 9g/샷은 이 재고 계산 범위에 속한다.

확인된 펌프 토출량이나 원문의 명시적인 ml는 그대로 사용한다. 예를 들어 스위트 바닐라 소스 18펌프는 10.2ml × 18 = 183.6ml이며, 원문의 180ml는 사용자가 반올림 표기로 확인했다. 이 합의로 다른 제조법의 빈 완성량까지 채우지 않는다.

2026-09-25 공개 자료 확인에서는 한국 매장 컵 선의 ml와 한국 매장 에스프레소의 샷당 9g을 확정할 근거를 확보하지 못했다.

- [Starbucks at Home 에스프레소 안내](https://www.starbucksathome.com/brewing-guide/how-use-espresso-machine-brew-espresso)는 가정용 싱글 9g·더블 18g과 장비 제조사 권장량 확인을 안내한다. 한국 매장 머신의 확정 규격으로 적용하지 않는다.
- [Starbucks 미국·캐나다 콜드 컵 안내](https://about.starbucks.com/stories/2024/new-more-sustainable-starbucks-cold-cups-are-made-with-up-to-20-percent-less-plastic/)는 미국·캐나다 컵의 형태와 흑백 계량선 디자인을 설명한다. 한국 컵의 기준선별 ml나 높이를 제공하는 자료로 사용하지 않는다.

콜드 브루는 두 실제 자료를 구분한다. 현재 게임이 사용하는 `cold-brew-batch`는 기존 제공 자료의 5lb·물 14L·20시간 제조법이며 완성량 3L는 재고 추정치다. 별도 `cold-brew-toddy`는 원문의 3lb·물 5L 후 4L·21~27°C에서 20시간·완성 원액 6L·즉시 10°C 냉장 보관을 기록한다. TODDY의 6L를 다른 배합의 수율로 대입하지 않는다.

## 월간 갱신 절차

1. 바뀐 원문의 문장·표를 확인하고 해당 `data/recipes/` JSON의 제조 구분, 수량, 순서, 조건을 수정한다. 임시 원본 이미지로 판독할 수 있지만 이미지 자체는 앱에 넣지 않는다.
2. 필요한 재료·도구·용기 정의를 연결한다. 정확히 같은 항목은 기존 ID를 사용하고, 다른 재료를 이름 유사성만으로 연결하지 않는다. 미확인 수량과 수율은 비워 둔다.
3. 원문 충돌을 해결했다면 해당 `review`만 해소한다. 미변환 영상·전자책의 자료를 확보한 경우에는 `coverage.json`의 범위도 갱신한다.
4. 판매 메뉴를 바꾸는 작업에서는 `menu.json`과 실제 재료·장비·준비·주문·전달 지원을 함께 연결한다. 레시피 추가만으로 판매 범위를 넓히지 않는다.
5. 레포 루트에서 다음 검사를 실행하고 오류가 가리키는 문서·단계·참조를 수정한다.

```sh
bun run --filter=@sobok/cafe check:recipes
bun run --filter=@sobok/cafe build
```

`dev`와 `build`도 자료 검사를 먼저 실행한다. 필수 필드, 중복 ID, 없는 재료·도구·용기, 잘못된 사이즈·범위·장비 프로그램, 준비 재료 의존 관계와 현재 메뉴의 제조 계획을 확인한다. 자료의 제조 행동이 바뀌면 H 자료실 표시와 영향을 받는 실제 작업 흐름도 확인한다. 원본 엑셀 가져오기 스크립트, 데이터 버전 번호, 구형 자료 변환 단계는 없다.

## 이번 연결에서 확인한 범위
