# 첫 플레이 버전의 구현 규칙

사용자는 2026-09-23에 제공 자료의 공개 사용과 초기 게임 규칙 적용을 허용했다. 2026-09-25 자료 정리에서는 제조를 원문 기준으로 바꾸고, 확인되지 않은 기존 물리 수치는 재고 계산에만 유지하도록 정했다. 이 문서는 제조 원문, 재고 추정치, 조작·운영에 관한 게임 규칙을 구분한다.

## 자료

현재 제조 자료는 `apps/cafe/data/` JSON을 직접 편집한다. [제조 자료 운영](./recipe-data.md)에 스키마·카탈로그·실행 계획과 월간 갱신 절차를 정리했다. 다음 원본 엑셀은 `apps/cafe/references/`에 참고 자료로 남기며 앱의 가져오기나 빌드 입력으로 쓰지 않는다.

| 파일                         | 사용 시트                 |
| ---------------------------- | ------------------------- |
| `26_pre-autumn_recipes.xlsx` | 음료 제조, 폼·베이스 제조 |
| `best_by_core.xlsx`          | 제조 베이스, 코어 원재료  |
| `best_by_special.xlsx`       | 특화 원재료               |
| `ingredient_prep_guide.xlsx` | 부재료 제조               |

현재 수록 자료는 아카데미 표에서 정리한 203개와 기존 콜드 브루 배합 1개를 합한 204개 문서·272개 제조 구분이다. 표 미검출 영상 25개와 미변환 전자책 1개는 `data/coverage.json`에 별도로 남긴다. 원문 확인 10개와 그 외 정량 미기재·동작 확인 53개를 구분하며 게임 장비 지원 여부와 섞지 않는다. 수량·단위의 빈칸은 0이나 이전 행의 값으로 채우지 않는다.

현재 판매 메뉴 9개·28개 사이즈 조합과 준비대 4종의 단계·수량·조건은 JSON의 `operations`에서 읽는다. 새 자료에서 행동이나 순서가 바뀌면 작업대 연결과 재고 차감도 함께 확인한다. 품질 기준은 `data/quality.json`을 읽으며 아래 표는 원본 근거를 설명한다.

`recipe-schema.ts`는 구조와 행동 타입을 정의하고 `recipe-catalog.ts`는 ID·참조·단위·용기선·장비 프로그램·준비 재료 연결을 검사한다. `recipe-plan.ts`가 사이즈와 컵·서비스·선택 조건을 적용한다. 한국어 이름·설명문·엑셀 행 번호로 제조 행동을 추정하지 않는다. `check:recipes`는 개발 시작·빌드에서도 실행한다.

샷·펌프·드리즐·토핑은 각 온도·사이즈의 값을 보존한다. 폼의 크림·우유·펌프와 블렌딩 시간, 바모카의 봉·온수 L, 콜드 브루의 추출 시간도 해당 제조 문서에서 읽는다. 보관·품질 기한은 재료 ID와 개봉·소분·제조 조건으로 연결한다. 아래 행 번호는 참고 엑셀의 위치이며 코드의 조회 키가 아니다.

| 재료               | 자료 근거                                                            |
| ------------------ | -------------------------------------------------------------------- |
| 원두               | core / 제조 베이스 13행                                              |
| 우유·휘핑크림      | core / 코어 원재료 23행·22행                                         |
| 글레이즈드 소스    | special / 특화 원재료 72행                                           |
| 번트 카라멜 파우더 | special / 특화 원재료 51행의 소분후 기준                             |
| 바모카             | prep / 부재료 제조 13행, core / 제조 베이스 20행, 사용자 동일성 확인 |
| 글레이즈드 폼      | recipes / 폼·베이스 제조 7~10행                                      |
| 콜드 브루          | recipes / 폼·베이스 제조 24~26행, core / 제조 베이스 11행            |
| 클래식 시럽        | core / 코어 원재료 10행의 개봉후 1개월·실온 기준                     |
| 호지차 샷          | recipes / 폼·베이스 제조 15~17행의 제조 후 냉장·24시간               |
| 말차 샷            | recipes / 폼·베이스 제조 18~20행의 제조 후 냉장·24시간               |
| 말차 파우더        | core / 코어 원재료 36행의 개봉 후 실온·3개월, 사용자 동일성 확인     |

바모카 **원팩**은 준비 가이드의 봉 단위만 근거로 삼는다. 게임의 개봉 후 7일은 직접 대응하는 품질 기준이 없는 임시값이며, 제조한 **바모카 배합**의 24시간과 구분한다. 번트 카라멜 파우더는 소분후 7일, 글레이즈드 소스는 개봉후 3일을 선택한다. 2026-09-24 사용자는 모든 ‘N일’ 기한에 시작일 포함 N일의 마지막 날 종료 기준을 적용하도록 결정했다. 예를 들어 9월 1일 15시에 개봉한 우유는 9월 3일 0시에 만료된다. 24시간 기한인 휘핑크림은 같은 조건에서 9월 2일 15시에 만료된다.

레시피의 Tall 폼 50ml는 텀블러 계량값이다. 현재 일회용 컵 기준선의 재고 차감은 기존 추정치 45ml를 유지한다. 폼 450ml·바모카 1500ml·콜드 브루 3000ml 수율과 샷당 원두 9g, 원팩 크기·가격도 자료 갱신만으로 실제 규격이라고 간주하지 않는다.

## 메뉴 사이즈와 판매 가격

2026-09-25 사용자 요청에 따라 스타벅스 코리아의 메뉴별 판매 가격과 사이즈를 반영한다. 두 글레이즈드 라떼는 HOT·ICED 모두 Tall·Grande·Venti다. 콜드 브루는 Tall·Grande·Venti와 포장 전용 Trenta를 제공한다. 현재 메뉴의 Short 판매 근거는 확인되지 않아 사용자 확인 후 제외했다. 가격은 런타임 조회 없이 `data/menu.json`에 고정하며, 확인한 출처와 시점을 이 문서에 남긴다.

| -------------------------------- | -----------: | -------------: | ------------: | ------------------: |
| 콜드 브루 ICED                   |      5,100원 |        5,700원 |       6,500원 | 6,900원 · 포장 전용 |

확인일은 2026-09-25다. 콜드 브루 Tall은 [SSG 판매 상품](https://www.ssg.com/item/itemView.ssg?itemId=1000555813470), Grande·Venti는 [사이즈별 가격 자료](https://tis2055.tistory.com/87)를 대조했다. 두 글레이즈드 라떼는 [2026-09-15 판매 가격 자료](https://wonthrough.tistory.com/345), 블랙 라떼는 [2026-09 매장 결제 후기](https://www.th-study.com/blogs/life/699/show), 호지 Tall은 [2026-09-06 서울경제 취재](https://v.daum.net/v/pBSPswMVyr)를 함께 확인했다. 공식 홈페이지에서 모든 사이즈의 판매가를 제공하지 않으므로 공개 판매 자료를 대조한 고정값이며 실시간 가격 동기화는 아니다.

Trenta는 [2023-10-04 공식 상시 판매 공지](https://www.shinsegaegroupnewsroom.com/starbucks-trenta-150-million-sold/)와 [현재 공식 상품 등록](https://www.starbucks.co.kr/menu/drink_view.do?product_cd=9200000004770)을 확인했다. 최신 판매가는 공개 웹에서 검증하지 못했으며, 사용자가 마지막으로 확인된 [2024-08-27 가격 6,900원](https://earthman8202.tistory.com/128)을 적용하도록 명시했다. Trenta 추출액은 원본에 별도 수량이 없어 기존 비율 환산으로 224.9ml를 소비하며, Trenta 일회용 컵 재고를 사용한다. 매장 주문과 두 라떼에는 Trenta를 허용하지 않는다.

퓨어 호지차·말차는 2026-09-25에 [공개 사이즈별 가격 자료](https://www.sano.co.kr/스타벅스-가을메뉴-추천과-후기)와 [스타벅스 앱 가격을 인용한 매장 후기](https://www.diningcode.com/profile.php?rid=4KRvrNQ6ivng)를 대조했다. 두 메뉴 모두 Tall·Grande·Venti를 제공하며 위 가격은 공개 자료 기준 고정값이다. 공식 실시간 판매가 조회는 아니다.

손님의 메뉴·온도·이용 방식에 사이즈를 추가한다. 처음 두 주문은 기존 안내를 유지하도록 Tall이고 이후에는 주문 가능한 사이즈 중 하나를 고른다. POS의 선택 가격, 주문표, 필요한 컵, 제조 수량과 전달 시 매출이 같은 사이즈를 따른다. 손님 요청과 다른 사이즈는 전달을 거부한다.

- 샷 수는 원본의 Tall 1샷·Grande 2샷·Venti 2샷, 소스·클래식 시럽은 3·4·5펌프를 사용한다. 드리즐과 토핑도 각 온도·사이즈의 원본 값을 사용한다.
- 사용자 실측을 적용할 수 없는 컵 기준선 재료의 재고 차감은 `data/simulation/stock-estimates.json`의 승인된 추정치를 사용한다. 기존 Tall 추정량에 `사이즈 ml / 355`를 곱하고 소수 첫째 자리까지 사용한다. 콜드 브루 추출액과 우유, ICED 호지차 샷에 적용한다.
- 폼은 기존 Tall 컵 추정량 45ml를 유지하면서 원본 텀블러 수량 50·60·70ml의 비율을 적용해 45·54·63ml로 둔다. HOT 호지차 샷은 기존 50ml에서 원본 수량에 따라 50·60·70ml로 둔다. 두 값 모두 실물 컵 기준선의 정확한 ml로 간주하지 않는다.
- 얼음은 원문에 명시된 컵 선·테두리 간격을 목표로 채운다. 피처에서 컵으로 옮길 때도 원문 계량 기준을 사용한다. 3D 컵 크기는 용량 비율의 세제곱근으로 확대하는 게임 표현이며 실물 컵 치수는 아니다.
- 컵 재고는 종류·사이즈마다 독립적으로 관리한다. 다회용은 각 4개, 일회용은 보관대 2개·후방 12개로 시작한다. 일회용 컵 보충·입고도 선택한 종류·사이즈만 바꾸며 입고 단가와 묶음 수량은 기존 게임 규칙을 유지한다.
- 세척 화면은 피처·HOT 머그·ICED 유리잔으로 묶는다. 사이즈 선택이나 추가 세척 단계는 없으며 현재 주문에 필요한 사이즈가 대기 중이면 우선 고른다. 회수·세척·운반 중에도 컵의 종류·사이즈는 유지되고 해당 보관 재고로 돌아간다.
- 저장 데이터는 손님·주문표의 사이즈와 종류·사이즈별 컵 수량을 필수로 검증한다. 제조 컵의 종류에 사이즈를 포함하고 주문표와 일치하는지 확인한다. 기존 정책대로 이전 저장본의 누락 필드를 보완하는 마이그레이션은 두지 않는다.

## 직접 제조

직원은 카운터 안쪽 타일 통로에서 시작한다. 제조대·POS·픽업대는 직원 쪽 접근을 확인한 뒤 상호작용을 허용한다. 준비·세척·도구 정리·재고 관리도 안쪽에서 수행한다. POS 옆 직원 출입구로 나가면 객석 청소와 분리수거를 할 수 있다. 손님의 대기 위치와 객석은 카운터 바깥에 둔다.

E로 컵을 집거나 작업대에 내려놓고, G로 해당 단계의 도구를 집거나 놓는다. 클릭 또는 Space를 유지하면 붓기·젓기가 진행되고, 펌프·파우더는 원문의 횟수를 세고, 얼음은 원문의 목표선·간격 또는 명시된 스쿱 기준으로 계량한다. 목표량에 도달하면 도구를 놓고 F로 확인한다. 완성된 컵은 픽업대에 놓고 F로 전달한다. 다음 단계가 같은 작업대면 그대로 이어서 작업한다.

근무 시작·재개 후에는 마우스 버튼을 누르지 않아도 시점이 움직인다. 컵을 내려놓거나 부재료 준비·세척을 시작하면 시점이 작업물을 향하고 마우스 커서가 풀려 HUD의 버튼을 사용할 수 있다. WASD 이동, 컵·피처 집기, 작업 종료 후에는 다시 마우스로 시점을 조작한다. 작업대에 컵·준비 배합·세척 작업이 남아 있다는 이유로 시점 복귀를 막지 않는다. 준비·세척 작업대를 다시 바라보고 E를 누르면 커서 조작으로 전환한다. 오류가 난 컵은 화면 버튼 또는 F로 폐기한다.

입력 모드는 상시 HUD에서 설명하지 않는다. 마우스 고정이 지원되지 않을 때의 드래그·방향키 조작은 H 도움말에 둔다. 입력 모드는 저장 데이터에 넣지 않는다.

HOT은 피처에 우유를 직접 계량한 뒤 스팀을 시작한다. 스팀 피처는 우유를 컵에 붓거나 컵을 폐기할 때 세척 대상으로 보낸다. 블랙 글레이즈드 ICED는 샷 글라스에 추출한 뒤 혼합대에서 직접 컵에 이관하고 젓는다. 샷 글라스는 컵과 함께 운반되는 것으로 단순화한다. 스팀 우유는 이미 계량한 피처 잔량까지만 붓고, 기간이나 횟수가 없는 젓기와 장비 동작은 완료를 확인해 다음 단계로 진행한다.

재료는 실제 입력 진행량에 비례해 차감한다. 연속 붓기·얼음·드리즐은 입력 진행률이 원문 목표에 도달하면 멈춘다. 펌프·톡 등 정수 횟수가 목표를 초과하면 컵의 오류·작업대 오염으로 기록되고 재제조해야 한다. 제조 목표에 추가 허용 구간은 없으며 `1e-9`는 부동소수점 계산 오차만 보정한다. 이미 투입한 재료는 폐기하거나 저장을 다시 불러와도 자동으로 반환되지 않는다. 화면의 컵 높이·액체 층은 진행 상태를 표현하는 비율이며 실제 ml 눈금이 아니다.

이동·시선 이탈·입력 해제·일시정지·창 포커스 이탈은 연속 투입을 멈춘다. 장비 작업 중에는 컵 이동을 막는다. 도구를 든 상태에서는 컵을 집을 수 없다. 폼·드리즐 보틀·머들러·스쿱 등의 개별 세척은 아직 단순화하고, 피처·준비 배합 도구와 매장용 머그·유리잔을 세척·보관 흐름에 연결한다.

세척이 끝나면 선반에서 정리해야 피처를 다시 사용할 수 있다. 준비 배합 역시 깨끗한 피처를 소모한다. 작업대의 동시 작업과 제조 중인 컵의 중복 작업을 막는다.

피처 한 개를 세척대에 놓으면 세척 대기 수량에서 분리한다. G로 스펀지를 집고 누르며 문지른 뒤 스펀지를 놓고 F로 헹구기를 선택한다. 누르는 동안 헹구고 F로 완료를 확인한다. 씻은 피처는 E로 집어 도구 선반에 E로 놓아야 깨끗한 도구 수에 포함한다. 피처를 들고 다른 제조 도구를 동시에 사용할 수 없다.

문지르기·헹구기는 손을 떼거나 이동·일시정지하면 멈추며 저장 후 이어진다. 세척 취소는 피처를 오염된 대기 수량으로 돌려놓고 진행량을 지운다. 이미 씻었거나 들고 있는 피처를 세척대에 놓으면 세척 완료 수량으로 유지한다. 테이블·작업대 청소와 쓰레기 정리도 아래의 직접 조작 흐름을 사용한다.

컵이 있는 작업대에서는 컵 조작을 우선한다. 다른 작업대에 컵을 두면 혼합 작업대의 청소 메뉴를 열 수 있다. 부재료 준비나 피처 세척 전에 컵을 내려놓아야 하는 경우 다음 업무 안내에 선행 행동을 표시한다.

잘못된 주문 입력은 전달 시 손님의 원래 요청과 대조해 알려준다. 재제조 시 이미 쓴 재료는 복구하지 않는다. 일회용 컵은 폐기하고 다회용 컵은 내용물을 비워 세척 대기로 보낸다. 주문을 전달해야 판매 기록과 운영비가 증가한다.

## 첫 근무 안내와 작업음

플레이 중에는 현재 행동·키·계량만 표시한다. 도구 순서, 부족한 재료의 개봉·준비·라벨·보관, 종류별 컵·피처 운반은 H 도움말에서 현재 상태에 맞춰 안내한다. 도움말은 자동으로 나타나지 않으며 확인 중에는 시간이 멈춘다. 닫으면 열기 전 작업 패널과 입력 모드로 돌아온다. 안내가 업무를 잠그거나 재료·돈·작업 진행을 바꾸지는 않는다.

작업음은 기본 음소거이고 기본 음량은 35%다. Esc 메뉴의 설정에서 켜고 0~100%로 조절하거나 미리 들을 수 있다. 2026-09-25 사용자가 비교 화면에서 고른 실제 녹음으로 컵에 붓기·우유 피처 계량·추출·스팀·얼음·테이블 닦기를 구분한다. 스팀은 머신·우유 거품 녹음을 번갈아 사용한다. 완료·전달 bell은 유지하고 계량 목표 도달·확인·주문 입력·라벨 부착은 무음이다. 사용자 요청에 따라 컵·도구 조작의 타격음과 펌프·오류의 스위치 찰칵음을 제거했다. 특정 카페나 장비의 실제 녹음 재현은 아니며 [음원 크레딧](../../apps/cafe/public/audio/CREDITS.md)에 원본·라이선스·가공 내용을 기록한다.

연속 작업음은 실제 입력과 가까운 장비의 작동 상태를 따른다. 손을 떼면 붓기·닦기 소리가 멈추며, 일시정지·백그라운드·창 포커스 이탈·음소거 시 재생 중인 소리를 중단한다. 백업·자동 저장을 불러왔다고 지난 완료 알림을 다시 재생하지 않는다. 마우스 감도·음소거·음량은 같은 브라우저의 별도 설정으로 저장하고 게임 백업에는 포함하지 않는다. 게임 저장 형식은 바꾸지 않으며, 소리를 끄거나 재생에 실패해도 화면 게이지·완료·오류 안내를 통해 진행할 수 있다.

마우스 감도는 사용자 선택에 따라 현재 속도를 100%로 두고 50~200% 범위에서 조절한다. 마우스 고정과 드래그 시점에 같은 배율을 적용하고 방향키 회전 속도는 일정하게 유지한다. 감도도 현재 설정 형식의 필수 필드이며 이전 설정의 누락값을 채우는 코드는 두지 않는다.

## 부재료와 라벨

글레이즈드 폼 기본 배합은 원본의 200ml 휘핑크림 → 50ml 우유 → 글레이즈드 소스 7펌프(펌프당 10.2ml) → 3번 버튼 1회(약 25초)를 읽어 직접 조작에 연결한다. 바모카는 원팩 1봉·온수 1L를 읽고 잘 섞은 뒤 완료를 확인한다. 혼합 시간은 원문에 없으므로 지정하지 않는다. 준비대의 붓기 진행률도 목표에서 자동으로 멈추며 추가 허용 구간은 없다. 펌프·원팩은 원문의 정확한 횟수가 필요하다. 온수 공급은 기존 물 규칙처럼 제한하지 않는다.

준비대에 피처를 놓으면 깨끗한 도구 한 개를 예약한다. 실제 투입량만큼 재고를 차감하고, 혼합 완료 또는 배합 폐기 시 피처를 세척 대상으로 보낸다. 음료 컵이나 다른 도구를 든 상태에서는 준비를 시작할 수 없지만, 컵을 바에 두면 주문 도중 필요한 부재료를 만들 수 있다. 계량 중 다른 일을 하거나 저장을 불러와도 투입량이 유지된다.

완성된 배합은 준비대에 보관 대기 배치로 생긴다. 개봉·제조 시각, 품질 기한과 보관 조건을 확인해 라벨을 붙이고 E로 집는다. 폼·호지차 샷·말차 샷은 냉장고, 바모카는 실온 선반까지 직접 운반해 E로 보관한다. 원래 작업대에 E로 다시 내려놓을 수 있으며 잘못된 보관 장소는 거부한다. 이동은 같은 배치의 위치만 바꾸고 ID·잔량·라벨·만료 시각을 바꾸지 않는다. 냉장 밖 체류에 따른 별도 변질은 구현하지 않는다.

배합 용기는 한 번에 하나만 들고 컵·제조 도구·피처·스펀지·청소용 천·회수 컵·소모품과 동시에 들 수 없다. 운반 중 만료돼 보관할 수 없으면 원래 작업대에 내려놓고 폐기한다. 창고 재고 화면에서 원격으로 준비 용기에 라벨을 붙이거나 보관하는 경로는 제공하지 않는다. 원팩은 기존처럼 창고에서 개봉·라벨·보관한다.

원재료도 개봉 후 라벨과 보관 단계를 거쳐야 사용 가능 재고에 포함한다. 라벨 없는 배치·보관 대기 배치·기한이 지난 배치는 음료와 준비 배합에 소비할 수 없다. 라벨 부착과 위치 이관은 원래의 개봉·제조 시각과 기한을 바꾸지 않는다. 진행 중인 준비와 미보관 배치는 마감 전에 완료하거나 폐기해야 한다.

폼·바모카·호지차 샷·말차 샷에는 기한이 빠른 재고부터 실제로 투입한다. 여러 배치를 사용하면 투입량이 0보다 큰 배치들의 가장 빠른 만료 시각을 준비 상태에 기록한다. 빈 배치, 쓰지 않은 재고, 나중에 입고한 새 재료는 이미 기록한 기한을 늘리지 않는다. 완성 배치에는 제조 완료 후 기본 기한과 이 원재료 기한 중 이른 시각을 적용한다. 이는 제공 자료에 없던 관계를 사용자가 게임 규칙으로 확정한 것이다.

계량·혼합·블렌딩 중 원재료 기한이 지나면 작업을 중단하고 폐기해야 한다. 장비 완료 시각이 원재료 만료보다 이르면 배합을 완성하지만 그 이후에는 저장된 배합 기한을 그대로 적용한다. 만료 시각과 완료 시각이 같으면 사용할 수 없다. 라벨은 사용할 수 없는 시각을 ‘만료 시각’으로 표시하며, 원재료 때문에 짧아진 배합은 이유를 함께 안내한다.

## 호지 글레이즈드 티 라떼

2026-09-25 사용자가 처음 선택한 추가 메뉴는 Tall 호지 글레이즈드 티 라떼 HOT·ICED다. 기존 세 음료 뒤에 두 주문을 추가하며 첫 콜드 브루·첫 블랙 라떼 안내 순서는 유지한다. HOT은 우유 계량·스팀 → 클래식 시럽 → 스팀 우유 → 호지차 샷 → 폼 → 파우더 → 리드, ICED는 클래식 시럽 → 우유 → 호지차 샷 → 얼음 → 폼 → 파우더 → 리드 순서다. 에스프레소·바모카 드리즐은 넣지 않는다.

두 온도의 클래식 시럽 3펌프·펌프당 7.5ml와 파우더 2톡은 각 레시피 행에서 읽는다. 샷 준비는 정수 250ml → 1티스푼 스쿱으로 호지차 파우더 8스쿱 → 보틀 10회 쉐이킹을 자료에서 읽는다. 계량 피처를 기존 깨끗한 도구 재고에서 예약하고 완료·폐기 시 세척 대상으로 보낸다. 준비된 샷은 라벨 후 냉장고로 운반해야 사용할 수 있고, 제조 후 24시간과 투입 원재료 기한 중 이른 시각에 만료된다. 매 음료 사용 전 다시 섞은 뒤 계량해 붓는다.

재혼합 완료는 사용할 수 있는 실제 호지차·말차 재고 배치에 귀속되며, 사용할 배치가 없는 빈 보틀은 혼합할 수 없다. 선택한 배치가 만료되거나 폐기되면 새 배치를 다시 혼합해야 한다. 이미 부은 진행량은 유지하고 재혼합 후 남은 양부터 이어 붓는다. 재혼합 자체는 재료를 소비하지 않는다.

**추가 확인 전 적용한 게임용 임시값:** 재고용 완성 샷 250ml, HOT 우유 200ml·ICED 우유 140ml·샷 50ml·폼 45ml, 메뉴 가격은 [메뉴 사이즈와 판매 가격](#메뉴-사이즈와-판매-가격)의 스타벅스 코리아 가격표로 교체했다. HOT 원문의 샷·폼 50ml는 텀블러 한정 수치이고 ICED 컵 기준선에는 ml가 없으므로 현재 일회용 컵의 ml 환산을 실물 규격으로 간주하지 않는다. 클래식 시럽 원팩은 750ml·5,000원, 호지차 파우더는 80스쿱·6,000원·개봉일 포함 실온 7일로 둔다. 파우더의 개봉 기한은 제공 품질 표에 직접 대응하는 항목이 없어 임시값이며 준비된 샷의 24시간과 구분한다.

클래식 시럽의 원문 `1개월`은 달력 한 달로 임시 적용했다. 9월 25일 개봉이면 10월 25일 0시, 다음 달 같은 날짜가 없으면 그 달 말일 종료 시각에 만료된다(1월 31일 → 3월 1일 0시). 월 계산은 기존 기한 규칙을 유지한다. 위 물리 수치는 실제 규격으로 확정한 값이 아니며 사용자가 재고 계산에 한해 유지하도록 허용했다.

## 퓨어 호지차·말차 HOT·ICED

2026-09-25 사용자가 미구현 메뉴 중 이 두 종류, 네 온도 형태를 선택했다. 먼저 기존 샷을 사용하는 퓨어 호지차, 다음으로 말차 원재료·샷 준비와 퓨어 말차를 연결하고, 네 메뉴의 주문·제조·전달·저장을 확인하는 단위로 나눈다. 기존 다섯 주문 뒤에 퓨어 호지차 HOT·ICED, 퓨어 말차 HOT·ICED 순서로 손님 주문을 추가한다.

HOT은 워터 스테이션에서 주문 사이즈의 온수 디스펜서 버튼을 한 번 누르고 F로 확인한 뒤, 혼합 작업대에서 샷을 재혼합해 붓는다. 원본의 T·G·V 버튼과 텀블러 샷 60·70·90ml를 각 열에서 검증한다. ICED는 정수 중간선 → 샷 상단선 → 얼음 순서다. 두 온도 모두 포장 컵에만 리드를 덮고 매장 컵은 바로 전달한다. 우유·시럽·폼·파우더 토핑은 사용하지 않는다.

말차 샷은 원문의 정수 250ml → 1티스푼 스쿱으로 말차 파우더 8회 → 쉐이킹 10회를 사용한다. 날짜 라벨을 붙인 뒤 냉장고로 운반해 보관해야 음료에 쓸 수 있고, 제조 후 24시간과 투입 원재료 기한 중 이른 시각에 만료된다. 말차 준비 용기·샷 보틀·컵의 차 층은 녹색으로 구분한다. 준비·컵 중간 상태와 실제 차감·폐기량도 저장한다.

사용자가 레시피의 말차 파우더를 품질표의 `유기농 100% 말차 100g`과 연결하도록 확인했다. 현재 원팩 개봉 흐름에는 **실온·개봉 후 3개월**을 적용한다. 별도 소분 동작은 없으므로 소분 후 7일 규칙을 원팩에 대신 적용하지 않는다. 달력 월 계산은 기존 `expiryAt` 규칙을 따른다.

**사용자가 허용한 게임용 임시값:** 말차 원팩 80스쿱·6,000원, 재고용 완성 샷 250ml. 두 차 모두 원문대로 사용 전 다시 섞고 완료를 확인하며 재혼합 횟수는 지정하지 않는다. HOT 차감은 60·70·90ml, 미측정 ICED 컵은 Tall 60ml에 `사이즈 ml / 355`를 곱해 60·79.9·99.9ml를 사용한다. HOT 원문은 텀블러 수치이므로 실제 컵 ml로 단정하지 않는다. 80스쿱은 게임 재고 규격이며 100g의 실측 환산이 아니다.

3D 목표 높이는 HOT 온수 0.72 → 차 0.90, ICED 정수 0.40 → 차 0.80 → 얼음 0.96의 게임 비율이다. 원문의 테두리 아래 12mm·6mm를 정확한 실물 치수로 재현한 값이 아니다. 온수 버튼은 해당 단계의 정량 공급으로 표현해 반복 입력으로 중복 충전하지 않고, 정수·샷 직접 붓기는 입력 진행률을 원문의 목표에서 자동으로 멈춘다.

## 시간과 저장

게임의 가상 날짜를 기준으로 근무 중 실제 시간처럼 흐른다. 일시정지·백그라운드·앱 종료 중에는 멈춘다. 다음 날 버튼으로 이동한 시간은 재료 기한과 장시간 추출에 함께 적용한다.

IndexedDB에 주요 행동 뒤와 주기적으로 저장한다. 현재 저장과 이전 정상 저장은 하나의 트랜잭션으로 교체한다. 잘못된 현재 저장은 이전 저장본 복구를 시도한다. 백업 가져오기는 형식·수치 범위를 검증한 후 저장한다. 지원 브라우저에서는 Web Locks로 같은 출처의 동시 쓰기를 제한한다.

탭 간 상태 동기화는 사용자 결정으로 구현하지 않는다. 현재처럼 앱 로딩 후 한 탭이 잠금을 갖고, 다른 탭은 기존 탭을 닫은 뒤 새로고침해 진행한다. 시작 화면의 잠금 보유도 유지하며 자동 인계·강제 가져오기·잠금 시점 변경은 추가하지 않는다. Web Locks 미지원 환경의 현재 동작과 상세 범위는 [후속 작업 분석](./next-steps.md)에 기록한다.

저장에는 컵 위치·내용물·계량 진행량·피처 잔량·도구·장비 작업, 부재료 준비 상태·라벨·보관 대기/운반 용기와 콜드 브루 계량·추출·회수 상태를 포함한다. 버튼을 누르고 있다는 입력 상태는 저장하지 않는다. 콜드 브루는 추출 완료 뒤 직접 회수·보관해야 사용할 수 있다.

사용자 요청에 따라 저장 데이터의 버전 필드와 마이그레이션은 두지 않는다. 현재 데이터 구조에 맞는 저장만 읽으며, 이전 구조의 컵·작업·플레이어 위치를 자동 변환하지 않는다. 맞지 않는 기록은 이전 정상 저장본을 확인하거나 새 근무를 시작한다.

개봉·제조 시 확정한 만료 시각은 라벨 부착이나 운반으로 바뀌지 않는다. 준비의 원재료 기한 필드는 null 또는 실제 기록 시각이어야 한다. 누락 필드 허용·보완, 레거시 형식 판별, 버전별 분기, 마이그레이션·호환 코드를 두지 않는다.

초기 배치는 즉시 플레이할 수 있도록 준비되어 있다. 폼·바모카·호지차 샷·말차 샷은 직접 준비해야 한다. 전체 자료실의 모든 장비를 현재 매장에서 조작할 수 있다는 의미는 아니다. 원문 미확인 사항과 게임 기능 지원 범위는 별도로 관리한다.

## 청소와 하루 운영 기록

두 고객 테이블과 컨디먼트 바는 컵 수와 오염 여부를 각각 저장하며, 새 근무는 깨끗한 상태에서 시작한다. 매장 주문 전달 때 사용한 테이블 하나를 무작위로 고르고, 다회용 컵은 90% 확률로 컨디먼트 바에 반납하거나 10% 확률로 해당 테이블에 남긴다. 사용한 테이블과 반납에 사용한 컨디먼트 바, 음료 작업대는 각각 30% 확률로 얼룩이 생긴다. 컵 위치와 얼룩 판정은 독립적이며, 계량 초과로 생기는 작업대 오염은 유지한다. 이 확률은 사용자 확인을 받은 임시 게임 규칙이다. 결과는 성공한 전달 시점에 한 번 계산해 저장하며 새로고침이나 렌더링으로 다시 뽑지 않는다. 테이블이 더러워져도 신규 주문을 잠그지 않는다. 손님의 착석·반납 이동·퇴장을 실제로 표시하며, 정해진 시점에 해당 표면에 컵과 오염을 반영한다.

테이블·컨디먼트 바 청소는 E로 다회용 컵을 하나씩 회수해 세척대에 내려놓고, G로 천을 집어 누르고 닦은 뒤 천을 놓고 F로 마친다. 얼룩이 없는 자리는 컵 회수·세척대 운반만으로 표면 정리를 완료한다. 회수한 컵의 세척·컵 보관대 반납은 별도로 마쳐야 한다. 혼합 작업대도 직접 닦는다. 현재 오염된 작업대는 한 번의 닦기로 정리한다. 쓰레기는 누르고 모아 봉투를 묶고 F로 비운다. 봉투 작업 시작 뒤 추가된 쓰레기는 이번 봉투에 포함하지 않는다. 한 번에 한 청소 작업을 진행하며, 자리를 떠나거나 저장해도 진행량·들고 있는 컵이 유지된다. 취소하면 닦기 진행만 초기화하고 이미 회수·폐기한 물건은 되돌리지 않는다. 천이나 회수한 컵을 들고 다른 도구를 동시에 사용할 수 없다.

운영 기록은 하루의 시작 잔액·판매액·입고 지출·현금 증감·현재 잔액과 재료별 폐기량이다. 원팩, 컵, 소모품, 콜드 브루 추출 준비비를 각각 기록하고 다음 날에는 당시 잔액으로 새 기록을 시작한다. 현금 증감은 판매액에서 입고 지출을 뺀 값이며 순이익으로 표시하지 않는다.

재제조 컵은 실제 소비한 재료량을 폐기로 기록한다. 아직 완성되지 않은 배합은 투입 원재료를, 완성된 배치는 남은 완성 재료량을 기록해 원재료와 중복 집계하지 않는다. 스팀 피처의 남은 우유를 정리할 때도 폐기로 기록한다. 물·얼음은 기존 무제한 공급 규칙에 따라 재고·폐기량에 포함하지 않는다.

재고 화면은 사용 가능·미개봉·라벨/보관 대기·만료를 서로 겹치지 않게 구분한다. 현재 컵의 남은 단계, 진행 중인 준비, 주문에 부족한 폼·바모카·호지차 샷·말차 샷 한 배치의 원재료를 기준으로 부족 품목을 먼저 보여준다. 라벨·보관 대기는 사용 가능량에 합산하지 않는다.

## 컨디먼트 소모품

사용자 확인을 받은 임시 규칙으로 냅킨·빨대·설탕은 각각 진열 최대 20개·초기 진열 20개·후방 100개로 시작한다. 전달 성공 시 소모품 이용 의도를 정하고, 손님이 컨디먼트 바에 도착해 이용을 마칠 때 냅킨 1장, ICED 음료의 빨대 1개, 30% 확률의 설탕 1개를 진열대에서 소비한다. 품절인 품목은 음수로 차감하지 않고 보충 안내를 띄우며 주문·판매를 막지 않는다.

창고에서 비어 있는 진열 수량만큼 집으면 후방 재고에서 빠지고 운반 상태에 들어간다. 컨디먼트 바에 E로 놓아야 진열 수량이 늘어난다. 창고에서 E로 다시 내려놓으면 같은 수량을 반환한다. 운반 중 저장·복원으로 수량이나 소모품 종류가 바뀌지 않으며, 들고 있는 동안 컵·피처·다른 도구를 동시에 집지 못한다. 마감 전에 운반 중인 물품은 정리해야 하지만 진열을 가득 채우도록 강제하지 않는다.

각 품목의 추가 입고는 100개당 게임용 1,000원이며 당일 입고 지출에 포함한다. 매장 현황·결산에서 손님이 실제 사용한 소모품 수량도 확인한다.

## 손님 동선과 영업 마감

한 명씩 입장해 POS에 도착한 뒤 주문을 받는다. 주문표를 출력하면 손님이 픽업대로 이동하며, 대기 위치에 도착한 뒤에만 전달할 수 있다. 주문 번호·요청 메뉴·손님 ID를 같은 응대 동안 유지하고, 판매액은 전달 성공 시 한 번 기록한다. 이미 주문한 손님은 대기시간 때문에 퇴장하지 않는다.

매장 손님은 컨디먼트 바에서 소모품을 챙기고 테이블에 앉아 게임 시간 10초 동안 머문다. 이후 90%는 컨디먼트 바로 컵을 가져가 반납하고, 10%는 테이블에 컵을 남긴다. 테이블 오염은 이용을 마친 시점에, 반납 컵과 반납대 오염은 반납을 마친 시점에 반영한다. 이동 속도 1.7m/s, 소모품 이용·반납 동작 각각 1.2초는 시각적 연결을 위한 임시 조작 시간이다. 한 손님이 출구로 나가야 다음 손님이 입장한다.

이동 경로의 현재 지점·위치·방향, 단계별 경과 시간, 수령 후 이용 의도를 저장한다. 일시정지·백그라운드·종료 중에는 이동이나 체류가 진행되지 않으며 저장을 불러와도 판매·소모품 소비·컵 반납을 다시 수행하지 않는다.

신규 주문 마감 시 주문 전 손님은 돌아 나가고, 이미 주문했거나 수령한 손님은 이용·반납·퇴장까지 마친다. 손님이 남아 있으면 결산할 수 없으며, 퇴장 후 생긴 컵·오염까지 정리한다. 닦는 도중 새 반납 컵이 놓이면 닦기를 확인한 뒤 컵 회수 단계로 이어진다.

## 매장·포장과 컵 재사용

2026-09-25 사용자 확인에 따라 손님이 입장할 때 매장·포장을 50%씩 뽑아 저장한다. 매장 주문은 HOT 머그·ICED 유리잔, 포장 주문은 HOT 종이컵·ICED 일회용 투명 컵을 사용한다. POS 주문표에 이용 방식을 포함하며 주문표에 맞는 컵을 집는다. 전달할 때 손님의 메뉴와 이용 방식에 따른 컵이 모두 맞아야 판매된다.

매장용 컵은 종류·사이즈별 4개로 시작한다. 보관대의 깨끗한 컵 → 제조 → 손님 → 테이블 또는 컨디먼트 바 → 회수·세척 대기 → 문지르기·헹구기 → 씻은 컵 운반 → 컵 보관대 순으로 순환한다. 씻기만 한 컵은 재사용할 수 없으며 컵 보관대에 E로 돌려놓아야 한다. 피처는 기존 도구 선반으로 돌아간다. 세척 중 취소하거나 씻은 용기를 세척대에 다시 놓아도 수량을 유지한다. 재제조한 다회용 컵은 내용물만 폐기하고 세척 대상으로 보낸다. 컵 회수로 쓰레기가 늘어나지 않는다. 깨끗한 컵이 없으면 해당 종류·사이즈를 회수·세척해야 하며 일회용 컵으로 대체하지 않는다.

일회용 컵은 기존 총량을 둘로 나눠 종류별 보관대 2개·후방 12개로 시작한다. 종류별 한 번에 최대 6개를 보충하며 보관대 최대 12개, 추가 입고 24개·2,000원은 기존 게임용 값을 적용한다. 사용자는 이 수량 분할과 입고 규칙을 확인했다. 포장 손님은 음료와 소모품을 챙긴 뒤 컵을 들고 바로 퇴장하고 테이블·반납대에 컵이나 얼룩을 남기지 않는다. 제조 작업대의 오염은 기존 30% 규칙을 유지한다.

포장 음료는 리드를 덮고, 매장 머그·유리잔은 리드 없이 제공한다. 라떼 원문은 일회용 컵에만 리드를 덮도록 명시한다. 이용 방식에 따른 리드 처리는 구조화된 제공 행동과 게임의 컵 정책을 따른다.

컵 형태는 종이컵의 슬리브, 일회용 투명 컵의 테이퍼, 낮고 넓은 머그의 손잡이, 유리잔의 두꺼운 바닥으로 구분한다. ICED 컵의 하단·중간·상단 기준선은 [스타벅스 공식 콜드 컵 자료](https://about.starbucks.com/stories/2024/new-more-sustainable-starbucks-cold-cups-are-made-with-up-to-20-percent-less-plastic/)의 흑백 계량선 표현을 참고했다. 현재 단계의 목표 높이는 별도 선으로 표시하며 HOT 컵도 제조 중 목표 높이를 표시한다. 공식 자료에서 실제 높이·ml 환산 규격은 확인되지 않았으므로 모델 비율과 기준선 높이는 게임용 표현이다. 재고 차감용 추정치는 별도 파일에서만 유지하고 컵에 실측 ml 눈금으로 표시하지 않는다. 공개 컵 자료와 가정용 에스프레소 9g 안내를 한국 매장의 확정 계량값으로 적용하지 않으며 근거의 한계는 [제조 자료 운영](./recipe-data.md#재고-추정과-실제-계량-근거)에 기록한다.

저장에는 이용 방식, 제조 컵 종류, 표면·운반 중 컵의 종류별 수량, 세척 대상과 종류별 재고를 필수로 포함한다. 저장 검증에서 머그·유리잔이 각각 4개로 유지되는지 확인한다. 이전 구조를 읽거나 변환하는 코드는 추가하지 않는다.
