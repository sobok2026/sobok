# 카페 코드 구조 진단과 정리

2026-09-25 기준. `apps/cafe`의 전체 진단과 동작을 유지하는 리팩터링을 진행했다. 사용자는 미사용 저장 필드 제거와 운영 기록의 소모품 사용량 표시 복원도 승인했다.

## 검토 범위와 기준

변경 전 `src/`와 `scripts/`의 TypeScript·TSX·JavaScript·CSS 49개 파일, 10,291줄을 검토했다. 앱 설정, 의존성, 자료 가져오기 경로, 저장·백업, 음원 참조와 관련 문서도 확인했다. 생성 JSON과 원본 엑셀은 코드 줄 수에서 제외했다.

우선순위는 변경의 파급 범위, 중복 규칙의 불일치 가능성, 코드를 이해하는 데 필요한 맥락으로 정했다. 고정된 파일 줄 수를 품질 기준으로 추가하지 않았다. Google의 공개 리뷰 기준은 설계·복잡도·현재 필요한 기능·문서의 일관성을 강조한다. 이 기준에 따라 실제 책임 경계를 분리하고, 향후 확장을 가정한 엔진이나 라이브러리는 추가하지 않았다. [Google 코드 리뷰 기준](https://google.github.io/eng-practices/review/reviewer/looking-for.html)

기존 Vite·React·Three.js·IndexedDB 구조, 게임 규칙, 단일 저장소와 단일 탭 정책을 유지했다. 자동 테스트 코드는 사용자 요청에 따라 추가하지 않았다.

## 적용한 구현 원칙

- **한 곳에서 상태를 발행:** 행동 처리와 tick은 기존처럼 상태를 복사한다. 업무 함수는 발행 전 복사본과 일시적인 입력만 변경하고, `CafeStore`가 마지막에 새 snapshot을 알린다. React가 읽은 이전 snapshot을 변경하지 않는다. [React `useSyncExternalStore`](https://react.dev/reference/react/useSyncExternalStore)
- **실제 책임으로 훅 분리:** `useWriterLock`, `useCafeScene`, `useWorkPreferences`는 각 브라우저 자원의 설정과 정리를 함께 소유한다. 단순히 줄 수를 줄이기 위한 범용 생명주기 훅은 만들지 않았다. [React custom Hooks](https://react.dev/learn/reusing-logic-with-custom-hooks)
- **닫힌 행동 타입:** 50개 행동을 식별 가능한 union으로 표현하고 라우팅의 마지막에서 `never`를 확인한다. 새로운 행동을 추가하면서 라우팅을 빠뜨리면 타입 오류가 된다. [TypeScript discriminated unions와 exhaustiveness](https://www.typescriptlang.org/docs/handbook/2/narrowing.html#discriminated-unions)
- **한 스키마에서 타입 추론:** 영속 상태를 별도 인터페이스와 동시에 수정하지 않도록 각 스키마에서 타입을 추론한다. 런타임 상수와 타입 의존성은 구분한다. [Zod 타입 추론](https://zod.dev/basics#inferring-types)
- **GPU 자원 수명 유지:** 장면 종료 시 geometry·material·texture·instanced mesh·shadow·renderer를 정리한다. 분리한 도형은 같은 scene 아래에 있으므로 기존 정리 경로가 계속 소유한다. 텍스처의 중복 수집 목록은 제거했다. [Three.js 자원 정리](https://threejs.org/manual/en/cleanup.html)

## 확인 결과와 한계

위 확인 중 앱의 브라우저 오류는 발생하지 않았다. 백업과 화면 캡처는 저장소 밖의 확인용 파일로 남겼으며, 임시 브라우저와 서버는 종료했다.

이번 확인은 모든 음료·실패 조합·장시간 근무·모든 브라우저를 완주한 결과는 아니다. 20시간 추출은 시작과 저장 복원까지 확인했고, 실제 20시간 대기나 다음 날 전체 마감 흐름을 다시 수행하지 않았다. 성능 벤치마크도 새로 측정하지 않았다.
