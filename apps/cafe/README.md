# Cafe · Day Shift

1인칭 카페 매장 운영 게임의 첫 플레이 버전. Vite + React + TypeScript + Three.js로 실행하고, React UI는 Tailwind CSS로 스타일링하며 IndexedDB에 저장한다.

```sh
bun install
bun run --filter=@sobok/cafe dev
```

로컬 주소: `http://127.0.0.1:3018`.

```sh
bun run --filter=@sobok/cafe type
bun run --filter=@sobok/cafe build
bun run --filter=@sobok/cafe preview
```

`build` 결과는 `apps/cafe/dist`에 생긴다. 원격 서버·로그인·DB 설정 없이 실행한다. 이번 버전은 PC 키보드·마우스와 WebGL 2를 대상으로 한다.

## 배포

운영 주소는 `https://cafe.sobok.cc`다. GitHub Actions의 **Cafe Deploy**를 `main`에서 실행하고
`confirmation`에 `DEPLOY CAFE`를 입력하면 카페만 빌드·배포한다. **Production Deploy**의 전체 운영 배포에도 포함된다.

`wrangler.jsonc`는 `dist`를 Cloudflare Workers Static Assets로 배포한다. `workers.dev`와 preview URL은
끄고, custom domain은 `sobok-ops`의 `account-workers` HCP Terraform workspace가 소유한다.
최초 배포는 GitHub Actions에서 `cafe` Worker를 생성한 뒤 Terraform으로 도메인을 연결한다.
스테이징은 구성하지 않는다.

## 플레이

- 콜드 브루 ICED, 블랙 글레이즈드 라떼 HOT·ICED, 호지 글레이즈드 티 라떼 HOT·ICED를 제공한다. Tall·Grande·Venti를 선택하고, 콜드 브루는 포장 전용 Trenta(887ml·6,900원)도 제공한다. 호지 라떼의 클래식 시럽은 사이즈별 3·4·5펌프를 넣고, 준비된 호지차 샷을 매번 3회 다시 흔들어 계량한다.

- WASD 이동, 마우스 또는 방향키로 시점 조작. Esc 설정에서 마우스 감도를 50~200%로 조절한다. 기본값은 100%이며 방향키 회전 속도는 일정하다. 근무 시작·재개 후에는 버튼을 누르지 않고 마우스를 움직여 둘러본다. 마우스 고정이 지원되지 않으면 화면을 누른 채 드래그하거나 방향키를 사용한다.
- E로 작업대 열기 또는 컵 집기·내려놓기. 컵은 작업대의 정해진 자리에 자동 정렬된다.
- 컵을 내려놓거나 부재료 준비·세척을 시작하면 커서가 풀려 작업 버튼을 누를 수 있다. WASD 이동, 컵·피처 집기, 작업 종료 후에는 마우스 시점으로 돌아간다. 다른 작업대에 진행 중인 작업이 남아 있어도 이동·시점 조작은 가능하다. 준비·세척 작업대로 돌아와 E를 누르면 다시 커서를 사용할 수 있다.
- G로 도구를 집고, 클릭 또는 Space를 누르고 있으면 붓거나 젓는다. 펌프·파우더·얼음은 한 번 누를 때마다 한 회씩 넣고, 보틀도 한 번씩 눌러 흔든다.
- 목표 구간에서 멈추고 G로 도구를 놓은 뒤 F로 계량을 확인한다. 초과한 음료는 정리하고 다시 만든다. 다회용 컵은 세척 대기로 보내고 일회용 컵은 폐기한다.
- 손님이 입구에서 POS로 걸어와 도착하면 주문을 입력한다. 컵 보관대 → 주문표의 제조 단계 → 픽업대 순서로 진행하고, 손님이 픽업대에 도착하면 F로 전달한다.
- 매장·포장 손님은 50%씩 등장한다. 매장은 HOT 머그·ICED 유리잔, 포장은 HOT 종이컵·ICED 일회용 컵을 사용한다. 포장 컵에만 리드를 덮는다.
- 매장 손님은 컨디먼트 바에서 소모품을 챙기고 테이블에서 10초 머문 뒤 컵을 반납하거나 남기고 퇴장한다. 포장 손님은 소모품을 챙기고 컵을 들고 바로 퇴장한다. 앞 손님이 나가야 다음 손님이 들어온다. 이동·착석·반납 상태도 저장·복원된다.
- 카운터 안쪽 직원 통로에서 시작한다. 제조 장비·POS·픽업대는 직원 쪽에서만 사용할 수 있다.
- 세척대에서 피처·HOT 머그·ICED 유리잔을 선택해 놓고 G로 스펀지를 집어 누르고 문지른다. G로 스펀지를 놓고 F로 헹구기로 넘어간 뒤, 누르고 헹궈 F로 완료한다.
- E로 씻은 피처는 도구 선반으로, 머그·유리잔은 컵 보관대로 운반해 E로 놓는다. 제자리에 놓은 뒤에만 다시 사용할 수 있다. 다회용 컵은 종류·사이즈별 4개로 시작한다. 세척 순서는 같고 사이즈는 자동으로 유지해 해당 재고로 돌려놓는다.
- 세척 중 손을 떼거나 자리를 떠나도 진행량이 유지된다. 취소해 대기 위치로 돌려놓은 용기는 처음부터 다시 씻는다.
- 두 테이블 사이 창가에 컨디먼트 바가 있다. 매장 손님은 90% 확률로 컵을 반납하고 10%는 테이블에 남긴다. 테이블·반납대·작업대의 얼룩은 사용 시 30% 확률로 생긴다. 컵과 오염은 실제로 이용·반납을 마친 시점에 반영된다.
- 두 고객 테이블과 컨디먼트 바의 컵·얼룩은 각각 관리한다. 테이블에서 청소를 시작하고 E로 다회용 컵을 집어 세척대까지 옮긴 뒤 E로 내려놓는다.
- 테이블로 돌아와 G로 천을 집고 클릭·Space를 누르는 동안 닦는다. G로 천을 놓고 F로 확인하면 청소가 끝난다. 다른 작업대에 컵을 두면 혼합 작업대도 같은 방식으로 닦을 수 있다.
- 얼룩이 없는 자리는 컵 회수로 표면 정리를 마친다. 회수한 컵의 세척·보관대 반납은 따로 진행한다.
- 일회용 컵은 종류·사이즈별 보관대 2개·후방 12개로 시작하고, 후방에서 같은 종류·사이즈를 보충하거나 24개·2,000원으로 추가 입고한다.
- ICED 컵에는 흑백 기준선, 제조 중인 컵에는 현재 단계의 금색 목표선을 표시한다. 컵 높이와 ml 환산은 게임용 임시값이다.
- 냅킨·빨대·설탕은 컨디먼트 바에서 사용된다. 창고에서 보충품을 집어 바에 가져가 E로 채우고, 창고에서 E로 다시 내려놓을 수도 있다.
- 각 소모품은 진열 20개·후방 100개로 시작한다. 냅킨은 주문당 1장, 빨대는 ICED 음료당 1개, 설탕은 30% 확률로 1개 사용된다. 창고에서 100개를 1,000원에 추가 입고하며 품절이어도 주문은 계속된다.
- 분리수거함에서는 누르고 쓰레기를 모아 봉투를 묶은 뒤 F로 비운다. 청소·컵 운반 도중 저장해도 이어서 진행할 수 있다.
- 직원 통로 뒤쪽에 준비대·세척대·도구 선반·콜드 브루 추출대·실온 선반·냉장고와 창고가 있다. 객석 청소와 분리수거는 POS 옆 직원 출입구로 나가서 진행한다.
- 준비대에서 폼·바모카·호지차 샷을 선택하고 G로 도구를 집어 직접 계량한다. 폼은 크림 → 우유 → 7펌프 → 3번 블렌딩, 바모카는 원팩 → 온수 → 젓기, 호지차 샷은 정수 250ml → 파우더 8스쿱 → 10회 흔들기 순서다.
- 준비가 끝나면 준비대에서 날짜 라벨을 붙이고 E로 용기를 집는다. 폼·호지차 샷은 냉장고, 바모카는 실온 선반까지 직접 운반해 E로 보관한다. 원래 작업대에 E로 다시 내려놓을 수도 있다. 이동·저장 중 잔량·라벨·기한은 유지되며 보관 전에는 음료에 사용할 수 없다.
- 콜드 브루 추출대에서 9,000원으로 원두 한 배치분을 준비한다. G로 원두 봉투를 집어 Space를 누르고 5lb를 모두 담은 뒤, G로 놓고 F로 확인한다. 물도 G·Space로 14L 목표 구간에 맞추고 놓은 뒤 확인한다.
- Space로 20시간 추출을 시작한다. 추출 중에는 마감하고 다음 날로 넘어갈 수 있다. 끝나면 E로 3L를 용기에 회수하고 F로 라벨을 붙인 뒤, E로 집어 냉장고에 운반·보관한다. 회수는 기한을 새로 시작하지 않는다.
- 용기를 운반하는 동안 다른 물건은 들 수 없다. 잘못된 보관 장소에서는 보관을 거부하며, 운반 중 만료되면 원래 작업대에 내려놓고 폐기한다. 콜드 브루 준비를 중단하면 한 배치분을 폐기하며 준비비는 반환되지 않는다.
- 냉장고·창고에서 사용 가능·미개봉·라벨/보관 대기·만료 수량과 배치의 기한을 확인하고 개봉·보충·입고한다. 현재 주문과 필요한 부재료 준비에 부족한 품목을 먼저 보여준다.
- 새 원팩도 개봉 → 날짜 라벨 → 보관을 거쳐 보충한다. 기한은 실제 개봉·제조 시점부터 계산하며 라벨을 다시 확인해도 늘어나지 않는다.
- ‘N일’ 기한은 시작일을 포함한 N일의 마지막 날까지, ‘N시간’은 시작 시각부터 계산한다. 9월 1일에 개봉한 2일 기한 재료는 9월 3일 0시부터 사용할 수 없다.
- 폼·바모카·호지차 샷은 실제로 투입한 원재료의 가장 빠른 기한과 제조 후 기본 기한 중 이른 시각에 만료된다. 준비 도중 원재료 기한이 지나면 계량·블렌딩을 멈추고 배합을 폐기한다. 투입한 원재료 기한은 저장·복원된다.
- POS에서 신규 주문을 마감하면 주문 전 손님은 돌아 나가고, 접수한 손님은 이용·퇴장까지 마친다. 모든 손님이 나간 뒤 청소·설거지·정리·폐기를 마치면 결산할 수 있다. 매장 현황과 결산에는 시작 잔액, 판매액, 품목별 입고 지출, 현금 증감·잔액과 재료별 폐기량이 표시된다.
- 상단에는 근무일·시각·영업 상태와 접수한 주문만 표시한다. 하단에는 바라보는 대상의 행동 또는 진행 중인 작업명·계량값·조작만 표시한다.
- H로 현재 작업 도움말·조작법·레시피를 연다. 도움말은 자동으로 나타나지 않으며, 확인 중에는 게임 시간이 멈춘다. H 또는 Esc로 열기 전 작업에 돌아온다.
- 작업음은 처음에는 꺼져 있다. Esc 메뉴의 설정에서 켜고 음량·미리 듣기를 조절한다. 선택한 실제 녹음으로 컵에 붓기·우유 피처 계량·에스프레소 추출·스팀·얼음·테이블 닦기를 구분한다. 스팀 두 음원은 재생 시작마다 번갈아 사용하고, 완료·전달은 기존 bell을 유지한다. 계량 목표 도달·확인·주문 입력·라벨 부착은 무음이다. 컵·도구 조작의 타격음과 펌프·오류의 스위치 찰칵음은 사용하지 않는다. 일시정지·백그라운드·창 포커스 이탈 시 소리를 멈춘다.
- 마우스 감도·음소거·음량 설정은 이 브라우저에 따로 저장한다. 게임 백업을 불러와도 설정은 유지되며, 소리를 꺼도 작업 결과를 화면에서 확인할 수 있다. 녹음 음원의 출처와 가공 내용은 [음원 크레딧](./public/audio/CREDITS.md)에 기록한다.
- M으로 매장 현황을 열어 할 일·진행 중 작업·비품을 확인한다. 판매·입고·폐기는 운영 기록에서 확인한다. 확인 중에는 게임 시간이 멈추고 M 또는 Esc로 돌아온다.
- Esc로 일시정지. 메뉴에서 전체 조작법을 확인하고 JSON 백업을 내보내거나 불러온다.
- 지원 브라우저에서는 한 탭만 실행·저장할 수 있다. 다른 탭을 열었다면 기존 탭을 닫고 새로고침한다. 탭 간 상태 동기화나 자동 인계는 제공하지 않는다.

스타벅스 코리아 기준 메뉴 가격·사이즈와 출처는 [메뉴 사이즈와 판매 가격](../../docs/cafe/prototype-rules.md#메뉴-사이즈와-판매-가격)에 기록한다. 클래식 시럽의 달력 한 달 계산과 호지차의 추가 용량·원팩 규격은 [임시 규칙](../../docs/cafe/prototype-rules.md#호지-글레이즈드-티-라떼)에 구분해 기록한다.

## 실행 성능

목표 환경은 데스크톱 Chrome·Edge, 1920×1080, 60fps다. 바닥 줄눈·카운터 장식은 묶어서 그리고, 컵의 액체·토핑 모양은 내용물이 바뀔 때만 갱신한다. 시작·일시정지·결산 화면은 상태나 화면 크기가 바뀔 때 다시 그리며, 숨겨진 탭에서는 3D 렌더링을 멈춘다.

측정 환경과 범위는 [구현 기록](../../docs/cafe/implementation.md#표현과-성능-측정)에 남긴다. 모든 PC의 60fps를 보장하는 수치는 아니다.

프로덕션 빌드는 React와 Three.js의 코어·렌더러를 별도 청크로 출력한다. Vite의 기본 500KB 경고 기준을 유지하며, 분리 근거와 크기·로딩 확인 결과는 [빌드 청크 분리](../../docs/cafe/implementation.md#빌드-청크-분리)에 기록한다.

## UI 스타일

Tailwind CSS v4와 공식 `@tailwindcss/vite` 플러그인을 사용한다. `src/style.css`는 테마·기본 요소 스타일·높이 반응형 변형을 정의하고, 화면 스타일은 `src/app`, `src/features`, `src/shared/ui`의 JSX에 둔다. 반복되는 버튼과 작업 HUD는 앱 내부 컴포넌트로 공유한다. 계량 게이지의 진행률·목표 위치는 계산된 인라인 스타일을 사용한다.

[화면 정보 설계](../../docs/cafe/hud.md)에서 정보의 노출 기준을 정의한다. 구체적인 작성 원칙과 공식 문서 근거는 [구현 문서의 UI 스타일](../../docs/cafe/implementation.md#ui-스타일)을 따른다.

## 자료 갱신

사용자가 제공한 네 엑셀을 `apps/cafe/references/`에 두고 레포 루트에서 다음을 실행한다.

```sh
bun run --filter=@sobok/cafe import:references
bun run --filter=@sobok/cafe check:references
```

생성된 `src/content/references.generated.json`을 사용하므로 빌드 시 원본 엑셀은 필요하지 않다. 가져오기는 원본 파일을 수정하지 않는다. 자료 공개는 사용자가 명시적으로 허용했다.

가져오기에서는 열 제목과 현재 플레이하는 메뉴·온도·제조 단계·단위·품질 기준을 확인한 뒤 JSON을 교체한다. 검사나 포맷에 실패하면 이전 생성 파일을 유지한다. `check:references`는 생성된 JSON만 검사하며 `dev`·`build`에서도 먼저 실행된다. 누락·중복·단위 변경·실제 제조 순서 변경이 발견되면 출력된 파일·시트·항목을 확인한다.

메뉴와 단계의 배열 위치 대신 이름·온도·단계 의미로 연결한다. HOT·ICED 수량은 각각의 자료를 사용하며 자료에 새 메뉴가 들어와도 POS 메뉴는 자동으로 늘어나지 않는다. 컵의 ml 환산·수율·원팩 규격은 [임시 규칙](../../docs/cafe/prototype-rules.md)을 유지한다. 날짜 계산과 배합의 원재료 기한 상한은 사용자 확인을 받은 게임 규칙이다.

컵과 부재료의 내용물·도구·계량 진행량, 배합 용기 운반, 콜드 브루 계량·추출·회수, 피처·다회용 컵 세척·운반, 종류별 컵 재고·매장/포장 주문, 테이블별 오염과 청소·컵 회수 상태, 컨디먼트 소모품·운반 상태와 당일 입고·폐기 기록도 저장한다. 저장과 백업은 필수 필드를 모두 가진 현재 데이터 형식만 검증한다. 레거시·마이그레이션·버전별 분기·호환 코드는 두지 않는다.

첫 버전은 작업 순서와 직접 계량, 단순 도형을 사용한다. 실제 장비·컵·세척 절차의 완전한 재현은 후속 작업이다. 자동 테스트 코드는 사용자 요청에 따라 추가하지 않았다.

저장과 백업은 현재 데이터 형식만 허용한다. 주문 사이즈·종류/사이즈별 컵 재고·준비의 원재료 기한과 세척 상태는 필수 필드이며, 누락된 데이터를 보완하거나 변환하는 코드는 두지 않는다.
